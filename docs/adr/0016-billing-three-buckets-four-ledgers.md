# ADR-0016: 计费三桶额度与四账本运行时合同

Status: accepted (2026-07-24)

> 本 ADR 凝结自决策日志 D-109/D-123/D-124（含 D-044/D-045 既有基建），是实施投影；冲突以决策日志为准。内部成本基准与毛利参考线只在 D-123 记录，永不进前台、不硬编码、不复制到其他文档。

## Context

商家购买的是可认知的产品权益，不是 Token 或供应商算力。计费横跨营销页、支付、权益、执行、后台五个面，必须一套合同贯穿，禁止各模块自造口径。

## Decision

**四条真相账本，不可混写（D-109）**：`ProductCatalogRevision`（商品与公开售价）、Payment/Order Ledger（实收/退款/周期）、Entitlement/Usage（授予/预占/结算/退回/到期）、ProviderCost Ledger（供应商真实成本，只记录、供线下核算取数）。上游价格变化不改写已购权益；运营赠送不改写套餐或支付记录。

**三桶额度＋三类加油包（D-123，修订 D-109 两桶）**：套餐额度＝文案/图片/视频三桶；加油包分文案包/图片包/视频包。档位命名统一**初级/中级/高级**＝内容工作区 1/2/3（ADR-0015）；视频档位定数 3/6/9 条/月（拍板数），超出走视频加油包（标高定价，代运营引流钩子）。高规格输出可用多个额度单位，但不透传供应商价格。

**运行时合同**：一个用户主动任务只产生一笔权益预占；内部 Planner/评估/质量淘汰/fallback/重试全进 ProviderCost，不重复扣用户；最终失败全额退、部分交付退未交付部分；用户主动「再来一版」＝新任务再扣。提交前经服务端 `UserDebitPreview`＋quote revision 冻结；模型/参数变化实时更新预览。周期额度不累计；加油包长期有效；赠额显示到期日；最早到期先消耗。商家感知面＝付款→得到次数/额度、每次消耗→扣减、**缺额提醒、超额报停**（预占失败任务不可发起）。

**数字＝运营参数（D-123）**：全部套餐组合（价格/三桶额度/工作区数/加油包/促销）为后台可调配置，运营线下核算后手填（admin-config CAS/审计/回滚承载）；促销走 `PromotionalGrant/GrantLot` 不改已发布套餐；**前期不建毛利守门/成本告警/自动核价**。

**公开付费六项收口的门槛归属（D-124）**：R 门（真实商家试点前）＝①注册/验证/找回邮件＋④单一商品目录＋⑤前台去工程语言；E 门（公开收款前）＝②支付 Provider 真实 checkout/webhook/续费/取消＋③删除/匿名化＋⑥取消/退款/人工补单闭环。试点期支付零开发：兑换码＋人工开通＋人工补单（D-045 既有）承接，收款链路 E 门一次建成。

## 实施红线

- Provider 成本≠售价；前台永不出现 Token、供应商单价、毛利、路由、重试次数或技术式报价。
- 禁止在代码/前端硬编码套餐数字——一律从 ProductCatalogRevision 取数（营销页/订单/支付/权益同源，D-102 ④）。
- 文案桶按 D-123 三桶实施，勿按 D-109 条目旧「两桶」口径（该处已有修订横幅）。
- 计费对象只由 Coordinator 创建；子 job 只写 ProviderCost，绑同一 billing lineage。
