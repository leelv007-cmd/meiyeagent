# ADR-0018: 生成期零阻断与发布收口门禁架构

Status: accepted (2026-07-24)

> 本 ADR 凝结自决策日志 D-117/D-122（及 D-112 四底线的收窄口径、D-006 分派标注、D-025/D-039 既有合同），是实施投影；冲突以决策日志为准。

## Context

这是被「好心加错门」最多的原则：评审建议、复刻参考（如绘文 Codex 拆解的「无 store_fact 不得称本店在售」硬规则）和实施 Agent 都倾向在生成链加事实阻断。用户两次明确纠偏：商家自有信息量不足以支撑丰富内容输出，演绎是产品力的一部分；让内容生成平台承担全流程风控是错误定位。本 ADR 把「哪里允许建门」钉死。

## Decision

**生成过程零内容限制（D-117）**：允许适当美化、多角度演绎、场景与体验叙事；不做生成期事实阻断、不做逐句核验、不因「事实未登记」拦截生成。

**硬门只有五处，别处不许建**：

| # | 硬门 | 承接 |
|---|---|---|
| 1 | 忠实性——商家**已提供**的信息不得生成错（价格 398→389 类） | D-115 exactText/OCR 校验门 |
| 2 | 红线硬停——准入层监管红线（医美等） | D-025 |
| 3 | 权利授权——素材/肖像/身份授权状态 | D-022 + D-112 权利门 |
| 4 | 产品额度——预占失败任务不可发起（超额报停） | ADR-0016 |
| 5 | 外部发布确认——唯一硬阻塞审批 | D-112 |

**AIGC 标识承接（D-117/D-118 裁决）**：AI 生成软提示（「内容由 AI 生成，请注意甄别真实性」类）随成品交付＋发布确认提醒；视频不做我方像素烧录，各发布平台上传素材时自动执行标识。内容真实性责任在商家，发布确认是商家行使责任的位置。

**HITL 三允许（D-122，编排容错总纲）**：允许 LLM 幻觉、允许工具微小错误、允许人介入修正，流程恒前进。人的介入位是**修正点不是审批墙**——可介入可不介入，不介入有默认值/超时放行/容灾轨。**设计检验三问**（任一为否须重设计）：①是否为追求零错误而阻塞流程？②介入位是否可跳过？③错误发生时是否有人工修正轨、且修正产物同 schema 无损进入后续引用？

**D-006「永不猜测」分派口径（2026-07-24 标注）**：原清单不再作为生成期硬拦截；医疗效果→红线、授权状态→权利门、忠实性关键事实→校验门，其余演绎类（顾客评价/名额/场景叙事）→发布确认收口。

## 实施红线

- 评审/复刻建议中「为消灭错误而加生成期阻断」类方案默认拒绝（按 D-122 降级处理）；新增任何门必须先过三问并对照五处硬门清单。
- 确认卡一律带默认值＋超时放行（D-116）；引导永不变成阻断。
- 软提示是提示不是门：不得实现为拦截或强制勾选。
- 五处硬门本身不得放松：忠实性校验门与发布确认门是产品诚信底线，与生成自由并行不悖。
