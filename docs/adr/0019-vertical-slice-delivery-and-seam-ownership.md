# ADR-0019: 纵切交付与接缝属主——反模块孤岛

Status: accepted (2026-07-24)

> 本 ADR 把反复出现的工程病灶规范化为交付纪律，依据 D-032（三进三出合同）/D-043（体验合同）/D-110（装配门与「模块各自为战」诊断）及历次评审实证；冲突以决策日志为准。

## Context（病灶实证）

反复发生的同一个病：**功能拆分按模块横切**——每张票各建自己那层，模块间接缝无人负责，验收只验模块单测，测试没测出断链，结果是代码冗余堆积、前端体验割裂。项目史实证：三套结果事实靠投影拼接（ADR-0011 病灶：采用后内容页显示 0 条）；视频管线 ~2500 行建好但 UI 不可达（违 D-027）；TodayRecommendationCard/ExampleStorePreview 组件写完从未挂载（评审 P-01）；07-18 评审定性「缺陷面貌＝最后一公里未接线，非架构错误」；07-13 五根因含「前后端接线断层」「验收不验体验」。

## Decision

**1. 拆分单位＝用户旅程纵切片，不是模块横切片。** 每张开发票的交付物必须是「用户可触达入口→API/执行→可感知结果回显」的一条完整链。允许存在纯底座票，但必须显式声明**消费方票号**，且该消费方票的验收覆盖本底座——没有消费方的底座票不得开票。

**2. 接缝先立合同、每条接缝唯一属主。** 跨模块/跨前后端接缝先冻结合同（D-032 三进三出：HTTP+SSE 合同测试先行），再各自实施。两票各建一半时，票面必须写明**谁负责接线与联调**（跨票唯一属主矩阵）；「都以为对方接」即无人接。

**3. 验收以旅程为单位，不以模块为单位。** 完成定义（DoD）＝该纵切旅程 e2e 真机走通（真服务启动、真数据点击，fixture 可用但链路必须真走）。模块单测绿≠完成；**「组件已建未挂载」「管线已建无入口」「投影已建无消费面」一律记为未完成**。装配门（D-110：注册→默认栈→首次出活）是这一纪律的第 0 号 required 旅程。

**4. 同一语义唯一投影。** 新功能接入既有权威投影（ResultShellModel、pending-actions 等），禁止为新页面新建平行投影或第二真相（ADR-0011 总闸的交付面延伸）；新旧投影并存必须带显式退役计划。

**5. 动工前先盘点存量，复用优先。** 每票实施前对照存量代码盘点（已有则接线不重建）；发现重复层当场登记退役票，不带病堆积。

**拆票组织（D-131）**：前端相关票统一归「前端组」（frontend lane），由用户指定的 Agent 与模型执行（名称待登记）。分组不破本 ADR 纵切纪律：票面三要素照旧，前后端同旅程拆分时接缝合同与属主显式写明，旅程收口落前端票或专设联调票——前端组内部自闭环、不接真后端＝未完成。前端组每票附自包含上下文包（DESIGN.md＋ADR-0014＋D-130 组件基准/镜像/模板起点＋接缝合同）。

## 实施红线

- 禁止交付「无用户可达入口」的功能并声明完成；验收清单第一项永远是「从真实入口点得到」。
- 禁止第二套投影/事实/提交合同；禁止绕过 canonical command 写入。
- e2e 必须真机链路（教训：CI e2e job 曾因 harness 未激活+fixture 模型缺失＝启动必崩而假绿）；断言不得被脚本吞掉真实 exit code。
- 票面三要素缺一不发：入口与结果的旅程描述、接缝合同与属主、旅程级验收命令。
