## 差距锚点

- 报告§一根因②：现有验收只确认“功能存在”，没有确认能力是否进入桌面核心路径、用户能否看见和用完、第一眼质感是否达到对标；因此组件可被桶导出、矩阵可全绿，主工作台仍完全不可见。
- 报告§六共同前置第 2 项已点名体验合同的最低必选项：token 流式呈现、生成中阶段白话叙事、提交后占位卡、chips 点选行为；这些必须进入 `required`，不得只留在实现票描述中。
- 旧矩阵 `.scratch/creatok-uiux-wayfinding/assets/13-uiux-acceptance-matrix.md:11-94` 当前实核为 49 条（48 required、1 waivable），绝大多数证据仍是测试、日志、接口或工程报告；报告所述“41 条矩阵全绿”是形成报告时的历史快照，不作为当前行数事实。
- ADR-0010 与 MAP 将 Path B 的切换证据改为“用户可见行为 + 对标产品逐屏截图”，并规定同一候选构建验收；静态原型、旧构建、桶导出、隐藏路由或不同提交的拼接证据均不能代替。
- 本票只定版验收合同和红/绿判定方式，不提前实现 Phase 1-5。票 02 可在条目完成定义、映射和基线取证后关闭；条目可保持红色，后续票只有把所映射的 required 条目验绿才可关闭。

## 改造方案（步骤级 + 涉及文件清单）

1. 在现有 `.scratch/creatok-uiux-wayfinding/assets/13-uiux-acceptance-matrix.md` 上升版为 v2，保留 A-H 的工程/安全门槛，新增独立的 `I. 体验合同`；不得用新条目删除或降低原 required 门槛。
2. 为 I 区采用 `I01...` 稳定 ID，列固定为“ID / 级别 / 用户可见行为 / 对标对象 / 必需证据 / 映射票”；所有行均为 `required`，且逐行映射 MAP 票号与报告 P0/P1/P2 编号，禁止只写“见设计稿”。
3. 写入下列最小体验合同，不扩张报告范围：
   - `I01` 主路径可见：能力必须从 `/dashboard` 的真实用户旅程可发现、可操作、可完成，桶导出或隐藏页面不算交付（根因②；票 03/13/15/16/21）。
   - `I02` D3 外壳：保持单一生成工作台；外层呈拟人化问候、建议与对话式时间线，内层仍是可检查的结构化 Work/Job/Asset/Content，不新增独立 Chat clone（P1-5；票 19）。
   - `I03` 流式：副驾 token 逐步出现，文案候选可见部分对象逐步成形；等待期间不得是整段静默后一次性跳出（P0-1/P1-1；票 06-08）。
   - `I04` 生成反馈：提交立即出现与本次任务对应的占位卡；长任务自动更新白话阶段、离页再回可恢复，禁用无法证实的百分比（P0-6/P1-3/P1-4；票 09-11）。
   - `I05` chips：今日建议与场景 chips 可直接点选，点后意图被真实预填并可继续生成，不是装饰标签（P1-5；票 19）。
   - `I06` 渐进 Composer：默认先见场景/预设与必要输入，高级参数按需展开；预设选择可隐藏提示词框，模型保持显式选择，禁止跨品牌 Auto（P0-4/P1-8/P1-9；票 12/13/15）。
   - `I07` CheckBox 套组：内容模块可多选、默认组合可见、提交前可预览成套结构；不得把执行合同确认框冒充内容模块构建器（P1-7；票 14）。
   - `I08` D4 候选择优：每次展示 3 个文案候选，只能 3 选 1 单选采用，并提供换一批与免费重试不超过 2 次；不得改成多选采用（报告§二；票 18）。
   - `I09` 成品呈现：图片/视频在结果、历史与资产入口显示真实缩略图/预览，文案按富文本可读呈现，不再只显示 ID 串或裸文本（P0-3/P0-5；票 08/17）。
   - `I10` 全局回收：用户离开当前 Work 后仍能从任务浮标看见运行/完成状态并一键回源；`⌘K` 在业务壳全局可用且区分“导航”和“添加到创作”（P1-4/P1-6；票 10/20）。
   - `I11` 三喂料：打字、传图/拍照、图片拖放/粘贴均从统一输入台可用；只清除无功能链接占位，不恢复已 de-scope 的 L-1 贴链接抓取（P2-1；票 22）。
   - `I12` 一致性与可达性：用户旅程不出现模板品牌、内部模型 ID 或无故中英混杂；移动关键触区、大字号、生成中/完成反馈在目标视口真实可见（P0-2/P1-11/P1-12/P2-2/P2-4/P2-5；票 04/23-25）。
4. 每行证据模板统一为：同一候选构建、同一测试数据、相同视口的“当前产品 vs 对标产品”并排截图；流式/阶段变化另附开始—进行中—完成三帧或短录屏。对标选择须诚实：流式用即梦/KickArt，不能拿报告已判 UNKNOWN 的 CreatOK 运行态冒充；画廊/模块组合可用 CreatOK。
5. 给每行增加 `red / green` 判定说明：任一关键动作不可发现、只在非主路径可见、截图来自静态原型、或证据不是同一候选构建，均判红；不得以主观“更好看”代替具体行为差异。
6. 在矩阵总切换判定中加入 MAP 全局规则：I 区任一 required 未绿，相关实施票和 Path B 均不得关闭；最终证据按 MAP Exit milestone 汇入其指定的 UIUX Upgrade B 证据包。

## DoD（全部必须是用户可见行为；至少 1 条截图对照项：当前产品 vs 对标产品）

- 用户从桌面生成工作台即可完成“开场建议/场景 chip → 输入或传图 → 提交 → 看见生成过程 → 查看成品 → 采用/回源”的连续旅程；无需跳到演示页或手输其他地址寻找关键能力。
- 用户点击今日建议或场景 chip 后，输入区立即出现对应的可编辑意图并可继续开跑；chip 只变色、无后续作用即不通过。
- 用户提交副驾或文案生成后能连续看见内容逐步出现；图片/视频长任务则立即出现占位卡并自动显示可信的白话阶段，离页返回后状态和结果仍可恢复，不显示无法证实的百分比。
- 用户默认先看到低门槛场景/预设与必要输入，按需才展开专业参数；模型供应商选择保持显式且不会跨品牌自动切换。
- 用户构建内容套组时可勾选多个内容模块并在提交前看到组合预览；用户采用文案候选时看到恰好 3 条且只能单选 1 条，并能换一批、免费重试最多 2 次，两种交互不可混用。
- 用户在结果、历史和资产入口能直接看到图片/视频缩略图或预览以及可读的文案排版，不需要靠 Asset ID、对象键或裸 JSON 判断产物。
- 用户离开当前 Work 后仍能通过全局任务浮标看见运行/完成状态并一键回到来源；在业务壳任一一级页按 `⌘K` 都能看见分开的“导航”和“添加到创作”。
- 用户可在统一输入台打字、选择/拍摄图片、拖放或粘贴图片；界面不承诺贴链接抓取，也不出现看似可用但只写本地占位的链接动作。
- 用户在桌面与 MAP 要求的移动视口完成上述旅程时，不看到 TanStarter/MkFast 等模板品牌、`recorded-*` 内部标识或无故中英混杂；关键动作可触达、文字可读，生成中与完成反馈不被裁切。
- 至少产出一组同尺寸并排截图：当前产品 `/dashboard` 首屏 vs 即梦/KickArt 的 Agent 开场与生成中状态；另以 CreatOK 对照结果画廊或模块组合。截图必须来自同一候选构建的真实可操作页面，并附旅程步骤、视口和时间，不得用静态原型替代。

## Blocked-by / Blocks

- Blocked-by：无。
- Blocks：全局阻塞票 01、03-25 的关票；票 02 定版前，任何票不得关闭。票 02 定版后，各票仍须把自己映射的 I 区 required 条目验绿才可关闭。
- 主链映射不变：03 blocks 13/15/16/21；06 → 07 → 08；09 → 10；12 → 13 → 14。本票只提供统一验收基准，不改变依赖顺序。

## 风险与回退

- 风险：把体验合同写成“组件/接口/测试存在”的工程清单。控制：每行主语必须是用户动作或用户所见，工程证据只能做旁证，不能单独转绿。
- 风险：截图挑选不同版本、不同数据或最佳个案，制造虚假对齐。控制：固定候选构建、账号/数据、视口和旅程步骤，保留开始—进行中—完成连续证据。
- 风险：体验条目重开锁定决策。控制：D3 只允许“对话式外壳 + 结构化内核”，不做 Chat clone；D4 保持 3 选 1 单选；不恢复 L-1 链接抓取；不引入模型跨品牌 Auto。
- 风险：新增 required 过宽导致所有票永久阻塞。控制：每行只映射报告现有差距和 MAP 已列票；若发现新范围，回 ADR 决策，不在矩阵中静默追加。
- 回退：若 v2 条目口径不可执行，回退到本票实施前的矩阵内容并保持所有后续票“不可关票”，修订体验合同后再解锁；不得回退为只看功能存在的旧关票标准。
