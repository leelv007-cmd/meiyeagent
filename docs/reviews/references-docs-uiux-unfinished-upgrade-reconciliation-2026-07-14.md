## 1. 结论：当前不是“功能差几个”，而是产品主体尚未形成

当前工程已有大量页面、状态机、卡片和 fixture，但用户仍不能连续完成：

`像本店的真实内容 → 快速看到可用成品 → 采用后继续改/发/复用 → 下周知道该做什么`

这才是“美业内容运营副驾”的产品主体。OCR、Hook、Recent 筛选、Admin overview、回收站和总验收都不是这条主体本身。

## 3. 最终只保留三条核心产品 frontier

### Frontier A · 从一句需求到可用成品

Owning ticket：`35-end-to-end-productized-generation-workbench.md`。

这是唯一新增的核心 UIUX 票，同时吸收首版 35/36/37 中有价值的部分：

- 门店事实与真实素材成为内容 grounding，而不是用多源导入数量衡量功能。
- AI 把用户意图编译成可确认 Brief，字段编辑真正写回 Work，而不是添一张 `local only` 补丁卡。
- 候选必须显示真实门店事实/素材来源；无事实时请求补充，不用示例店或编造价格伪装成商家成品。
- 成品领屏，用户只需判断“用哪条、改哪里、下一步做什么”，而不是读一屏对象证据和技术参数。
- 实际模型、报价、用量、进度和结果一致；真实 media 由票 30，真实选模由票 32 承接。

### Frontier B · 从生成结果到可继续经营的内容

Owning tickets：27 + 28。

- 采用后进入唯一 Content / Asset 事实，一级内容库立即可见。
- 在同一内容上完成就地改稿、撤销、平台变体、L3/已激活 L1 交接、发布结果、线索关联和“做同款”。
- Work / Session / Job 从自身地址继续、恢复、重试或派生，不返回“最新 Work”冒充续作。
- Asset 归档/恢复/引用保护是该闭环的内部治理，不单独占据产品 frontier。

### Frontier C · 从每周下一行动到发布回写

Owning ticket：29。

- 用户首页只看到一个真正最优先行动，并直达对应 Content、Asset、Work、Job、发布或连接上下文。
- 首个持久动作推进 Task，系统产物不自动宣告经营任务完成，用户确认后才完成。
- 生成可离开、恢复且不重复提交/扣费；L3 或 verified L1 结果回写原 Content/任务。
- Recent 的聚合和高级筛选只在服务这条旅程时手术式修补，不另建大 IA 票。
