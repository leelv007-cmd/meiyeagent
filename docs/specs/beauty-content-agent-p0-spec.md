## Problem Statement

美业到店商家需要持续在小红书和抖音生产能体现本店项目、审美、价格与真实案例的内容，但店主和店员通常兼任运营，单条内容可能耗费 1–2 小时，且缺少策划、写作、拍摄、剪辑和平台运营时间。通用 AI 工具要求用户自己写提示词，容易生成同质化、缺少真实素材支撑、价格失真或不符合平台语境的内容，无法稳定变成可发布结果。

视频成片是商家能直接感知价值的主打产物，但它同时带来分钟级异步任务、供应商质量波动、额度计费、失败补偿、文件存储以及 AIGC 显式与隐式标识等工程要求。只生成视频脚本，不能解决商家的实际交付问题。

发布侧还受到平台开放能力、账号权限和自动化合规限制。P0 不能承诺跨平台自动发布，也不能托管平台凭据或依赖浏览器自动化；必须把人工发布交接做成正式、低摩擦的 L3 发布包，而不是临时兜底。

医美/医疗资质准入制商家还涉及资质查验、医疗广告、敏感个人信息、顾客案例授权、违法内容与 AIGC 标识义务。产品必须区分我方服务提供者义务、受托处理者义务和商家广告主责任：硬性义务内建，风险提醒可追溯，行为红线不可绕过。

商家最终需要知道内容是否带来咨询、加微、预约或核销，但 P0 无法稳定读取平台数据，也不应声称复杂因果归因。因此需要一个足够轻的手工线索台账，把内容生产与经营结果连接起来，同时不把产品做成 CRM。

## Solution

建设一个面向美业到店与医美/医疗资质准入制商家的云端 Web 内容创作副驾。P0 以一个 Agent 工作台作为产品本体，以对话式外壳承接自然意图，以结构化 brief、场景 chips、候选卡、合规卡和任务卡保证结果可控；内容库、线索台账和门店档案作为三个轻量资产页。

商家先确认门店档案、项目价目、品牌音和账号基础记录，再上传带标签与授权状态的真实素材。Agent 基于这些事实生成小红书和抖音文案，或执行“可确认 AIDA 分镜 → 首帧 → 视频片段 → 薄合成 → 按开关处理产品标签并记录 provenance/metadata → 存储”的视频成片链路。长任务允许提交即走，并通过任务中心与连接桥恢复进度。

创作与草稿阶段保持开放；发布包创建、L1 提交或明确公开交付时执行发布阶段核验，普通 Work 保存、导出和下载不触发发布审核。行为红线在明确要求不安全、欺骗、未授权或绕过平台时硬停止；普通风险可以返回建议，但不把图文创作变成审批流。医美/医疗内容采用资质准入制轻量 Preflight，以强提醒和审计留痕为主。产品品牌水印与产品侧 AIGC 标识由创作者开关控制，供应方/平台强制标识和实际元数据如实记录；专门法务团队在功能完整后审核生产规则与默认值。

发布默认走 L3 发布包，包含扫码转手机、分段一键复制、图片与视频存相册以及发布 checklist。发布后由商家人工标记结果，并在手工线索台账中关联咨询、预约、核销等经营结果，形成“流里创作、库里沉淀、包里交接、台账里复盘”的最小闭环。

## User Stories

1. 作为首次使用的门店经营者，我希望在五分钟内理解产品并产出第一条可发内容，从而判断它是否值得继续使用。
2. 作为首次使用的门店经营者，我希望看到只读的示例美甲店与高质量示例内容，从而无需先录入全部资料也能理解最终价值。
3. 作为首次使用的门店经营者，我希望示例工作区不消耗额度并可一键隐藏，从而放心探索且不干扰正式经营。
4. 作为门店经营者，我希望从历史帖子、价目表截图和公开主页信息生成档案初稿，从而减少冷启动录入工作。
5. 作为门店经营者，我希望逐项确认或修改 AI 生成的档案初稿，从而避免未经确认的事实进入内容。
6. 作为门店经营者，我希望维护店名、城市、商圈、地址、交通和停车信息，从而让同城内容使用准确的到店信息。
7. 作为门店经营者，我希望维护项目名称、价格、时长、适合人群和注意事项，从而让内容来自真实服务信息。
8. 作为门店经营者，我希望维护品牌音、人设语气、主推卖点和禁忌话术，从而让生成结果更像本店而不是通用模板。
9. 作为门店经营者，我希望在门店档案中记录平台、账号昵称、主页链接、认证状态和备注，从而保留 P0 所需的账号基础事实。
10. 作为医美/医疗商家，我希望在准入时记录机构资质、平台认证和广告审查证明，从而让后续提醒基于真实资质档案。
11. 作为门店经营者，我希望未确认的价格、活动和资质不能进入发布包，从而避免把猜测当成经营事实发布。
12. 作为门店经营者，我希望能随时更新档案并保留确认记录，从而让后续内容使用最新且可追溯的信息。
13. 作为移动端店员，我希望从桌面快捷入口直接打开相机、拍摄并上传，从而把素材采集压缩成一次动作。
14. 作为移动端店员，我希望上传后自动获得项目、风格和用途标签建议，从而无需事后整理大量文件。
15. 作为门店经营者，我希望区分真实素材、AI 生成素材、已用于内容的素材和回收站，从而快速找到可用资产。
16. 作为门店经营者，我希望为素材记录权利人、授权范围、人物与敏感信息状态，从而知道它能否用于公开营销。
17. 作为门店经营者，我希望 before/after 或顾客案例只有在授权状态确认后才可被引用，从而降低敏感素材误用风险。
18. 作为门店经营者，我希望未成年人素材不能进入公开营销或付费广告，从而遵守更严格的个人信息保护要求。
19. 作为门店经营者，我希望撤回授权的素材进入下架或替换队列，从而停止后续使用并处理已关联内容。
20. 作为门店经营者，我希望按项目、平台、用途、授权和合规状态筛选素材，从而快速选出本次创作可用的真实素材。
21. 作为门店经营者，我希望素材不足时收到具体拍摄清单，从而知道下一次应该拍什么，而不是只看到“素材不足”。
22. 作为门店经营者，我希望 Agent 工作台用一句拟人化、专业且口语化的开场建议我今天做什么，从而降低开始创作的心理成本。
23. 作为门店经营者，我希望通过打字、拍照传图或粘贴文本表达需求，从而使用手边最方便的输入方式。
24. 作为门店经营者，我希望通过一行场景 chips 快速选择新客拓客、项目种草、口碑晒单等目标，从而绕过提示词写作。
25. 作为熟练用户，我希望展开完整场景货架并逐步调整高级字段，从而在需要时获得更多控制而不增加默认复杂度。
26. 作为门店经营者，我希望所有可编辑字段都有合理的 AI 默认值、常驻说明和回到 AI 版本的操作，从而不用面对空表单。
27. 作为门店经营者，我希望价格字段不由模型预填，必须来自价目表、活动表或我的确认，从而避免编造价格。
28. 作为门店经营者，我希望 Hook 作为独立可选槽位并可使用爆款开场脚本库，从而快速改善内容第一段或前三秒。
29. 作为门店经营者，我希望在执行前看到可编辑的 brief 确认卡，从而确认目标、平台、素材、语气、转化钩子和额度消耗。
30. 作为门店经营者，我希望 brief 编译和提示词工程对我不可见，从而只处理业务语言而不是技术参数。
31. 作为门店经营者，我希望一次获得三条文案候选并能三选一或换一批，从而在选择质量与生成成本之间取得平衡。
32. 作为门店经营者，我希望生成小红书标题、正文、话题、私信引导和图片顺序建议，从而得到可直接整理发布的笔记。
33. 作为门店经营者，我希望生成抖音 15/30/60 秒口播、开头钩子和结尾转化，从而适配不同视频节奏。
34. 作为门店经营者，我希望使用“更口语”“更专业”“弱化广告感”“加同城定位”等快捷改稿，从而快速迭代而无需重写需求。
35. 作为门店经营者，我希望每次改稿形成新版本并可撤销，从而保留历史结果并避免误操作丢失好版本。
36. 作为门店经营者，我希望内容优先引用本店真实素材、档案和历史内容，从而让结果具有本店辨识度。
37. 作为门店经营者，我希望同一内容母体可形成小红书和抖音平台变体，从而保持核心事实一致并适配平台表达。
38. 作为门店经营者，我希望在内容卡上看到推荐平台、转化钩子、素材来源和合规状态，从而判断内容是否可用。
39. 作为门店经营者，我希望将选中的候选保存到内容库，从而在创作流结束后继续管理和发布。
40. 作为门店经营者，我希望内容库 P0 界面只突出草稿和已发布两态，从而不被复杂运营状态淹没。
41. 作为门店经营者，我希望从内容库打开详情、再改一版、生成平台变体、生成发布包和关联线索，从而围绕同一内容连续工作。
42. 作为门店经营者，我希望能从已有优质内容发起“做同款”，从而复用有效结构而不是复制旧文案。
43. 作为门店经营者，我希望视频生成先给出 AIDA 分镜并允许逐镜确认或替换，从而在消耗昂贵生成额度前控制叙事。
44. 作为门店经营者，我希望分镜映射为探店钩子、痛点共鸣、项目或手法特写和到店引导，从而符合美业短视频结构。
45. 作为门店经营者，我希望系统基于真实素材和已确认 brief 生成首帧候选，从而保证视频视觉起点与本店相关。
46. 作为门店经营者，我希望系统生成视频片段并按美学、画质和合规择优，从而减少明显不可用的成片。
47. 作为门店经营者，我希望片段被合成为带字幕、BGM 和可配置产品标签的竖屏短视频，从而得到可交接的完整文件。
48. 作为门店经营者，我希望产品品牌水印与产品侧 AIGC 标识可以在创作阶段开关，并且实际 provider/platform provenance 被记录，从而在发布时按平台规则处理。
49. 作为门店经营者，我希望视频文件同时写入隐式 AIGC 元数据，从而满足文件级追溯要求。
50. 作为门店经营者，我希望视频任务提交后可以离开页面并在返回时恢复状态，从而不必等待十几分钟。
51. 作为门店经营者，我希望任务中心显示排队、运行、需要处理和完成状态，从而随时知道下一步是否需要我操作。
52. 作为门店经营者，我希望视频完成或需要处理时通过连接桥收到通知，从而在常用协作工具中及时回来处理。
53. 作为门店经营者，我希望成片生成成功后可以直接预览、存相册或加入发布包，从而完成从生成到发布的交接。
54. 作为门店经营者，我希望成片不满意时可获得最多两次免费重试，从而降低单发候选的质量风险。
55. 作为门店经营者，我希望技术失败自动退还视频额度并留下记录，从而不会为无产物的任务付费。
56. 作为门店经营者，我希望在发起内容或视频生成前看到本次消耗与剩余额度，从而做出知情决定。
57. 作为门店经营者，我希望系统只在任务成功时提交用量，在取消、失败或超时后正确释放或退还预留，从而保证账目可信。
58. 作为门店经营者，我希望刷新、重试或重复点击不会重复扣费或创建重复任务，从而避免网络波动造成损失。
59. 作为门店经营者，我希望普通广告法风险得到内联提醒和可直接采用的替换表达，从而快速修正而不是被迫中断创作。
60. 作为门店经营者，我希望行为红线命中时看到“不指责、讲原因、给替换、归还控制权”的四段式说明，从而理解限制并继续合规创作。
61. 作为平台运营者，我希望违法不良信息在生成前后都被检测并停止生成或传播，从而履行服务提供者的内容安全义务。
62. 作为平台运营者，我希望连续三次或单日累计五次恶意输入触发服务暂停与留痕，从而阻止持续滥用。
63. 作为平台运营者，我希望所有 AI 生成或实质改写的文本、图片和视频都记录 AIGC 状态，从而证明标识覆盖完整。
64. 作为门店经营者，我希望复制、下载、导出和发布包中的内容都带有明确的 AI 生成标识，从而不会因交接链路丢失披露。
65. 作为医美/医疗商家，我希望资质缺件时看到强提醒但仍可保存草稿，从而先完成创作再补齐发布核验。
66. 作为医美/医疗商家，我希望采用或发布 AI 内容时确认“已审阅、内容由本店负责”并留下版本化记录，从而明确责任边界。
67. 作为医美/医疗商家，我希望伪造资质、未授权案例、疗效保证、未批药械、移除标识或绕过审核的请求被硬停止，从而避免高风险行为进入产物。
68. 作为医美/医疗商家，我希望 Preflight 显示机构资质、诊疗范围、广审证明、平台规则和素材授权提醒，从而在人工发布前完成必要核对。
69. 作为门店经营者，我希望发布默认生成 L3 发布包，从而不依赖平台 API、浏览器自动化或凭据托管。
70. 作为移动端店员，我希望扫描二维码把发布包转到手机，从而在常用设备上完成平台发布。
71. 作为移动端店员，我希望标题、正文、话题和引导语可分段一键复制，从而适配平台不同输入区。
72. 作为移动端店员，我希望图片和视频可保存到相册并有下载兜底，从而应对 iOS 分享或相册权限差异。
73. 作为移动端店员，我希望发布包提供平台对应的 checklist，从而不遗漏 AIGC 标识、地点、话题和人工核对步骤。
74. 作为门店经营者，我希望行为红线内容不能创建发布包，而普通 warning 或资质提醒内容可在留痕后继续，从而让风险等级与动作匹配。
75. 作为门店经营者，我希望人工发布后能标记平台、账号、时间和链接，从而让内容库反映真实发布结果。
76. 作为门店经营者，我希望未来 L1 官方能力失败时可降级到 L3 发布包，从而始终保留可交付路径。
77. 作为门店经营者，我希望手工新增私信、评论、加微、预约、团购券、核销和到店线索，从而记录平台无法自动读取的经营结果。
78. 作为门店经营者，我希望从内容详情直接创建线索并自动关联内容版本，从而减少重复选择和录入。
79. 作为门店经营者，我希望更新线索为新建、已联系、已预约、已核销或流失，从而跟踪最小业务进度。
80. 作为门店经营者，我希望为线索记录项目、金额和人工备注，从而保留复盘所需的上下文。
81. 作为门店经营者，我希望人工汇总哪些内容带来咨询、哪些互动高但线索低，从而决定下一批内容方向。
82. 作为门店经营者，我希望系统不把人工关联描述为因果归因，从而避免对内容效果做虚假承诺。
83. 作为陪跑运营人员，我希望查看门店档案、素材缺口、内容、发布包和线索的可追溯记录，从而提供边界清晰的使用辅导。
84. 作为陪跑运营人员，我希望不能代写或改写医美医疗声明性内容，从而维持工具辅导而非受托制作的边界。
85. 作为试点运营人员，我希望记录每家商户的 Day-0 网络可达性，从而区分技术不可达与产品无意愿。
86. 作为试点运营人员，我希望记录首条内容耗时、采用率、周产出、发布包使用和线索关联，从而判断 P0 是否达到产品验收。
87. 作为业务负责人，我希望 0–4 周先验证至少三家在不低于 399 元档位付定金，从而在扩大建设前验证真实付费意愿。
88. 作为业务负责人，我希望后续看到至少两家连续 8–12 周真实扣款和纯自助组四周留存，从而验证陪跑之外的持续价值。
89. 作为系统管理员，我希望所有业务数据按 workspace 隔离且跨租户访问被拒绝，从而保护门店、顾客和经营数据。
90. 作为系统管理员，我希望所有关键状态变更、工具调用、用量变化、合规结果和人工确认都带关联标识并可审计，从而重建一次完整执行。
91. 作为系统管理员，我希望顾客 PII 与人脸素材不发送到海外模型，从而满足验证期数据卫生规则。
92. 作为系统管理员，我希望模型、对象存储和通知能力都通过可替换适配器接入，从而支持后续国内云迁移。
93. 作为系统管理员，我希望视频供应商失败时任务可恢复、重试或退款，而不留下半完成业务事实，从而维持系统一致性。
94. 作为系统管理员，我希望能观察每个模型和视频任务的成本、耗时、成功率与质量结果，从而控制单位经济和供应商路由。
95. 作为系统管理员，我希望公开收费上线前完成备案、登记和页面公示 Gate 0，从而不在前置义务未完成时开放公众付费。
96. 作为门店经营者，我希望可在一次“本周内容”任务中生成 3–5 张内容卡，从而以有限成套产出安排一周内容而不进入复杂批量生产。

## Implementation Decisions

### 1. Scope and delivery gate

- P0 固定为“保 8”：门店档案、真实素材库、小红书/抖音文案生成、视频成片、内容库、做厚的 L3 发布包、合规 gate、手工线索台账。
- “缓 4”固定为图文渲染管线、能力矩阵四表、自动周报和完整用量账本。P0 只实现支撑保 8 所需的最小额度、退款和视频成本记录。
- “砍 6”固定为 L1 官方接入代码、全部 L2 与凭据保险库、内容任务收件箱、Skills 版本系统、Sources registry 和完整 Permission 三模式。
- 0–4 周阶段先做访谈、WoZ 陪跑和付费验证。进入 P0 build 的商业门槛是至少三家商户在不低于 399 元档位支付定金。
- Go 门槛是进入 build 的条件，不计入软件 Definition of Done；软件验收、试点产品指标和持续商业验收分别记录，不能用其中一组替代另一组。
- P0 不承诺固定 4–10 周交付。通过 Go 门槛后，按保 8 范围、视频 spike 结果和团队容量重新排期。
- P0 Done 要求保 8 端到端真实跑通，而不是八个孤立页面分别可演示。

### 2. Product skeleton and navigation

- 产品骨架为一个 Agent 工作台和三个轻量资产页：内容库、线索台账、门店档案。
- Agent 工作台是唯一主创作入口，不再提供独立副驾浮层。桌面端使用轻侧栏；移动端使用五槽 bottom nav：工作台、内容库、新建内容、线索、门店，其中“新建内容”聚焦工作台意图框。
- 账号中心和用量/套餐不作为 P0 一级页面。账号基础记录归入门店档案；额度只在顶部 meter、生成动作旁和账户抽屉显示。
- “流里跑、库里存”是交互边界：brief、过程旁白、候选、合规和任务状态在工作台创作流中出现；稳定内容资产进入内容库。

### 3. Workbench interaction model

- 工作台采用对话式外壳和结构化内核。自然语言负责接收意图和解释进度；业务关键值必须进入结构化 brief、字段、状态和产物对象。
- 首屏包含拟人化问候、今日建议 chips、中央意图框、场景 chips、创作时间线、异步任务浮标和 quota meter。
- 意图框支持打字、拍照传图和粘贴文本三种喂料方式；不新增产品内语音输入。
- L0–L4 降门槛内核保留，但重新容器化：默认一行场景 chips，按需展开场景货架；通过少量语义槽位确认内容类型、Hook 和场景；“做同款”采用逐槽确认；高级字段渐进展开。
- 字段默认不留空。非价格字段可以使用带 AI 标识的可编辑默认值，提供常驻说明、undo 和 revert-to-AI；价格、优惠和套餐数字必须来自结构化事实或用户确认。
- 文案采用三选一加“换一批”；视频采用单成片加最多两次免费重试。生成动作旁必须在执行前展示本次额度消耗与余额。
- 示例美甲店包含完整档案、已授权示例素材、三张高质量内容卡和一个发布包；只读、不计用量、可隐藏。示例质量是第一眼价值验收的一部分。

### 4. Store profile and account facts

- 门店档案保存基础位置、项目价目、服务注意事项、主推卖点、预约方式、品牌音、人设语气和禁忌。
- 冷启动可从历史帖子、价目表截图和公开主页信息生成初稿，但所有价格、活动和资质都必须经用户确认后才能进入发布包。
- P0 账号基础记录仅保存平台、展示名、主页链接、认证状态和人工备注。完整账号能力矩阵、健康状态、凭据保险库和独立账号中心后置。
- 医美/医疗商户在销售准入阶段录入机构主体、执业许可、诊疗范围、平台认证、广告审查证明、有效期和承接时间。以上信息保存为独立的 workspace/store 级 Qualification Profile，并在每次 Preflight 中记录所用资质快照。未通过线下筛选的商户不进入试点。

### 5. Real asset library and rights

- 对象存储只保存二进制文件；素材 metadata、授权、敏感性、合规状态和 workspace 权限保存在业务事实库。
- 素材核心事实包括来源类型、权利人、授权范围、是否含人物或敏感个人信息、是否涉及未成年人、脱敏状态、AIGC 状态和权利证据。
- 授权范围至少区分内部参考、发布包、公开营销和付费广告。before/after、顾客案例、人脸及医疗健康相关素材必须有单独同意和明确范围。
- 未成年人素材不得用于公开营销或付费广告；撤回授权后进入下架/替换队列，并阻止新内容引用。
- 移动端上传优先验证 PWA 生产构建、相机选择层和 iOS 存相册双保险。上传完成后自动建议标签，但最终 metadata 可由用户修改。
- P0 使用结构化标签与筛选，不引入向量检索。素材不足时由 Agent 生成具体拍摄清单。

### 6. Copy workflow and content model

- P0 自动生成范围仅包含小红书和抖音。大众点评项目介绍、公众号/私域短文、评论/私信话术只可在 WoZ 中验证或后置。
- P0 支持两种有限产出：单条内容生成三条文案候选，或一次“本周内容”任务生成 3–5 张内容卡。任意数量批处理、多项目队列、自动排期和团队批量审稿属于 P1。
- 文案生成读取已确认门店档案、项目价目、素材标签、授权状态、历史内容、平台规则、场景包、Hook 库和合规规则。
- 内容模型以 Content Item 为母体，关联 Platform Variant、Version、Asset Link、Compliance Result、Publish Task 和 Lead Link。
- 文案候选包含标题、正文、话题、封面文案、素材顺序、转化钩子、推荐平台和合规状态。图文部分只输出封面与排序建议，不在 P0 自建渲染管线。
- 每次改稿创建新版本；采用、保存、状态变化和素材关联均写审计事件。用户可 undo，并可恢复 AI 默认版本。
- 内容库 P0 UI 只突出草稿和已发布两态，但持久化模型保留完整生命周期：`draft`、`review_required`、`ready_to_package`、`package_created`、`published`、`needs_manual_action`、`failed`、`archived`。
- 平台变体状态为 `draft`、`ready_for_review`、`ready_to_package`、`package_created`、`published`、`archived`。`ready_to_publish` 不是合法状态。

### 7. Finished video workflow

- 视频成片是 P0 主打功能，不是脚本建议。主链路为：AIDA 分镜确认 → 首帧候选 → 视频片段 → N→1 质量评估 → ffmpeg 薄合成 → 按开关处理产品标签并记录 provider/platform provenance 与 metadata → 对象存储 → 存相册或加入 L3 发布包。
- 模型能力通过可切换供应商购买。首选技术路线为 Seedream/Seedance 直调或即梦/可灵直调；KickArt 只作为范式参考和第三技术候选，不订阅套壳。
- 分镜作为流内可确认的过程产物，至少包含 Hook 和镜头列表。美业默认映射为探店钩子、痛点共鸣、项目/手法特写和到店引导。
- 视频质量评估使用美学、画质和合规三维。医美/医疗场景把违禁词、功效承诺和素材授权纳入合规评分。
- 分镜生成可以消耗内容额度；只有用户确认分镜后才创建视频成片任务并 reserve 视频额度。刷新或重复确认必须复用同一幂等结果。
- ffmpeg 薄合成壳只负责拼接、字幕、BGM、按开关处理产品标签、记录 metadata 和文件交接，不提供专业时间线编辑器。
- 视频成片只有在可读取文件、所选产品标签开关已按配置处理、供应方/平台 provenance 与实际 metadata 已记录且任务结果已关联时才能标记为 `completed`；标签不是固定不可关闭的创作门禁。
- 视频产物保存分镜、首帧 manifest、片段 manifest、合成 manifest、供应商、模型、时长、画幅、对象 key、额度预留、合规结果和状态。
- 视频产物状态为 `queued`、`running`、`needs_action`、`completed`、`failed`、`archived`。分钟级任务必须支持提交即走、恢复、取消、重试和通知。
- 成片不满意最多提供两次免费重试；技术失败自动退款。免费重试与技术退款是两套独立规则，均需留痕。

### 8. Compliance and qualification

- 合规按三类责任拆分：我方生成式 AI 服务提供者义务由系统硬实现；我方受托处理者/潜在广告经营者义务由档案、协议、SOP 和留存实现；商家广告主责任通过提醒、审阅确认和审计留痕实现。
- 合规状态统一为 `unchecked`、`pass`、`warning`、`regulated_preflight_required`、`blocked`、`manually_confirmed`。
- 违法不良信息在生成前和生成后两次检测。命中时停止生成与传播、消除产物并按规则记录或报告。
- 滥用执行连续三次或单日累计五次规则，达到阈值后暂停服务并保存记录。
- 行为红线包含处方药/未批药械宣传、疗效或安全性保证、治愈率/有效率承诺、伪造资质、未授权顾客案例、伪造或绕过强制 provider/platform provenance/发布标识和绕过平台审核。关闭可选的产品侧 AIGC 开关不属于该红线；命中真正红线后不可 override。
- 普通广告法和价格表达风险返回 warning 与建议替换。拦截文案采用四段式：陈述限制且不指责、说明原因、提供一条可采用替换、提供继续编辑动作。
- 医美/医疗 Preflight 在发布包交接和未来 L1 提交前展示。资质缺件产生强提醒并记录“已展示”，但不把每条内容变成逐项审批；普通保存、导出和下载不触发它。
- AI 抽取但未经商家确认的价格、活动或资质事实不得用于发布包；已确认档案中的资质材料缺件只触发强提醒。只有伪造资质、未授权案例等行为红线阻断交付。
- Preflight 展示日志与责任确认分开建模。展示日志记录触发节点、展示时间和资质快照，不要求点击；医美/医疗内容在采用或发布节点另行记录一次版本化的“已审阅、内容由本店负责”确认。
- 顾客 PII、人脸及医疗健康信息不发送到海外模型。线索联系人信息遵循最小化、留存期限和 workspace 隔离。
- 提供投诉举报入口、处理流程与反馈时限。用户协议写明 AIGC 标识方式、用户义务、数据处理和内容责任边界。

### 9. AIGC labels

- AI 生成或实质改写的文本、图片和视频均记录内容级 AIGC 状态。
- 产品品牌水印与产品侧 AIGC 标识在创作阶段提供开关；文件型产物记录实际开关值、生成属性、服务提供者标识、内容编号及可得的 provider/platform provenance。
- 发布包和平台提交阶段按当前平台规则执行最终标识/审核要求；不得把平台门禁倒灌成普通创作门禁。产品不提供伪造或篡改 provenance 的能力，法务默认值待功能完整后终审。
- P0 验收应验证所选标识策略、实际 metadata 与发布交付记录一致，而不是假设所有创作输出都必须携带同一个不可关闭的显式标识。

### 10. Publishing and L3 handoff

- P0 默认且完整实现 `L3_HANDOFF_PACKAGE`。发布包包含二维码转手机、分段复制、图片/视频存相册或下载以及平台 checklist。
- L2 浏览器辅助不进入 P0 schema、路由选项或 UI；不托管 cookie，不做验证码绕过、私有签名或群控。
- `L1_OFFICIAL` 只保留合同和账号能力边界，P0 不实现平台连接器。未来只有账号能力状态为 verified 时才可启用，失败必须降级 L3。
- 发布包创建前检查内容、素材授权、价格事实、AIGC 标识与合规状态。`blocked` 不得进入 `ready_to_package`；`regulated_preflight_required` 先展示 Preflight 并留痕。
- 发布任务状态为 `preparing`、`compliance_pending`、`confirmation_pending`、`handoff_ready`、`publishing`、`published`、`manual_required`、`failed`、`archived`。
- 人工发布后记录平台、账号、内容版本、路由、合规结果、操作人、时间、失败原因和平台链接。

### 11. Lead ledger and manual insight

- 线索台账是手工经营记录，不是 CRM，也不声称因果归因。
- 线索保存发生时间、来源平台、类型、项目、可选金额、备注和状态，并可关联一个或多个内容版本。
- 线索状态统一为 `new`、`contacted`、`booked`、`redeemed`、`lost`、`invalid`。
- P0 支持商家或陪跑人员人工汇总“哪些内容产生咨询、哪些互动高但线索低、下周主推什么、缺什么素材”。自动周报后置。

### 12. Usage, pricing, refunds, and idempotency

- P0 额度类型包括内容、视频、发布包和存储；图文渲染和 account pack 额度后置。
- 额度变化采用 append-only usage ledger，流程为 reserve → commit 或 refund。任务、工具和 worker 不得直接修改余额。
- 用量状态为 `estimated`、`reserved`、`committed`、`refunded`、`failed_no_charge`、`expired`。
- 创建内容、视频和发布包等扣费动作必须使用幂等键。重复提交、网络重试、worker 重放和退款重试不得产生重复业务对象或重复账目。
- `refunded` 表示已有付费 reservation 且余额已恢复；`failed_no_charge` 表示在 reserve 前失败或该次 reservation 金额为零。两者都必须关联失败原因和原任务。
- 成功但不满意不退原额度。每次免费重试创建新的 job 和金额为零的 reservation，以 `quality_retry` 原因关联原成片；最多两次，第三次必须新 reserve 视频额度。
- 排队中或等待确认的任务取消后保证退款；运行中的取消为 best effort。若停止后没有可交付成片，向用户退款并把已发生的供应商成本记入内部成本日志；若取消到达前成片已经完成，则 commit 原额度并交付产物。
- 视频按条计价，但具体套餐额度必须等待 Week-1 spike 测出单条成本、端到端时长、可用质量率和标签开关/provenance 记录可行性后确定。
- 试点挂价为 Starter 199 元、Growth 499 元，onboarding 300–800 元单收；最终价格带由付费数据决定，不作为代码常量写死。

### 13. Notifications and long-running jobs

- P0 连接桥最小实现为飞书或企微群机器人 webhook，支持“本周内容就绪”“素材补给”“任务完成/需处理”和“人工复盘提醒”中的已启用事件。
- 个人微信自动化不实现，WoZ 阶段由陪跑群人工推送兜底。
- Durable job 持久化状态为 `draft`、`queued`、`running`、`waiting_for_approval`、`completed`、`failed`、`cancelled`、`refunded`。
- 工作台只投影用户需要理解的四态：`queued`、`running`、`needs_action`、`completed`；失败、取消和退款通过结果卡和账目状态解释，不伪装成完成。
- Worker 采用领取、租约心跳、完成和失败回写协议。任务中断后可以从已持久化步骤恢复，不重复执行已提交的外部副作用。

### 14. Runtime and system boundaries

- P0 运行拓扑为 Cloudflare Workers App Shell、单 Node 服务、单托管 Postgres 和对象存储适配器。
- App Shell 负责官网、认证 UI、dashboard 壳、typed BFF、上传签名和可选 chat endpoint，不拥有门店、素材、内容、合规、发布、线索或用量事实。
- 单 Node 服务包含 Core API 域模块、AI runner、durable step-runner、视频合成 worker、发布导出 job 和供应商适配器。
- Postgres 是唯一业务事实源，包含认证表。D1 不保存业务数据。对象存储 key 只是 artifact reference，不代表权限、授权或合规。
- AI runner 不直接修改业务表，只能通过 Core API tools 读写。视频 worker 不判断权限、扣费、合规或发布路由，只回写任务结果。
- 业务代码依赖 Runtime Port，而不直接依赖 AI SDK 或未来框架类型。P0 使用 Vercel AI SDK 和薄 step-runner；只有真实出现多分支、子流程或复杂人在环矩阵时才重新评估 Mastra。
- 模型 provider registry 支持文案、图像、视频和合规检测分别路由，并记录供应商、模型、耗时、成本和结果。
- 四服务拆分只在真实信号出现时进行：视频合成阻塞事件循环、Agent 发布节奏与 Core API 分叉、或 Postgres 出现测得的瓶颈。

### 15. API and domain contracts

- 外部业务 API 使用 `/v1`，App Shell 可通过 typed BFF 聚合或透传；BFF 不写业务事实。
- 工具命名统一为 `domain.snake_case`。发布层级通过 REST 资源和路由建模，不创建与 L1/L3 同名的 agent tools。
- 主要资源包括 workspace、store、project、qualification profile、account basic facts、asset、asset rights evidence、content item、platform variant、content version、video artifact、compliance result、preflight display event、content responsibility confirmation、publish package、publish task、lead、usage entry、agent run、tool call、durable job 和 audit event。
- 主要工作流包括生成本周内容、创建视频成片和创建发布包；图文套图与自动线索周报为 P1+ 保留合同，不在 P0 UI 暴露。
- 视频内部步骤至少包括生成首帧、生成片段和合成；所有 worker 结果必须回写 Core API 后才成为业务事实。
- 所有资源带 workspace、创建时间、更新时间和稳定 ID。跨 workspace 资源引用、对象读取和状态变更必须拒绝。
- 所有 API 返回统一 envelope 和稳定错误码。至少覆盖未认证、无 workspace 权限、非法状态流转、合规硬拦截、授权不足、额度不足、供应商失败和幂等冲突。
- 所有关键调用携带 correlation ID，并贯通 agent run、tool call、job、供应商调用、用量、合规和审计事件。

### 16. Deployment phases and portability

- 验证期 Cloudflare-first，允许国内外模型按质量混用，但顾客 PII 和人脸只路由国产模型或先脱敏。国产模型从第一天进入同一评测集。
- Cloudflare 专属能力必须位于 adapter 后，领域逻辑保持可移植的 Node/Postgres 实现。对象存储可从 R2 替换为 OSS/COS。
- 每个试点商户执行 Day-0 大陆网络可达性预检并留存结果。
- 公开收费上线前执行 Gate 0：算法备案、生成式 AI 服务登记和模型/备案号页面公示必须完成；若仍发生数据出境，完成相应合同与备案。
- 落地触发点不在本 spec 预设，由商业节奏决定；已知备案和 ICP 提前量进入项目风险计划。

### 17. Product acceptance and observability

- 激活目标：至少 70% 新店在五分钟内产出第一条可发内容。
- 内容质量目标：文案直接采用或小改采用率至少 60%。
- 持续使用目标：第 2–4 周至少 50% 门店每周产出或发布三条内容。
- 线索闭环目标：至少 60% 门店记录一条内容到线索的人工关联。
- 发布目标：继续开发线中的 L3 发布包使用率至少 60%。
- 合规目标：行为红线拦截覆盖率 100%，所选标签策略与 provider/platform provenance 记录一致率 100%，受监管内容发布阶段 Preflight 展示率 100%，敏感素材授权字段留痕率 100%。
- 视频验收必须记录每条成本、端到端时长、成功率、可用质量率、免费重试率、技术失败退款率和标识验证结果。
- 商业验收：至少两家连续 8–12 周真实扣款续跑，纯自助对照组四周留存至少 50%。

### 18. Implementation slices

- Slice 0 — Validation and spikes：先完成六项 Week-1 技术证伪与真实商户付费验证；任何未通过项必须有明确降级路径，不能用模拟结果宣称可交付。
- Slice 1 — Core facts：完成认证、workspace 隔离、门店与 Qualification Profile、项目价目、素材 metadata/授权、内容母体/变体/版本、合规结果、最小用量账本、agent run、tool call、durable job 和审计事件。
- Slice 2 — Onboarding and copy：完成示例工作区、档案初稿与确认、移动素材上传、Agent 工作台、brief、单条三候选与本周 3–5 内容卡、保存和改稿。
- Slice 3 — Video：单独完成创建视频成片、video artifact、分镜确认、首帧/片段/合成 worker RPC、任务事件、质量评估、标识与 metadata、对象存储、取消、免费重试和退款。视频不是 Slice 2 的可选子项。
- Slice 4 — Compliance and L3：完成违法内容/滥用、广告法替换、医美 Preflight 展示日志、责任确认、发布包四件套、人工发布标记和导出审计。
- Slice 5 — Lead and commercial loop：完成手工线索关联、人工洞察入口、额度展示、付费墙、试点指标采集和连接桥通知。
- 每个 Slice 必须先把对应业务旅程加入 E2E catalog，再实现代码；前一 Slice 的事实与状态合同稳定后才允许后一 Slice 依赖。

## Testing Decisions

### Primary test seam

- 主要且最高层的测试 seam 是“一个 workspace 内的 P0 业务旅程”：通过真实 App Shell UI 和 Core API，使用确定性的模型、视频供应商、对象存储、通知和支付替身，验证从门店档案与素材输入到文案/视频、合规、发布包、人工发布和线索关联的外部可观察结果。
- 该 seam 以 Playwright 为主，不断言 React 组件结构、step-runner 内部函数、SQL 实现或提示词文本。测试只观察用户可见状态、API 资源、导出文件、额度结果和审计结果。
- 现有 E2E 先例是本地优先的 Playwright harness、真实 Better Auth 登录、受保护路由与测试专用用户 API。新增业务旅程沿用相同的本地 `MODE=e2e`、隔离账号和受控清理方式。

### Journey coverage

- Onboarding journey：创建测试 workspace，生成并确认门店档案，验证未确认价格不能进入发布包，确认后可被内容引用。
- Authentication journey：游客访问工作台会进入登录流程；已登录但不属于目标 workspace 的用户收到拒绝，而不是空数据或资源是否存在的提示。
- Example workspace journey：示例美甲店可见、只读、不扣额度、可隐藏，且不会与正式 workspace 数据混写。
- Asset journey：移动上传会话、metadata、自动标签建议、授权状态和筛选可见；未授权 before/after 不能被内容或发布包引用。
- Copy journey：从场景 chip 和 AI 默认字段确认 brief，生成三条候选，采用一条、快捷改稿、撤销、保存并生成平台变体；刷新后版本与状态保持。
- Video journey：确认分镜后创建异步任务，页面离开再返回可恢复；任务按 queued → running → completed 投影；成片可预览、带字幕/BGM/显式标识、metadata 可读、可存相册并加入发布包。
- Video needs-action journey：需要逐镜确认或供应商返回可恢复问题时显示 needs_action，用户处理后从持久化步骤继续。
- Video failure journey：供应商失败不会生成 completed 产物，预留额度自动退款；重放同一 job 或重复退款保持幂等。
- Video cancellation journey：排队/待确认取消保证退款；运行中取消验证 best-effort 结果，只允许“无产物且退款”或“已完成且提交额度”两种一致终态。
- Free retry journey：成功但不满意可重试两次，第三次需要新额度；免费重试不误记为技术退款。
- Compliance warning journey：普通风险显示原因和替代表述，采用替换后可继续生成发布包，并保留原始与修订版本。
- Compliance block journey：疗效保证、伪造资质、未授权案例、移除标识和绕过审核被硬停止，无法通过直接 API 或 UI 绕过。
- Regulated preflight journey：资质缺件显示强提醒并写展示日志，但草稿仍可保存；采用/发布医美内容时单独记录版本化责任确认。
- AIGC label journey：文本复制内容、视频文件、发布包导出和二维码转移后的文件均保留显式标识；文件 metadata 包含隐式标识字段。
- L3 journey：发布包包含二维码、分段复制、图片/视频存相册和 checklist；人工标记发布后内容进入已发布视图并保存平台链接。
- Lead journey：从已发布内容创建线索，推进到预约或核销，刷新后关联保持；界面不显示自动归因结论。
- Quota journey：执行前显示消耗与余额；成功 commit，取消/技术失败 refund；重复点击、刷新重试和相同幂等键不会重复扣费。
- Tenant isolation journey：workspace A 的用户不能读取、关联、导出或修改 workspace B 的档案、素材、内容、视频、发布包、线索和额度。
- Worker isolation journey：伪造 workspace 的 job 回写、通知深链或对象 key 不能越权读取或关联其他 workspace 的资源。
- Data hygiene journey：捕获供应商请求，验证顾客 PII、人脸和医疗健康素材不会发送到海外 provider。
- Audit journey：一次成功视频发布链能用 correlation ID 追踪到 agent run、tool calls、durable job、供应商结果、compliance result、usage entry、publish package 和人工确认。
- Mobile journey：在目标 iOS Safari 尺寸验证相机入口、场景 chips、任务浮标、bottom nav、二维码、分段复制和存相册兜底，不出现文字或控件重叠。

### Narrow contract tests

- 只有无法稳定从浏览器断言的边界增加窄合同测试：供应商 adapter 的请求/响应映射、对象存储权限、ffmpeg 标签开关与 metadata/provenance、job 租约恢复、usage reserve/commit/refund 幂等，以及状态机非法流转。
- 模型与视频测试使用录制或手写的稳定 fixture，不在常规 E2E 中调用付费供应商。独立 smoke 环境再验证真实供应商凭据、成本和延迟。
- promptfoo 评测覆盖美业场景包、品牌音、价格不臆造、平台适配、广告法替换、医美红线和素材不足拍摄清单。评测失败阻止 prompt 或模型路由变更进入试点环境。

### Test quality bar

- 每个测试用业务结果命名，不用组件或内部函数命名。
- 每个 fixture 显式声明 workspace、授权状态、价格来源、监管类型和预期额度，避免隐式全局状态。
- 异步测试基于事件或状态轮询，不使用固定长 sleep。
- 异步进度只显示已知步骤和人话说明，不使用无法由真实步骤计算的假百分比。
- 失败断言同时验证用户解释、业务状态、额度结果和审计记录，防止只修 UI 提示而留下错误事实。
- 发布或大范围重构前运行完整 E2E；日常 CI 至少运行类型检查、构建、状态/用量合同测试和不调用真实供应商的核心旅程。

## Out of Scope

- 自建图文渲染管线、自由画布、图文卡片自动排版和多尺寸图片导出。
- 完整账号中心、账号能力矩阵四表、账号 packs、凭据保险库和平台 cookie 托管。
- 完整用量账本、全供应商成本分析页和独立用量/套餐一级导航；P0 仅保留最小额度、退款和视频成本事实。
- L1 官方平台连接器实现；P0 只验证账号级权限边界并保留未来合同。
- L2 浏览器辅助发布、浏览器扩展、私有 API 逆向、签名伪造、验证码绕过、住宅代理和群控。
- 自动周报、自动归因、平台表现自动读取和“内容导致成交”的因果结论。
- 完整 CRM/SCRM、评论/私信统一收件箱、自动回复和 7×24 值守 Agent。
- 内容任务收件箱、完整 Permission 三模式、Skills 版本系统和 Sources registry。
- 内容日历、批量铺量、团队审稿、店员转交链接、多门店集团或代运营 workspace。
- 专业视频时间线、逐镜专业编辑、数字人口播、批量百条视频和电商商品链接抓取。
- 大众点评、公众号、私域短文和评论/私信话术的正式自动生成能力。
- pgvector、泛化 RAG 平台和外部 Agent API key 管理。
- 产品内语音输入、口播提词器、周报转发长图和个人微信自动化。
- 自动投放、全平台自动发布承诺、未经核验提醒的医疗广告发布、诊疗建议和疗效保证。
- 公开注册与公开收费上线，直到 Gate 0 完成。
