# 开发规格：原地换壳保核 × D-101～D-131 产品合同全量落地（2026-07-25）

> 由 `/to-spec` 从 2026-07-24～25 Office Hours 决策层综合生成。权威来源：`docs/design/beauty-marketing-agent-product-design-2026-07-17.md`（D-101～D-131）、ADR-0013～0019、`docs/specs/bucket-disposition-matrix-2026-07-25.md`（223 行归桶终裁，用户已批准）、`docs/reviews/comprehensive-development-review-2026-07-24.md`（M/R/E 编号源）。冲突以决策日志为准（D-110 元原则：新裁决覆盖旧表述）。

## Problem Statement

单店单人的美业店主没有时间、没有专业能力做持续的宣发内容：写文案要学平台话术，做图要学设计工具，拍视频要学剪辑，发内容要懂各平台规则。现有产品要么是给专业运营用的工具箱（学习成本高），要么是模板套壳（产出千店一面）。

本代码库已有约 55 万行经真机验证的骨架（SaaS 底座、五段 Harness 编排、模型供给链、交付结果面），但当前交付面与 D-101～D-131 锁定的产品合同存在结构性断裂：新租户 Day-0 无法出活（装配失守——供给钩子未接、Harness 未激活）、输入到候选要走 8 步（对标产品 3 步）、图文没有合一交付物、平台变体合同单字段混淆内容语义与分发语义、旧交互面（槽位表单、旧 IA 页、compose/烧录链）与已拍板的对话式主线并存造成双轨混乱。

## Solution

**原地换壳保核（D-127）**：不重开、不整体重写。骨架保留+扩展，退役面真删，前端沿在途 Composer 主干换壳到 D-114 AGUI 对话流，新能力按 ADR-0019 纵切净新建。

交付后的产品形态：店主注册后进入「门店橱窗」风格的工作台，冷态看到三行业示例店与今日推荐，一句话（≤2 击）即可发起创作；定制主线＝agent 流式对话容器（意图正名→上下文注入→Brief 编译→执行择优→回装交付五段），产出四类输出（文案／图片／图文笔记／视频成片）；门店事实、品牌身份、素材经五步录入范式与 MinerU 解析管线沉淀为可复用资产；生成过程零内容限制、发布确认是唯一风控收口；计费＝套餐三桶（文案/图片/视频）+三类加油包，数字由运营后台手填。

执行序列单一权威（D-110）：**装配门（第 0 步）→ M-01～M-06 合入门 → R-01～R-08 试点/发布门 → E-01 发布工程门**；修复即建设（R 级修复直接按 D-101～D-109 目标形态实施）；退役与换壳按归桶矩阵批次执行。

## 接缝（Seams）

沿用既有接缝，不新增（ADR-0019；越高越少越好）：

1. **三进三出 HTTP+SSE 合同**（D-032/ADR-0013，主接缝）——任务提交→进度帧→交付物，合同测试全部打在这一层；前后端、四类编译器、计费扣点都经此缝验收。
2. **五段 Harness step 纯函数内核**（D-033/D-038①，次接缝）——step 级单测永不 import durable 载体（DBOS）。
3. **旅程级 e2e**（ADR-0019 DoD）——验收以旅程为单位：真服务启动、真数据点击；装配门「注册→首次出活」是第 0 号 required 旅程。
4. **前端组接缝**（D-131）——前后端同旅程拆票时，接缝合同与属主显式写在票面；前端组内部自闭环不接真后端＝未完成。

## User Stories

**注册与 Day-0（装配门）**
1. 作为新店主，我要用邮箱+兑换码完成注册（运营可代开账号），这样试点期不依赖短信通道就能进入产品。
2. 作为新店主，我注册后平台已备好默认模型栈（文案=deepseek-v4-pro、图=seedream-5-pro 系、视频=seedance-2 系）与试用额度，这样 Day-0 不用做任何配置就能出活。
3. 作为新店主，我在冷态首页能看到三个行业示例店与示例作品，这样我第一眼就理解这个产品能为我产出什么。
4. 作为新店主，我点击示例任务能真实执行（扣试用额、产物允许导出、口径与正式使用一致），这样试用体验就是真实体验。
5. 作为店主，我从注册到拿到第一份可用内容不超过一次对话（≤2 击、零前置表单），这样我不会在门槛上流失。

**定制创作主线（对话容器）**
6. 作为店主，我在一个流式对话容器里说一句话就能发起创作，agent 会把我的口语表述正名为创作意图，这样我不需要学任何专业词汇。
7. 作为店主，条件缺失时 agent 用渐进引导轻问补齐而不是弹表单拦截，这样流程永远在前进。
8. 作为店主，我能看到 agent 的阶段宣告、确认卡与任务总结都是拟人化交付语言（不出现工程术语、成本价、内部 ID），这样我感到在与专业顾问协作。
9. 作为店主，意图确认卡有默认值并超时自动继续，这样我不回应也不会卡死任务。
10. 作为店主，执行中我可以介入修正（改方向、换素材、调文案），流程接受修正后继续前进而非推倒重来。
11. 作为店主，我提交时确认的平台、交付物与模型设置就是最终执行的设置（服务端签名冻结，无静默覆盖），这样所见即所得。

**自由创作与 Pro Studio**
12. 作为熟手店主，我可以走自由主线直接下指令生成，不被定制流程绑架。
13. 作为高阶店主，我能看到 Pro Studio 入口（自由创作高阶版定位），当前冻结状态下不误导我可用。

**四类输出——文案**
14. 作为店主，我要一句话产出平台适配的文案（轻输出走五段退化执行），几秒到几十秒内流式看到结果。
15. 作为店主，文案候选默认单主候选（择优收窄），我不用在一堆平行选项里做选择题。

**四类输出——图片**
16. 作为店主，我用商家语言描述图片需求（做一张/改一改/换个说法三操作），不需要懂提示词。
17. 作为店主，图片上的促销价格、门店名等精确文字必须与我确认的事实一致（精确文字校验门），错字图不会交付给我。
18. 作为店主，图片产出走七类语义 slot 的 ImageIntent 合同，我改需求时 agent 知道我在改哪个语义位。
19. 作为店主，改图操作按次计入图点额度并在动工前展示用量预估。

**四类输出——图文笔记**
20. 作为店主，我要的「图文」是合一交付物（NotePlan 页级计划：封面/痛点/方案/案例/价格/引导页结构由语义决定），不是文案与图片两次分开提交。
21. 作为店主，图文默认给我双风格草稿（干货科普/种草叙事），配图跟随我选中的版本。
22. 作为店主，单页不满意可以只重生成那一页（计 1 图点），不用全包重来。
23. 作为店主，图文全包在交付前经过五维一致性评估回炉，这样图与文不打架。

**四类输出——视频成片**
24. 作为店主，我要模型原生直出的视频成片（单调用，不走 ffmpeg 拼接链），亮点定位对齐套餐档位（3/6/9 条每月）。
25. 作为店主，视频任务超时或失败时 agent 白话申报并给出补救选项，额度不被白扣。
26. 作为店主，视频产物与图文一样进入统一结果面与工作区，可回看可导出。

**分发与平台变体（M-01）**
27. 作为店主，我只回答「发到哪/用在哪」一个问题，系统内部把它映射为内容变体（小红书/抖音/视频号）与分发方式（导出/手动复制/协办交接/代发）双字段，我不感知工程拆分。
28. 作为店主，朋友圈是交付目标（拿图文去发）而不是变体主体，我选朋友圈时得到的是适合私域转发的成品与协办指引。
29. 作为店主，能否代发在提交前就展示清楚（可代发/生成后导出复制），不存在提交后才报错。

**门店事实与录入（M-02 + 五步范式）**
30. 作为店主，首次录入走五步范式：看示例卡→行业推荐→一句话+拍照代填→AI 编排→逐项确认，全程不超过几分钟。
31. 作为店主，我上传价目表截图/团购链接后，系统解析提取事实（MinerU 官方 API）、我逐项确认后入门店事实账本，此后创作直接引用不再重复问我。
32. 作为店主，上传外部文件解析时我能看到一句温柔的文字提示（数据经第三方解析服务处理），不设门槛不阻断。
33. 作为店主，Recipe 需要的事实（如团购价）优先由我已确认的门店事实满足，不会要求我把确认过的事实再用文本文件传一遍。
34. 作为店主，事实缺失时 agent 按我的意图判断关键性：核心事实轻问补齐并顺手入账本，可省略事实直接生成并在结果侧提示。
35. 作为店主，过期或已撤销的事实绝不会被用进内容（确定性硬校验），这样我不会发出过时价格。
36. 作为店主，批量录入走异步、单件走同步，我在对话里能看到解析进度而不是干等。

**品牌身份与发布收口（M-03 + D-117）**
37. 作为店主，营销身份建档是向导式的、可跳过的，Day-0 没有身份也能出活（中性身份），身份不是创作的前置闸门。
38. 作为店主，我有多个身份（门店号/个人 IP）时可显式选择并被记忆为默认，移动端同样能进入身份与素材管理。
39. 作为店主，生成过程零内容限制（允许美化演绎），软提示随行；发布确认是唯一风控收口，AI 生成提醒标识在发布位呈现。
40. 作为店主，发布确认、导出、协办交接三动作分离，各自绑定内容 revision，我确认的就是我拿到的。
41. 作为店主，涉敏感素材（客户面部等）的权利标记与数据政策是硬校验，不能被任何流程降级绕过。

**内容工作区（D-121）**
42. 作为店主，我有一个与租户严格分离的内容工作区，沉淀我的个性资产（作品、素材、事实、身份），按套餐 1/2/3 个+加油包扩容。
43. 作为店主，创作时可以引用工作区资产作为上下文入口，agent 自动注入相关事实与风格。
44. 作为店主，示例店资产（platform_sample）与我的资产隔离展示，不混入我的工作区。

**首页与日常经营（D-126）**
45. 作为店主，热态首页每天给我一条主推荐（确定性规则+行业先验），点击即预填充创作对话，这样我每天打开就知道今天发什么。
46. 作为店主，首页展示我的额度余量与本月产出概览，缺额提醒、超额报停。
47. 作为店主，待办与审批集中在收件箱（批准请求恰一次消费），不会散落各页找不到。

**计费与套餐（D-123/D-124）**
48. 作为店主，套餐额度分三桶（文案点/图点/视频点），用量预估在动工前展示，扣点凭执行回执。
49. 作为店主，额度不够时可买三类加油包，缺额时 agent 提醒并给出选项而不是静默失败。
50. 作为店主，试点期我用兑换码开通付费能力（支付零开发承接），后续升级不换账号。
51. 作为运营，我在后台手填价格与额度数字（数字＝运营参数，线下核算），改数字不用发版。
52. 作为运营，我能人工动态开关/调整试用状态与试用额度，滥用应对靠运营收紧而非预建防滥用系统。

**运营后台（D-107/D-130）**
53. 作为运营，我在模型装配后台管理供给目录（型号可换：DeepSeek/方舟直连/tuzi 容灾），带 CAS 审计与回滚。
54. 作为运营，Recipe Studio 让我用受控积木组装行业 Recipe（载体=PG 既有库），不用改代码上新玩法。
55. 作为运营，Skills 是一等能力单元（提示词走 Langfuse 版本化），我能受理、冻结、回滚提示词变更。
56. 作为运营，后台可视化（用量/任务/租户）基于 template-dashboard 组装，与商家前台视觉分离。

**Landing 与门面（D-125）**
57. 作为潜在用户，Landing 页诚实呈现产品当前真实能力（阶段一只改文案与前后链接），不夸大不预售未有功能。

**换壳一致性（D-127/D-130）**
58. 作为店主，全产品（对话容器、作品页、门店页、身份管理）是统一的门店橱窗视觉语言（Glass 主题），不再出现新旧两代界面并存。
59. 作为店主，旧交互面（槽位表单、旧任务收件箱、旧内容库）整批下线后，我在新主线都能完成原有任务，不需要回访旧页面。

## Implementation Decisions

**路线与批次**
1. 开发路线＝原地换壳保核（D-127）：KEEP_EXTEND 156 行保留扩展；RETIRE 48 行真删（git rm，分四批：1A 立即删≈36 行/12,764 行代码已批准；1B 迁移完成后删；1C 模型原生视频切换后删；1D 换壳完成后删）；FREEZE 7 行原地运行不投入（Pro Studio 全冻结仅留入口）；REBUILD 10 行沿 Composer 主干换壳；NEW 8 项纵切净新建。每票动工前查归桶矩阵，禁止在 RETIRE 桶续命、在 REBUILD 桶打补丁。
2. 执行序列（D-110）：装配门（第 0 步 required 旅程：注册→默认栈→首次出活）→ M-01～M-06 → R-01～R-08 → E-01。修复即建设：R 级修复直接按 D-101～D-109 目标形态实施；每项动工前对照校准。
3. god module（model-supply/operations）触碰时拆，不开专项重构票（D-127）。

**领域合同**
4. platform 双字段合同（M-01/D-112）：`contentPackagePlatform`（内容语义：xiaohongshu/douyin/video_account/wechat_moments/offline_material/generic）×`distributionTarget`（分发语义：export/manual_copy/assisted_handoff/publish:<platform>）；UI 单一「发到哪」，LLM 映射双字段；提交 Body→服务端签名 preview/quote→admission 冻结；同一 Recipe validator 覆盖发布/提交/全部正式 seed。
5. 事实槽（M-02/D-112 场景规则退位首例）：Recipe 声明结构化事实需求（factTypes 对齐 StoreFact 账本既有分类），已确认 StoreFact＝第一等满足来源，LLM 判断满足度三态，expiry/撤销/权利走确定性硬校验；部分满足＝LLM 按意图判事实关键性。
6. admission 场景规则冻结（D-112）：硬编码只保四类底线——事实真实、权利授权、产品额度、外部发布确认；其余场景适配一律 LLM 判断+确定性兜底。
7. 四类输出编排分级（D-118/ADR-0013）：copy=五段退化执行非旁路（prompt 模板+人设注入+单调用）；image=ImageIntent v1（三操作/七类 slot/exactText 校验门/OutputPlan 两型）；image_text_note=NotePlan v1 多阶段编排（页级计划→图并行文串行→五维评估回炉），R-01 验收对象＝ImageTextNote 全包；video=模型原生单调用直出（AgentKit 双参照，借组合模式不引 runtime）。
8. 交互架构（D-114/ADR-0014）：定制主线＝agent 流式对话+AGUI 三层卡片结构，session 一等容器；Day-0 与条件缺失＝双入口分流+意图驱动渐进引导（D-111）；HITL 三允许（D-122）：允许幻觉、允许工具微错、允许人介入修正，流程恒前进。
9. 发布收口（D-117）：生成自由/软提示/发布确认唯一风控收口；发布/导出/协办三动作分离、绑 revision。
10. 录入与解析（D-119/D-120/ADR-0017）：五步录入范式、双轨同链、录入永不前置；解析统一 MinerU 官方精准 API（温柔文字免责、不设门槛；自托管挂 E 门）；四层表结构，ContextBundle 只吃确认层。
11. 计费（D-123/ADR-0016）：三桶额度+三类加油包；内部成本基准只存 D-123 永不进前台；数字＝运营参数后台手填；示例任务真实扣试用额、产物允许导出（D-128）。
12. 注册（D-128/D-124）：试点期＝邮箱+兑换码+运营代开；手机号短信挂 E 门。产品命名挂 R 门前专项（不阻塞拆票）。

**组件与供给（D-129/D-130）**
13. 文案与全部文本判断位默认 LLM＝DeepSeek，默认型号 deepseek-v4-pro（轻量回退 v4-flash），OpenAI 兼容经 AI SDK 接入，供给目录运营可换；官方文档镜像为唯一集成参照，勿凭模型记忆写旧型号名。
14. 图默认 seedream-5-pro 系、视频默认 seedance-2 系；通道默认方舟直连、tuzi relay 容灾；exactText 校验＝既有多模态 VLM 零新件。
15. 基础组件 MkFast/Cloudflare 优先：邮件=Resend、对象存储=R2；Recipe/Skills 载体=PG 既有库、提示词=Langfuse（D-037）。
16. 前端组件供给基准＝HeroUI Pro V3（用户专属授权，镜像不入库不分发）：REBUILD/NEW 面优先取用组件与动效；AI Chat 组件族对 D-114 对话流；template-chat=工作区交互页起点、template-dashboard=运营后台起点；主题=Glass；门店橱窗 DESIGN.md 仍为唯一视觉权威（组件经 token 适配）；KEEP 桶不为换库迁移、触碰时换；Landing 例外保持现状。
