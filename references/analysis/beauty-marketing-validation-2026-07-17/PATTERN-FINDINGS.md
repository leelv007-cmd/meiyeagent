# 三平台第一轮发现与产品判断

- 日期：2026-07-17
- 状态：第一轮公开证据，待门店任务回放
- 平台：抖音、小红书、大众点评
- 证据窗口：2026-06-18 至 2026-07-17；抖音只统计页面已复核日期的代表作品，不把 ID 推算当发布日期

## 结论先行

这轮公开证据支持继续验证“美业宣发经营 Agent”，而不是直接扩成内容生成工具集合。正式 9 条门店观测中，稳定共性是内容围绕具体项目、服务或门店体验，并带有可识别表达身份；日常服务曝光和促销入口分别在至少 3 家、至少 2 个业态重复。其他入口和精确交互仍是探索假设。

但目前只能证明公开成品与页面结构，不能证明内部由谁发起、为什么选择、谁审核、是否带来到店。产品应把公开证据用于建立候选场景和资产编排规则，把主观选择、真实摩擦与经营结果留给后续门店任务回放。

## 正式门店观测中的共性

正式判断只使用 9 条已核身门店观测。至少 3 家独立门店、至少 2 个业态重复，才记为本轮 B 级门店共性；这仍是本样本内结论，不外推为行业渗透率。

### 主入口计数

| 主入口 | 正式观测 | 覆盖门槛 | 当前结论 |
| --- | ---: | --- | --- |
| 日常项目/服务曝光 | 3 / 9 | 达到至少 3 店、至少 2 业态 | B 级门店共性 |
| 促销/团购/到店转化 | 3 / 9 | 达到至少 3 店、至少 2 业态 | B 级门店共性 |
| 品牌/个人 IP | 2 / 9 | 未达到 3 店 | 保留为 D 级候选 |

| 日常宣传物料 | 0 / 9 | 无正式观测 | 仅记录证据缺口 |

因此，本轮能进入共性层的主入口只有“日常项目/服务曝光”和“促销/团购/到店转化”。品牌/IP、借势和日常宣传物料仍需继续验证，不能因发现层账号多次出现或个别案例突出而提高产品决策权重。

### 成品组合维度

| 组合维度 | 正式观测 | 当前结论 |
| --- | ---: | --- |
| 具体项目、服务或门店体验 | 9 / 9 | 是本轮最稳定的内容对象共性 |

正式观测支持的规律是：内容首先围绕可识别的项目、服务或门店体验，并带有明确表达主体；节点语境可以参与编排。促销是已重复出现的经营入口，但“明确 CTA 如何呈现”尚无足够证据。其余精确产品交互均保持 D 级，等待门店任务回放达到 C 级验证。

## 关键模式与反例

### 1. “经营机会”是高价值入口假设，不是已证实的真实起点

正式门店观测稳定出现具体项目/服务/门店体验与可识别表达身份，节点语境达到本轮共性门槛；发现层还出现经营目标、素材、历史内容和预期成品等可能起点。但公开页面不能证明门店内部任务实际从哪里开始，明确 CTA 也只有 1 / 9，不能把发现账号或单条作品直接固化为入口设计。

下一轮原型应并列验证经营目标、Agent 发现的机会、已有素材、历史做同款和预期成品五种起点。无论从哪里开始，系统都应收敛到一个完整主推荐，而不是把图文、视频、海报生成器并列成工具迷宫。该交互判断仍为 D 级，需 C 级任务回放确认。

### 2. 身份歧义反复出现；后台解析方案仍是 D 级

原大众点评 12 家锚点在小红书近 30 天严格同店匹配为 `0 matched / 2 probable / 10 not_found`；抖音为 `1 matched / 7 probable / 4 not_found`。两个平台都反复出现同品牌异店、近似店名、品牌账号缺分店字段和 UGC/商家账号混杂，这不是由某一个案例推出的规则。

这组发现支持继续验证后台身份解析，但还不能冻结精确数据关系或前台问法。当前 D 级方案是区分 `brand`、`store_branch`、`publishing_account`、`speaker_identity`、`promoted_store` 和平台稳定 ID，由 Agent 优先自动解析并给出置信状态；只在真实任务被身份歧义阻塞时，测试一句最小消歧。具体字段、阈值、问法和默认行为都需门店任务回放达到 C 级后再定。

### 3. 热点来源存在明显噪声；“机会解释器”是 D 级产品假设

- 抖音 `activities` 能返回 `activity_id/title/end_time`，适合形成有截止时间的节点候选，但规则与资格仍需复核。
- 抖音 `hashtag hot --keyword` 对四个美业词返回完全相同的全局榜，不能作为行业过滤。
- 小红书搜索能提供日期、笔记和表达结构，但旧内容、同名作者和泛语义假命中都存在。
- 城市写进查询不等于内容已经具有地域证据；必须在正文、标签、账号或 POI 中再次命中。

因此不能把热词命中直接当作推荐依据。当前 D 级原型可测试一张“机会解释卡”，尝试说明来源、抓取时间、过期时间、与本店的关系、命中的本店资产、可借机制及不可复制的原作与事实；卡片字段、顺序和是否需要单独成卡，均待 C 级任务回放验证。

### 4. 多资产共同编排是 D 级方案，不是已验证交互

正式观测证明成品普遍围绕具体项目/服务/门店体验，并带有可识别表达身份；但其他资产组合和精确编排方式尚未被验证。当前 D 级原型可尝试编译：

```text
门店/分店事实
  + 项目、服务或团购事实
  + 真实案例、环境、过程或专业证据
  + 品牌/店主/专业人员表达身份
  + 当前平台容器与机会机制
  + 到店、咨询、预约或买券 CTA
  + 来源、时效、权利与合规状态
```

“缺关键事实时换安全方案或只问一个阻塞问题、不暴露完整资产表”同样是 D 级产品响应，需要通过真实任务中的完成率、纠偏量和用户理解验证，不能由单条内容倒推为固定规则。

### 5. 当前证据不支持把“高频发布”设为优化目标

抖音发现样本中可见模板化、低信息量文案和与美业无关的话题词；搜索适配的播放字段也常为 `0`，不能用作效果比较。当前只能排除“把发布量直接当效果”的做法。本店相关性、事实正确、成品完整、修改少、发布/导出可完成和可复用可作为 D 级候选指标，仍需门店任务回放和经营结果验证。

## 面向共性的前台响应假设（全部为 D 级）

为避免把发现层个例固化成入口，下一轮原型测试“无论从哪个真实起点进入，先收敛出一个完整主推荐”，而不是预设表单或三选一。该响应尚未达到 C 级验证：

```text
现在建议做什么
  + 为什么是现在
  + 为什么适合这家店
  + 用了哪些本店事实/素材/IP
  + 顾客下一步做什么
  + 一个完整可判断的成品
```

首屏可先测试少量快捷动作；动作集合、命名和排序都属于 D 级：

- `就做这条`
- `换项目`
- `换素材`
- `换表达身份`
- `更本地 / 少一点促销`
- `不适合我家`

“来源、分店、价格、有效期、权利和合规状态用可展开 chips 呈现，并只在命中当前成品风险时确认”是待测方案，不是公开证据得出的交互定论。

## Human-in-the-loop 的切入点（D 级待 C 验证）

下表是下一轮任务回放要检验的交互假设。公开内容不能证明这些节点真实发生，也不能证明用户接受对应的确认方式。

| 类型 | 典型内容 | 待测交互 | 待测沉淀规则 |
| --- | --- | --- | --- |
| 主观喜好 | 视觉风格、语气、人物表达、促销强度、镜头节奏 | 成品旁快捷切换，不中断生成 | 默认仅本次；连续采用后提示保存为偏好，不静默晋升 |
| 临时纠偏 | 本次换项目、换素材、换 CTA、这个热点不适合 | 就地一句话/快捷动作，立即重编译主推荐 | 默认仅当前任务 |
| 长期资产 | 分店归属、品牌主张、稳定 IP 身份、长期禁忌、系列栏目、已确认可复用素材 | 在用户表达“以后都这样/保存系列/更新门店资料”时轻确认 | 明确确认后写入，保留来源、版本、撤回与适用范围 |
| 高风险事实 | 价格、团购权益、有效期、活动资格、顾客授权、功效/资质、公开发布或付费动作 | 只在成品真正使用该事实或动作前阻塞式精准确认 | 写回来源化事实或一次性授权；不得从“这次通过”无限外推 |
| 身份歧义 | 同品牌不同分店、门店账号/员工 IP/UGC 混淆 | 展示匹配理由，问一个最小消歧问题 | 用户确认后保存分店—账号—身份关系，可撤销 |

## 后端工作流假设（D 级待 C 验证）

```text
平台与门店来源摄取
  → 分店/账号/表达身份解析
  → 来源化事实、时效、权利与能力状态
  → 机会发现与行业/地域相关性过滤
  → 门店资产 + 行业场景策略匹配
  → 生成一个完整 MarketingPackage
  → 条件式 HITL
  → 发布/导出/明确失败
  → 采用、修改、拒绝、结果补记与做同款
  → 仅经确认晋升长期资产
```

这套工作流用于任务回放原型，不代表已经验证了节点顺序。验证目标是：工程复杂度能否藏在后台，同时让前端用户理解“为什么推荐这条”和“怎么最快改成我的”；若真实任务从不同起点进入，应允许改序或跳步。

## 现在不能下的结论

- 不能说五类入口已经代表全行业频率；当前只完成公开目的抽样。
- 不能说任何内容带来了咨询、预约、买券、核销或到店。
- 不能从账号人设推断谁负责拍、写、审、发或付费。
- 不能把公开图片、顾客评价或探店 UGC 自动晋升为门店可复用素材。
- 不能把小红书搜索排名、抖音全局热词或单条互动写成平台趋势。
- 不能把点评当前摘要当成仍有效的价格、团购、库存或预约事实。
- 不能说日常宣传物料入口已被验证；它需要门店提供真实物料与制作任务。
