## 权威边界

本手册用于验证“广义宣发曝光 + 到店引流”的产品主链，不验证预设的店内岗位流水线。验证单位是门店真实发生的一次宣发任务，不是研究团队规定的一条内容，也不是某个模型、Provider 或工作流节点。

`references/analysis/12-merchant-validation-plan.md` 与 `references/analysis/15-pilot-playbook.md` 仅作为历史输入。它们仍可提供访谈记录、素材来源、人工耗时、真实发布、付费动作和安全硬失败等方法，但以下旧设定不再具有当前约束力：

- 固定每店每周交付三条内容；
- Research Lead、Content Operator、Reviewer、Merchant Operator 的前台接力；
- 以人工陪跑产量代替门店自助完成能力；
- 把医疗美容探针混入普通美业首发的采用率或放行结论；
- 把发布时间接近的咨询、预约、买券、核销或到店写成内容带来的结果。

若旧文档与本手册冲突，以 `CONTEXT.md`、当前产品设计、D-020 至 D-025 和本手册为准。

## 要回答的核心问题

1. 门店真实宣发任务是否稳定落入五类入口，频次和优先级分别是什么。
2. 用户更常从经营目标、热点机会、现有素材、历史内容还是预期成品起步。
3. Agent 能否用最少输入匹配正确的门店事实、项目、品牌/IP、真实素材、平台机制和 CTA。
4. 第一次是否能给出一个完整、可判断、可直接采用或小改后采用的主推荐。
5. 用户能否在不依赖研究员实时救场的情况下完成修改、发布/导出、结果补记和做同款。
6. 哪些纠偏只属于当前任务，哪些偏好、栏目、素材组合和身份表达值得沉淀为长期资产。
7. 平台、账号、链接摄取、结果回流和物料渲染能力在当前真实范围内究竟是已验证、辅助完成还是不可用。

## 首发样本与周期

### 样本

- 覆盖 `8–12` 家非医疗美容门店。
- 分开记录美发、美甲美睫、生活美容和皮肤管理，不把品类差异平均掉。
- 覆盖店主自营、员工兼任、连锁集中运营和代运营协作，但不根据职位预设产品流程。
- 每家至少有一位真实内容操作者参与，并尽量让经营或付费决策人参加期初和期末复盘。
- 医疗美容只可作为独立研究探针，使用独立证据包、指标和放行判断，不计入本手册的首发结果。

### 周期

- 回看最近 `30` 天真实发布、活动、热点跟进、团购和宣传物料，建立任务基线。
- 连续进行 `2–4` 周真实任务回放；两周是最短可用观察窗，四周用于覆盖重复、热点过期、活动变化和异步恢复。
- 不要求门店为了研究固定凑内容数量。自然出现的任务全部入账；没有发生的入口记为“本周期未观察到”，不能用人工造任务补齐频次。
- 需要判断资产复利、长期自助和付费续用时，另延长到 `8–12` 周；延长期不得反向改写前 `2–4` 周的预登记结论。

## 任务回放实验处理（D 级，待 C 验证）

研究首先保留真实起点，可能是经营目标、Agent 机会、平台参考、项目/活动、现有素材、历史做同款、预期成品或其他。理解起点后，再对实验组施加“一个完整主推荐”的 D 级处理，以比较采用、修改和自助完成；这不是已验证的产品主链。真实任务允许跳步、改序或退出，偏离本图本身也是研究结果。

```text
真实起点（目标 / 机会 / 项目 / 素材 / 历史做同款 / 预期成品 / 其他）
  -> 记录门店原话、期望结果与当前上下文
  -> 收集最少且有来源的本店输入
  -> 实验处理：Agent 尝试编译门店事实、项目/服务、品牌/IP、真实素材、平台机制与 CTA
  -> 实验处理：先交付一个完整主推荐，备选按需展开
  -> 观察用户采用、就地修改、换安全方案、改序或退出
  -> 发布/导出，或明确记录不发及原因
  -> 在预先声明的观察窗内补记结果信号
  -> 选择仅本次、做同款、保存系列或晋升长期资产
```

图中的产品响应、顺序和完整包字段均待 C 级任务回放验证。只有安全、权利、专业事实和外部动作门禁属于硬约束：它们在当前成品真正命中对应素材、主张或动作时触发；不得把顾客授权、技师核验、店长策展或账号责任人审批变成每个任务的固定步骤。

### 单个任务的必记字段

| 阶段 | 最小记录 |
| --- | --- |
| 起因 | `task_id`、发生时间、门店原话、真实经营目标或机会、紧迫度 |
| 入口 | 五类入口之一；如暂时无法归类，保留原话并标为 `unclassified` |
| 起点 | 经营目标、Agent 机会、平台参考、项目/活动、现有素材、历史做同款或其他 |
| 输入 | 本次实际提供的链接、截图、文本、项目、素材和历史成品；逐项记录来源与时效 |
| 匹配 | Agent 使用的门店事实、项目/服务、品牌/IP、素材、行业配方、平台和 CTA，以及使用理由 |
| 实验主推荐 | 若进入该实验处理，记录完整成品预览、事实/权利状态、所选平台或用途、必要物料、CTA、发布/导出方式及用户认为多余/缺失项 |
| 人工介入 | 介入原因、由谁完成、操作内容、分钟数、如果不介入产品是否仍可完成 |
| 用户反应 | 直接采用、小改、大改、拒绝；修改内容、备选是否展开、拒绝原因 |
| 交付 | 发布、导出、暂存或放弃；地址/制品、状态、版本、耗时和失败原因 |
| 观察 | 预声明观察窗、信号来源级别、用户补记负担、实际观察信号 |
| 复用 | 做同款、保存系列、资产晋升、仅本次或不再使用；下一次任务是否减少输入和操作 |

任何入口分类、意图解释或结果解释都必须保留门店原话。研究标签不能覆盖原始记录。

## 五类候选入口的验证矩阵（D 级）

五类入口是待验证分类，不是已冻结的信息架构。实验组用同一种“一个主推荐先行、备选按需展开”处理来控制比较条件；若真实任务无法归类，保留原话并记为 `unclassified`。下表的完整包是待测交付假设，不是正式产品必填字段；当前能力不能完成时必须诚实记录缺口，不能用研究员补成半成品采用率。

| 候选入口 | 真实任务触发 | 本轮必须验证 | D 级待测完整包 |
| --- | --- | --- | --- |
| 日常项目/服务曝光 | 常规项目展示、环境/流程/产品/专业能力介绍 | 哪些项目高频、最少素材、用户认可的专业与促销强度 | 本店主张、来源事实、证据素材、平台成品、封面/图文、可选口播或拍摄建议、咨询/预约 CTA |
| 热点/同城/节点借势 | 平台热点、同城话题、节日季节、流行结构或临时经营机会 | 来源、采集/过期时间、本店相关性、原创角度、过期降级 | 机会卡、本店原创角度、匹配资产、平台成品、CTA 和常青回退 |
| 品牌/个人 IP | 品牌栏目、老板/主理人/专业人员持续表达 | 谁在表达、身份边界、语气与经历是否真实、系列能否续写 | 明确身份、栏目锚点、身份一致成品、系列续写入口和下一条建议 |
| 促销/团购/到店转化 | 上新、限时活动、团购、空档填充或明确转化目标 | 价格/权益/期限来源、承接终点和变更时效 | 已核验事实、优惠/价格卡、平台成品、预约/买券/到店 CTA 和过期行为 |
| 日常宣传物料 | 海报、项目卡、流程卡、价格/优惠卡、预约引导卡、私域或线下物料 | 真实照片、中文排版、尺寸、替换、导出和复用是否可用 | 指定用途的成套物料、明确尺寸、可替换文本/素材、确定性导出和做同款 |

实验覆盖的小红书、抖音和微信视频号内容变体也属于待验证范围；本轮平台研究只覆盖小红书、抖音和大众点评。大众点评当前只能提供本轮已核验的门店经营摘要；项目、团购、履约或自动发布在账号级能力未验证前不得计为产品能力。朋友圈和线下物料先按导出用途记录。

## 一个主推荐的实验处理

为检验“成品优先是否降低判断负担”，实验组第一次结果只展示一个有明确推荐理由的完整方向，最多两个明显不同的备选折叠在次级入口中；研究员不得为了测试选择偏好而强迫用户“三选一”。这一处理的顺序、备选数量和交互均为 D 级变量，需与真实起点和自助完成数据一起判断，不能直接晋升正式产品规则。

每个任务记录：

- `main_recommendation_direct_adoption`：是否直接采用；
- `main_recommendation_edit_level`：无修改、小改、大改或拒绝；
- `alternative_expanded`：用户是否主动展开备选及原因；
- `time_to_evaluable_package`：从任务开始到出现可判断完整包的时间；
- `time_to_usable_package`：到用户确认可发布/导出的时间；
- `why_this_fit_understood`：用户能否复述为什么适合现在、用了本店什么、希望顾客做什么；
- `package_completeness_gap`：用户认为缺失或多余的交付物。

用户修改首先按本次任务生效。只有用户明确表达“以后都这样”“更新门店资料”“保存为系列”或确认资产晋升时，才测试长期沉淀。研究员不得替用户把一次性改动写成长期偏好。

## 证据分层

这里同时记录两个正交维度，不能混成一套等级：

- `A/B/C/D` 是**结论成熟度**：平台直接记录、跨样本重复观察、门店确认、产品假设。
- `P0/P1/P2/P3` 是**证据来源层**：公开页面、授权来源、门店行为与陈述、研究推断。

同一结论必须同时标明来源层和成熟度，例如：页面原文为 `P0/A`；由多店公开记录归纳的重复模式为 `P0 + P3/B`；经门店任务回放确认的操作摩擦为 `P2/C`；由现有证据提出的交互方案为 `P3/D`。二者没有高低互换关系，`P3` 也不自动等于 `D`：只要达到公开分母与反例要求，研究归纳可以是 `P3/B`。禁止从平台页面反推店内流程、主观原因或经营结果。

### P0：公开可观察证据

来自抖音、小红书、大众点评等本轮公开可访问页面或公开内容，包括发布内容、时间、可见互动、项目/团购展示、门店主页和平台公开机制。

可以说明“页面展示了什么、何时展示、使用了什么可见结构”；不能单独证明“为什么发、谁决定、用了多久、是否产生咨询/到店、门店是否愿意付费”。平台热点和竞品内容只提炼机制与结构，不复制受保护表达。

### P1：授权账号或来源证据

来自门店明确授权的账号可见信息、可导出记录、后台截图、原始素材、价目表、团购/订单/预约/核销记录。必须记录账号/数据源范围、采集时间、字段含义、脱敏方式和授权边界。

账号已登录或技术上可访问，不等于获得了跨用途长期授权；超出本次研究范围的信息不得采集。仅有平台文档或适配代码不计为账号能力已验证。

### P2：门店行为与陈述证据

来自任务现场观察、屏幕回放、门店原话、真实改稿、发布/拒绝、补记结果、付费或排期动作。陈述与行为分开记录；“会用、愿意付费”必须与提交素材、完成任务、发布、定金或续用等动作区分。

### P3：研究推断

由 P0–P2 组合得出的模式、解释或产品建议。必须列出支持证据和反例，使用“推断、候选、待验证”措辞，不能升格为行业事实。

产品决定不得由单店、单任务或突出个例触发。要称为跨门店共性，至少需要 3 家独立门店、覆盖至少 2 个业态并完成反例检查；要称为平台无关规律，还需在至少两个目标内容平台重复。未达到门槛的发现只进入下一轮问题清单或 D 级原型假设，不提升路线优先级。

结论优先级不是简单的 P2 大于 P0，而是看问题类型：页面形态用 P0/P1，门店动机和操作摩擦用 P2，平台或经营结果以经过验证的 P1 为准。证据冲突时保留冲突，不用研究员判断覆盖原始事实。

## WOZ 边界：模拟产品，不变成代运营

WOZ 的目的，是找出 Agent 应自动完成的后台工作，并测量没有人工救场时产品能否成立。人工可以在界面背后模拟尚未实现的抽取、匹配、生成、排版和恢复，但商家必须看到并使用与目标产品一致的前台交互。

### 允许

- 在用户给出的任务和有来源输入上，后台人工模拟事实抽取、热点筛选、资产匹配和 MarketingPackage 生成；
- 使用成熟工具制作目标产品合同内的真实成品，并逐项记录工具、操作和分钟数；
- 在产品明确显示“辅助完成”时，帮助完成链接转录、截图/OCR、物料导出或人工发布交接；
- 解释一次研究任务规则，处理产品故障，并记录故障前后的完整路径；
- 因权利、事实、专业或外部动作条件门，向真正有能力的责任人发起一次必要确认。

### 禁止

- 研究团队替门店决定本周经营重点、虚构热点相关性或补写缺失价格/优惠；
- 代替商家持续拍摄、挑选、确认、发布、回复私信、运营账号或补记经营结果；
- 在每次结果前人工精修到“肯定会喜欢”，却不记录原始输出和人工耗时；
- 用研究员私聊、远程操作或线下解释绕过产品中的缺失步骤；
- 把未授权顾客素材、评价、个人肖像/声音或无来源事实放入公开成品；
- 用陪跑人员完成的产量、发布量或结果记录声称门店实现了自助价值。

每次人工介入必须写入 `intervention_log`：触发点、原因、分钟数、使用工具、交付差异、当前能力状态、是否可被产品化，以及拿掉这次介入后任务会完成、降级还是失败。

## 自助对照

自助对照用于暴露人工依赖，不用于在小样本中宣称严格因果提升。

- 每家先完成至少一个有记录的辅助任务，熟悉目标产品的正常入口。
- 从第 2 周开始，使用同店交替任务或至少 `1–2` 家无实时协助样本，预先指定哪些真实任务进入自助条件。
- 自助任务从开始到发布/导出决定期间，研究员不提供选题、素材代选、改稿、操作指路或私聊救场；只允许产品内已有说明、明确降级和故障通道。
- 紧急经营任务可退出对照，但必须记录退出时间与原因，不能移出分母。
- 辅助任务与自助任务按入口、输入复杂度、平台/用途、素材准备度和时间压力分层比较，不把不同难度直接平均。

至少比较：完成率、完整包达成率、主推荐采用/修改、用户操作数、用户主动输入分钟数、研究员介入分钟数、发布/导出决定、结果补记率、做同款/资产晋升和恢复成功。任何“效率提升”都要同时报告研究员隐藏耗时。

## 结果信号：记录关联，不声称因果

每个任务在看到结果前声明观察窗、CTA 和承接终点。发布或导出后只记录观察到或关联到的信号：

1. **已验证信号**：来自当前账号与数据源真实跑通、仍在有效期内的平台、交易、预约或核销接口/导出。
2. **门店记录信号**：经营者通过 chips 或简短补记确认的私信、加微、预约、买券、核销或到店。
3. **推断相关性**：仅有时间、话题、顾客自述或内容线索上的关联，必须标为推断，永不写成事实归因。

统一结果阶梯为：已发布 → 获得注意 → 发生咨询 → 预约/买券 → 核销/到店。周复盘只回答：

- 本周发了什么；
- 在预声明观察窗内观察到什么，证据级别是什么；
- 哪个假设值得下一轮继续、换 CTA、做同款或停止。

严禁使用“这条内容带来”“Agent 提升了”“热点导致了”等因果措辞，除非未来另有预注册、足够样本且能控制混杂因素的因果研究。播放量、点赞、咨询或到店的单点变化不能单独证明产品价值。

## 能力三态与证据门

依赖外部平台、账号、数据或渲染器的能力，必须按当前账号和数据源单独标注：

| 状态 | 判定 | 前台行为 |
| --- | --- | --- |
| 已验证 | 在版本化计划中登记范围、样本、阈值、真实回执/制品、失败样本、负责人、验证时间、有效期和重新验证触发器，并实际通过 | 只在已验证范围内正常提供；显示真实状态与来源 |
| 辅助完成 | 自动链路未通过，但用户可用截图/OCR、粘贴文本、授权导入、人工发布或明确导出完成同一经营任务 | 主动给出低负担回退，不伪装成自动能力；记录用户和后台人工耗时 |
| 不可用 | 没有安全、真实、可完成的路径，或能力已过期/越界 | 隐藏入口或明确说明不可用，不显示假按钮和假实时数据 |

至少逐项登记热点发现、链接摄取、门店/团购事实导入、图文物料渲染、平台发布/导出、订单/预约/核销回流、付费投放、生成耗时/成本和异步恢复。平台文档、开源代码、一次 demo、共享登录态或“架构已支持”均不能把能力升级为已验证。

跨门店串线、无来源关键事实、未授权素材公开使用、身份冒用、错误价格/权益、错误版本外发和未经精确确认的付费/公开动作，允许阈值固定为 `0`。其他能力的成功率、耗时和样本阈值必须在看结果前写入对应验证计划；未预登记时只能报告观察数据，不能宣称通过。

平台规则、账号权限、数据字段、模型/模板主版本、素材权利或安全策略变化时，相关证据立即失效或进入复核，前台自动降回辅助完成或不可用。

## 2–4 周执行节奏

### Week 0：基线与预登记

- 回放最近 30 天真实任务，不使用五类入口提示诱导门店补答案。
- 记录当前选题、素材、制作、发布、结果补记和复用的真实步骤与时间。
- 建立来源化门店事实、项目/团购、品牌/IP、素材和账号能力清单。
- 为每项能力锁定本轮范围、证据状态和回退路径。
- 锁定本轮任务字段、观察窗、硬失败和统计口径；开始后不得按结果改阈值。

### Week 1：真实任务回放与一个主推荐

- 所有自然发生任务入账，先观察其真实起点，再归入五类入口。
- 对每个任务交付一个完整主推荐，备选折叠。
- 记录匹配理由是否被理解、采用/修改/拒绝、包完整度、人工介入和发布/导出决定。
- 收集事实错误、身份错配、素材不合适、过度促销、平台不适合和 CTA 不成立等具体反例。

### Week 2：自助与恢复

- 执行预登记的自助任务，不做实时研究员救场。
- 验证最少输入、链接失败回退、一次只问一个阻塞问题、异步离开/恢复和做同款。
- 比较同层级辅助任务与自助任务，明确哪些价值来自产品，哪些来自隐藏人工。
- 两周期项目在此完成第一轮结论；没有观察到重复或热点变化的指标标为证据不足。

### Week 3：复用与变化（推荐）

- 优先观察同类任务复发、换项目、换平台、换 IP、活动过期和素材补充。
- 测试保存系列、资产晋升、撤回和“仅本次”边界。
- 检查第二次制作是否减少输入、操作和事实纠错，而不是只比较模型生成速度。

### Week 4：结果复盘与产品决定（推荐）

- 汇总五类入口真实频次、成品包缺口、主推荐采用、备选展开、自助完成、人工依赖和结果补记。
- 与门店逐条复盘原始任务，不展示汇总答案后再诱导确认。
- 记录继续使用、停止、付费、定金、排期、拉入决策人或提交下一周期素材等真实动作。
- 只对达到跨店、跨业态门槛的模式输出继续、收窄、修改或停止的产品决定；其余列为个例边界或未决证据。

## 指标与判断

### 必报指标

- 五类入口按品类、操作者形态和周次的真实任务频次；
- `unclassified` 任务及其原话；
- 主推荐直接采用、小改、大改、拒绝和备选展开率；
- 可评价完整包时间、可发布/导出时间和用户主动操作数；
- 完整 MarketingPackage 达成率及每类缺失项；
- 事实、身份、素材、平台、CTA 匹配正确率与具体反例；
- 辅助、自助、后台人工三方分钟数和介入依赖率；
- 发布/导出决定、结果补记、做同款、系列保存和资产晋升；
- 各能力已验证、辅助完成、不可用的任务覆盖和降级成功；
- 真实付费、定金、排期、续用、转介绍与停止动作。

### 不能作为单独通过依据

- 内部 demo、模型评测或 Provider benchmark；
- 研究员精修后的漂亮成品；
- 免费试用中的礼貌性好评；
- 没有行为支撑的使用或付费意愿；
- 单条内容的播放、点赞、咨询、买券、核销或到店；
- 平台文档描述、登录成功或一次抓取成功；
- WOZ 团队替门店完成的产量、发布和线索台账。

### 决策规则

研究开始前，为各产品假设登记样本范围、最低样本量和通过/收窄阈值；看过结果后不得移动。首轮尚未登记阈值时，只能输出“观察到的证据、反例和下一轮阈值建议”，不能补写一个 Go 结论。

无论采用率如何，以下任一硬失败发生都必须停止对应能力放行并调查：跨店串线、关键事实无来源、受限素材越权、冒用个人身份、活动/价格错误、错误版本外发、未经一次性批准的公开或付费动作。

产品方向可以继续进入原型或工程评审，至少需要同时看到：

- 五类入口中的真实任务分布能够解释首页优先级，无法归类任务已被审查；
- 一个主推荐在目标任务中有稳定的直接采用或小改证据，备选不是必经步骤；
- 至少一组自助任务能完成从起点到发布/导出决定，隐藏人工依赖被完整计量；
- 本店事实、IP、素材、平台和 CTA 的匹配可解释且关键错误为零；
- 发布后结果信号可以低负担分层记录，研究结论没有虚假因果；
- 每项外部能力都有真实三态和失败回退，不靠未验证按钮支撑闭环；
- 同类第二次任务出现可测的做同款或资产复用，且用户能控制“仅本次”与长期沉淀。

若证据只支持其中一部分，应收窄入口、品类、平台或成品合同再测，不得用增加后端兜底掩盖前台产品价值缺口。

## 研究交付物

本轮结束至少产出：

1. 五类入口的真实任务基准集，保留原始触发与反例；
2. 平台公开证据、授权账号证据、门店行为证据和研究推断的来源登记；
3. 各入口 MarketingPackage 的采用、删减和补充清单；
4. 一个主推荐、按需备选、快捷修改和自助完成的行为数据；
5. 个性化资产与行业资产匹配的正确、错误和缺失样本；
6. 各平台与外部能力的三态矩阵、证据有效期和回退结果；
7. 非因果结果信号周报、人工介入成本和真实付费/续用动作；
8. 下一轮产品合同、原型范围、能力门和待验证阈值建议。

最终报告必须把“已观察事实、门店陈述、研究推断、产品决定”分栏呈现。没有证据的产品判断保持开放，不再用角色链、工程对象或研究员经验补全行业事实。
