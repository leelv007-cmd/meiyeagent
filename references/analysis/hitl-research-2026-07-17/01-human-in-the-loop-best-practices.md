# Human-in-the-loop 最佳实践与交互规范

- 日期：2026-07-17
- 用途：作为产品、交互、工作流、数据模型和验收共同遵守的 HITL 基线
- 适用范围：美业内容 Agent 的创建、修改、学习、资产化、发布和异步恢复

## 核心判断

Human-in-the-loop 不是“让人审核 AI 的每一步”，而是把人的判断放在机器无法可靠代替、且判断结果会改变责任边界的节点。

最强的跨来源共识是：

> 局部反馈与全局规则分离；可逆动作就地修改；不可逆动作临门授权；任何学习都要说明学了什么、何时生效、作用在哪、如何撤销。

这条原则同时受到 [Microsoft HAX](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/)、[Google PAIR](https://pair.withgoogle.com/guidebook-v2/chapter/feedback-controls/)、[NIST AI RMF](https://airc.nist.gov/) 与多种 Agent HITL 运行时的支持。

## 六类人类决定不能混用

| 类型 | 用户真正回答的问题 | 默认作用域 | 是否阻塞 | 是否可自动沉淀 |
| --- | --- | --- | --- | --- |
| 主观喜好选择 | “这几个都可以，我更喜欢哪个？” | 当前版本 | 否 | 只记录弱观察 |
| 临时纠偏 | “当前成品哪里需要改？” | 当前版本或任务 | 否 | 否 |
| 事实纠错 | “什么才是真的？” | 对应事实实体的新版本 | 必要时阻塞 | 只能走事实确认 |
| 长期偏好 | “以后遇到同类任务是否默认这样？” | 最窄的门店 × IP × 场景 × 平台 | 否 | 明确确认后才生效 |
| 可复用资产 | “这次成品中哪一部分值得以后复用？” | 版本化资产 | 保存前阻塞 | 预览确认后入库 |
| 不可逆批准 | “是否允许执行这一次外部行动？” | 精确动作的一次性授权 | 是 | 永不学习、永不复用 |

### 1. 主观喜好选择

适用：画面、标题、Hook、内容结构、IP 口吻等存在多个合理答案，只有人能判断“更像我”或“今天更想推哪个”。

推荐交互：

- 一次给 2–3 个完整且差异明确的成品，不让用户先调 6 个参数。
- 用身份、受众、平台、印象、目标描述差异，例如“老板娘真实日常 / 技师专业解释 / 团购转化”。
- 选中后立即替换预览，不再追问“是否确认采用”。
- 可以问“喜欢哪里”，但必须是可忽略的补充，不成为完成任务的门槛。
- 单次选择只产生当前版本决定和弱信号。

不要做：

- 候选只换几个词，策略没有差异。
- 展示“92% 适合你”这类无法帮助审美判断的假精度。
- 把一次选择直接变成“以后都这样”。
- 只有一个方案却要求用户确认。

验证：候选直接采用率、选择后修改量、短期反选率、候选可区分率、决定耗时。

### 2. 临时纠偏

适用：“这条别太广告”“这次换小林口吻”“换掉这张图”“标题短一点”。

推荐交互：

- 把 `修改 / 换一个 / 重试 / 撤销 / 恢复 AI 版` 放在成品附近。
- 默认明确显示“仅这版”，不要先弹作用域表单。
- 支持自然语言修改、动态快捷动作和直接编辑。
- 修改后展示字段级或画面级差异，并保留 undo。
- 拒绝某个 Agent 动作时，把结构化原因返回给工作流继续规划，而不是把整项任务打成失败。

不要做：

- 只回复“收到”，用户看不出改了什么。
- 每次修改后追问“要记住吗？”。
- 重新生成时吞掉用户已经手改的内容。
- 把本次救火动作静默带到其他任务。

验证：一次纠偏成功率、纠偏耗时、撤销率、当前任务问题复发率、跨任务误带率。

### 3. 事实纠错

适用：价格、有效期、服务内容、员工身份、素材授权、资质、门店和团购范围等客观事实。

推荐交互：

- 从偏好通道分流到事实通道。
- 展示旧值、新值、来源、更新时间或生效期、将影响的草稿。
- 来源冲突时一次只问一个最关键的问题。
- 权利纠错作用在素材本体：
  - “这条不用”只影响当前内容；
  - “没有授权”冻结该素材所有公开用途；
  - “撤回授权”使所有未发布使用自动失效。
- 更新事实后重新编译 ContextBundle，不在旧 prompt 上打补丁。

不要做：

- 把“价格错了”记录成“不喜欢 199”。
- 用模型置信度代替来源核验。
- 静默覆盖历史版本或回写已发布内容。
- 允许普通内容确认绕过素材权利或资质红线。

验证：旧事实复发率、来源/有效期完整率、误更新率、冲突解决时间、未授权素材进入公开成品数。

### 4. 长期偏好

适用：“以后小林的小红书科普都少用强促销词”“老板娘日常发朋友圈不要太精修”。

推荐交互：

- 用户明确表达“以后、默认、都这样”时，立即生成偏好提议。
- 隐式行为只能先形成 `PreferenceCandidate`。
- 提议卡说明：
  - 系统观察到了什么；
  - 提议保存什么规则；
  - 推荐的最窄作用域；
  - 未来哪些内容会改变；
  - 如何暂停、调整或撤销。
- 用“记住 / 仅这次 / 调整范围”三个动作即可。
- 当某次输出受偏好影响时，可以回答“为什么这次这样写”。

作用域优先级必须确定性计算：

```text
当前任务 override
> IP + 平台 + 场景精确偏好
> 平台 + 场景偏好
> IP 偏好
> 门店默认
> 行业默认
```

语义相似度只能在同一合法作用域内排序，不能让一个“更相似”的全店规则压过当前 IP 的精确规则。

不要做：

- 一次行为即全局学习。
- 隐藏已经保存的记忆。
- 只能全部开启或全部关闭。
- 被检索一次就强化一次。
- 把批准某个工具等同于喜欢某种表达。

关于“三次阈值”：跨 3 个独立任务出现同语义修正，只能作为首版提议门槛。PAIR 支持“更长时间观察更容易辨别意图”，但没有资料证明 3 是最佳数字，必须通过实验验证。

验证：提议接受率、短期撤回率、规则启用后的重复纠偏率、跨作用域误用率、用户对规则影响的理解率。

### 5. 可复用资产化

适用：被采用的三段内容结构、镜头组合、IP 表达规则、场景打法、视觉布局、Hook/CTA 模块。

推荐交互：

- “喜欢这条”与“保存为同款”必须是两个动作。
- 资产预览必须拆出：
  - 固定骨架；
  - 动态变量槽；
  - 禁止继承的信息；
  - 适用场景、平台和 IP；
  - 来源成品和采用证据；
  - 素材权利、版本和示例。
- 价格、日期、库存、顾客信息、订单数据必须被删除或变量化。
- 晋升前可以用另一个服务或团购做一次回放，验证抽取的是结构而不是旧内容快照。
- 资产可版本化、回滚、停用；复用时重新解析最新经营事实。

不要做：

- 把整篇文案复制进模板。
- 只保存一段抽象 prompt，丢失素材槽、IP 和合规边界。
- 没有来源、权利与版本。
- 保存后又变成用户必须逐字段填写的刚性表格。

验证：资产复用采用率、复用后修改量、从复用到发布的时间、临时值泄漏、权利记录完整率、跨场景误用率。

### 6. 不可逆批准

适用：公开发布、定时发布、投放、发送外部消息、扣费、使用顾客隐私素材、代表某个 IP 对外表达。

推荐交互：

- 在最后可逆时刻确认，不在任务开头取得宽泛授权。
- 确认卡直接显示：平台、账号、精确成品版本、发布时间、金额/费用、关键经营事实、素材和授权。
- 授权绑定不可变动作信封：

```text
workspaceId
+ actionType
+ contextBundleRevision
+ contentPackageRevision
+ targetAccount
+ schedule
+ cost
+ actionHash
+ expiresAt
```

- 任一关键字段变化，旧授权自动失效。
- 一次性消费；重复点击返回相同结果，不重复执行。
- 提供拒绝并修改、暂缓、取消，而不是只有“同意/不同意”。
- 高频批量工作可以先审策略，但最终公开/付费副作用仍需绑定确切执行对象。

不要做：

- 让模型自行决定是否需要批准。
- 按钮只写“继续”。
- 默认勾选“始终允许”。
- 批准后内容还能变化。
- 把所有可逆小步骤都变成确认，造成注意力麻木。

验证：关键确认召回、确认精确率、无有效授权外部动作数、过期授权拦截率、重复副作用数、确认页发现错误比例。

## 七个前端插入点

### 上下文摘要

只告诉用户“本次将使用：门店 A、项目 B、小林 IP、小红书、已授权素材 6 张”。默认折叠，点击才展开来源和有效期。事实没有冲突时不要求确认。

### 事实冲突卡

一张卡只处理一个阻塞问题。适合内容：旧值、新值、来源、有效期、受影响草稿。事实责任人确认后工作流自动续跑。

### 主观候选卡

同屏比较 2–3 个完整成品。差异名称使用经营语言，不使用模型参数。选择即生效。

### 就地修改条

根据当前成品和历史行为动态出现 2–4 个快捷动作，例如“弱化促销感”“换技师视角”“不写价格”“换首图”，并保留自然语言输入。

### 记忆提议卡

只在结果已可用后出现，不阻塞任务。说明证据次数和范围，不保存聊天原句，而保存结构化规则。

### 资产化抽屉

只在明确要求“做同款”或稳定结构值得晋升时出现。展示固定项、变量槽、来源、权利和另一个服务的回放预览。

### 外部行动面板

面板与即将执行的动作同页，主按钮必须是“发布到抖音账号 A”“花费 ¥20 再生成高清版”这类结果描述。

## 异步恢复规则

1. 人工等待进入持久 `waiting_human` 状态后，当前 Worker 结束，不占用运行实例。
2. 保存 decision ID、内容 revision、上下文 revision、工作流/Agent/schema 版本和过期时间。
3. 用户响应先通过身份、权限、状态、版本和过期校验，成功后才生成 `ApprovalReceipt` 或 `DecisionEvent`。
4. 以确定性 key 重新入队 continuation，例如 `approvalId:resume`。
5. 恢复的是业务工作流状态，不只是 SSE 字节流。
6. 超时产生业务事件，例如 `ApprovalExpired`，随后提醒、降级为草稿或终止。
7. 公开发布和扣费仍做 effect claim、payload hash、幂等与结果对账。

## 记忆治理规则

### 最小候选模型

```text
PreferenceCandidate
- semantic_key
- proposed_value
- scope
- evidence_event_ids
- independent_task_ids
- explicitness: explicit_future | repeated_edit | single_edit
- supporting_count
- contradicting_count
- first_observed_at
- last_observed_at
- status: observed | eligible | proposed | accepted | rejected | expired | superseded
- extractor_model
- extractor_prompt_version
- supersedes_candidate_id
```

不要用一个神秘的 `confidence: 0.87` 代替可解释证据。用户应该看到：“过去 21 天，你在 3 个不同小红书团购任务中，都把强促销词改成了日常表达。”

### 衰减与撤回

- `TaskOverride`：任务结束失效。
- 未确认的 `PreferenceCandidate`：可以按时间衰减并过期。
- 已确认 `Preference`：不因很久没用自动删除；出现冲突时提议 supersede。
- 经营事实：只用 `valid_from / valid_to / revoked_at / source_revision`，不用行为 decay。
- `ApprovalReceipt`：动作完成、版本变化或到期即失效。
- 强化只来自采用、再次明确或发布后保留，不能来自系统自己检索过它。

Undo 不删除历史，而是追加 `DecisionReverted`；偏好变化追加 `PreferenceSuperseded` 并链接新旧版本。

## 认知负担和确认疲劳

“有人点过确认”不等于有效监督。逐动作批准会让用户形成机械点击习惯。普通审美选择不需要强制停顿；价格、权利、功效宣称、公开发布和付费才需要认知强制。

应同时衡量：

- `critical_confirmation_recall`：该确认的是否都确认了；
- `confirmation_precision`：出现的确认是否真的必要；
- `overreliance_rate`：AI 错误时用户仍批准的比例；
- `appropriate_reliance_rate`：AI 正确时接受、AI 错误时纠正的比例。

[Buçinca 等人的实验](https://arxiv.org/abs/2102.09692)发现，要求用户短暂停顿或主动分析能降低对错误 AI 建议的过度依赖，但会降低部分主观易用性。因此认知强制只放在高风险节点。

## 必须进入回归测试的场景

1. 一次“这条少点广告感”不得跨任务。
2. 连续三次相似修改只能产生 candidate，不能自动成为 Preference。
3. “以后小林的小红书科普都这样”只作用于该 IP × 平台 × 场景。
4. “价格不是 199，是 239”进入 FactCorrection，不能进入偏好记忆。
5. “这张图别用，因为没授权”冻结该素材未来公开用途。
6. 用户引用顾客的话，不得误识别为用户偏好。
7. 否定、反问、临时活动和第三方建议不得错误沉淀。
8. 新偏好 supersede 旧偏好后，旧值不得再次召回。
9. Undo 后投影、检索和 ContextBundle 必须一致恢复。
10. 不同门店、IP 和账号之间零泄漏。
11. 未知价格、授权和资质必须 abstain 并请求权威查询。
12. 删除记忆后，索引、缓存和投影不能残留。
13. 修改内容 revision 后，旧发布授权必须失效。
14. 重连、重复点击和 continuation 重试不得产生重复发布或扣费。
