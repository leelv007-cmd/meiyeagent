# 美业宣发 JTBD 与个性化资产编排

> 日期：2026-07-17
> 性质：对“美业岗位协作链”错误抽象的纠偏基线；用于补充产品设计、上下文编排、工作流与 HITL 方案。
> 核心结论：产品主链必须围绕 **广告曝光、流量借势、品牌/IP 塑造和到店转化** 组织。店内岗位不是主链，顾客素材授权也不是默认步骤。
>
> 范围说明：这里的“广告”指广义门店宣发；首发聚焦自然/自有内容、私域交接和本地营销物料，付费媒体投放仅在账号、预算、平台与回执真实验证后条件启用。

## 0. 先纠偏：被否决的不是一个步骤，而是一种建模方式

以下链路不能再作为产品主流程：

```text
技师采集 -> 顾客逐次授权 -> Agent 生产 -> 技师专业核验 -> 店长策展 -> 账号责任人发布
```

它的问题不是“角色还不够全”，而是把一个只在特定案例素材中可能出现的协作过程，误当成所有美业内容生产的共同结构：

1. 它从组织岗位出发，而不是从门店为什么要做内容出发。
2. 它无法解释项目曝光、热点借势、品牌 IP、个人 IP、团购促销和日常物料等高频任务。
3. 不同门店的人员配置差异很大，强行固化角色只会制造无效交接和表单。
4. 顾客授权只与部分顾客案例、面部/身体影像、评价截图等素材有关，不应阻塞环境图、项目介绍、价格卡、品牌故事、专业科普等内容。
5. 专业核验、策展和发布责任属于权限、风险与操作设置，不构成用户每次创作必须走过的页面链路。

正确的产品主链应改为：

```text
经营目标 / 流量机会 / 日常节奏
  -> Agent 推荐可做的宣发任务
  -> 编译门店事实 + 服务/活动 + 品牌/IP + 真实素材 + 行业场景 + 平台机制
  -> 先交付可直接判断的成品方案
  -> 用户做主观选择或最小纠偏
  -> 生成平台变体、宣传物料和发布包
  -> 私信 / 加微 / 预约 / 买券 / 核销 / 到店信号回流
  -> 沉淀本店可复用内容资产和成功打法
```

店内角色只在后台决定“谁能改事实、谁能确认高风险内容、谁能执行发布”；它不再决定产品信息架构。

## 2. 产品北极星与核心 JTBD

### 2.1 产品北极星

帮助美业门店用最少输入，持续获得 **像本店、能直接发、符合平台形态、带明确到店承接** 的宣传成品，并把每次有效结果沉淀为本店以后可复用的资产。

产品首先是“美业宣发与到店引流副驾”，其次才是内容生成工具。

### 2.2 核心 JTBD

> 当我需要维持门店曝光、抓住一个流量机会、推广项目/活动或长期塑造品牌与个人 IP 时，我希望系统基于本店真实信息和已有素材，快速给出能直接判断和发布的完整成品，让我不用学习提示词、整理多份表格或从空白画布开始，也能把注意力和咨询引向门店。

### 2.3 用户实际购买的结果

- 今天应该推什么，而不是一个空白输入框。
- 这条热点和我家有没有关系，而不是一份热榜搬运。
- 用谁的身份说、说什么更像本店，而不是通用 AI 文案。
- 同一内容在不同平台怎么变成可用成品，而不是简单改字数。
- 没有完美素材时也能先交付什么，而不是先让用户填完资产库。
- 用户确认一次后，下一次能否继续沿用本店表达和视觉，而不是每次从零训练。
- 发布之后能否看到咨询、预约、买券、核销和到店等信号，并据此调整下一轮内容。

## 3. 美业宣发任务体系

宣发任务回答“这次为什么做内容”。它比“图文、视频、海报”等内容格式更上位，也比店员、技师、店长等岗位更稳定。

| 宣发任务族 | 真实业务触发 | 典型成品 | 主要承接动作 |
| --- | --- | --- | --- |
| 日常项目/服务曝光 | 门店需要稳定更新；主推一个服务；展示手法、流程、环境、老师或产品 | 项目种草图文、服务流程卡、抖音口播/分镜、点评项目介绍、小红书封面、拍摄清单 | 私信咨询、查看主页、预约、门店导航 |
| 热点与流量借势 | 平台热点、流行内容结构、节日季节、同城话题与本店项目存在真实关联 | 热点切入选题、原创改写图文、口播脚本、热点封面、同城话题版本 | 获取曝光、主页访问、评论/私信、同城到店 |
| 品牌/个人 IP 经营 | 建立门店定位、审美和长期识别度，或让老板、主理人、专业人员稳定表达专业与人格 | 品牌栏目、门店故事、服务标准系列；或人设栏目、观点口播、科普、幕后日常、系列封面 | 关注、收藏、信任、品牌搜索、私信、指定人员预约 |
| 促销/团购转化 | 新项目、节日活动、团购套餐、限时优惠、空档补位、到店活动 | 活动海报、价格/优惠卡、团购卖点图、短视频脚本、朋友圈物料、预约引导卡 | 买券、预约、核销、加微、到店 |
| 日常宣传物料 | 线上线下持续需要可更新的宣传物料 | 价目卡、服务菜单、预约说明、门店长图、朋友圈海报、封面、店内屏幕图、项目套图 | 解释项目、降低咨询成本、承接预约和到店 |

任务之间可以组合。例如“春节前美甲预约”可以同时是热点借势、个人 IP 表达和促销转化，但必须有一个主要任务，避免一条内容同时承担所有目标。

口碑、案例、专业科普、环境和服务流程不是第六类入口，而是“日常项目/服务曝光”以及其他任务可调用的内容配方或证据类型。使用可识别顾客案例、评价或 before/after 时，再触发条件式素材权利门。

## 4. 六维宣发编排模型

每次生产都在后台解析六个维度。六维是 Agent 的编译契约，不是要求用户填写的六张表。

| 维度 | 回答的问题 | 典型值 | 主要来源 |
| --- | --- | --- | --- |
| 1. 宣发任务 | 这次要完成什么经营宣发结果？ | 项目/服务曝光、热点借势、品牌/个人 IP、促销团购、宣传物料 | 用户指令、经营日历、历史节奏、Agent 推荐 |
| 2. 流量机会 | 为什么是现在、为什么是这个角度？ | 当前主推、门店空档、平台热点、内容结构趋势、节日季节、同城议题、团购/预约/核销变化、历史高表现结构 | 当前任务、活动/排期、聚合经营信号、平台/人工策展信号、历史内容 |
| 3. 表达身份 | 谁在说，为什么用户相信？ | 品牌官方、门店主理人、技师/专家、服务顾问、顾客视角（仅在真实且授权时） | 品牌档案、IP 身份卡、账号人设、已确认历史表达 |
| 4. 平台机制 | 这条内容将在什么容器里被看见和承接？ | 小红书图文/封面、抖音短视频/口播、点评/美团项目与团购、微信朋友圈/长图/公众号 | 目标平台、账号能力、平台内容包、发布方式 |
| 5. 门店事实/素材 | 哪些事实和证据让内容属于这家店？ | 门店、位置、项目、价格、活动、团购、老师、环境、产品、流程、评价、真实图片/视频 | 门店档案、服务与价格、活动、团购信息、品牌/IP、素材库 |
| 6. 转化动作 | 看完以后希望用户做什么？ | 评论/私信、加微、预约、买券、核销、导航、到店、关注系列 | 本次任务、平台可用承接能力、预约/团购链接、线索目标 |

### 4.1 六维之间的关键约束

1. **任务决定成品，不由格式决定任务。** 用户说“推一下新团购”，Agent 应自动决定是否需要海报、图文、口播和朋友圈版，而不是先让用户选择“生成文案还是图片”。
2. **热点必须经过相关性判断。** 不能为了“蹭”而硬套；热点与门店服务、目标人群、表达身份至少要有一个可解释连接点。
3. **表达身份约束语气和证据。** 品牌官方可以讲标准，技师/专家可以讲经验，顾客视角只有真实来源和授权时才能使用。
4. **平台适配不仅是改字数。** 它还决定封面、内容结构、视频/图文形态、素材顺序、CTA、发布包和账号能力边界。
5. **所有事实必须可追溯。** 价格、优惠、资质、团购内容、老师经历和案例结果不能由模型补齐。
6. **转化动作必须与平台和账号能力一致。** 不存在的链接或未经验证的发布能力不能被包装为默认能力。

### 4.2 后台可用的最小任务契约

以下结构是后台状态，不是前台表单：

```text
MarketingBrief
  primary_job
  opportunity
  speaking_identity
  target_platforms
  store_facts_and_assets
  conversion_goal
  evidence_refs
  constraints
```

用户可以只说“把这个新团购做一套能发的宣传”，Agent 从已有上下文补齐大部分字段；只有团购价格、活动日期或目标平台等无法安全推断的关键事实才需要追问。

## 5. 个性化资产与行业资产不是两个资料库，而是两层编译输入

### 5.1 个性化资产：回答“为什么是这家店、这个人、这次活动”

| 个性化资产包 | 内容 | 使用规则 |
| --- | --- | --- |
| 门店事实包 | 门店名、地址、营业时间、商圈、环境、定位、预约方式、禁忌 | 稳定事实，可长期复用；变化后需更新版本 |
| 服务/产品包 | 项目名称、适合人群、流程、时长、材料/产品、注意事项、差异点 | 生成项目曝光和科普内容的事实底座；不从行业知识反推本店实际提供 |
| 价格/促销/团购包 | 价格来源、套餐、活动期、库存/名额口径、团购链接、预约规则 | 强时效；过期自动失效；每次对外使用保留来源 |
| 经营信号包 | 团购订单、预约、核销、项目热度、时段空档等聚合数据 | 用于发现和排序宣发机会；只取完成任务所需的聚合信号，不把顾客明细写进生成上下文 |
| 品牌资产包 | Logo、颜色、字体、视觉规范、品牌理念、固定表达、门店故事 | 约束视觉与品牌官方表达 |
| IP 身份包 | 身份定位、专业背景、擅长项目、语言习惯、可说/不可说、栏目线、出镜素材 | 不同 IP 独立保存；不能把一个人的经历或口吻复制给另一个人 |
| 真实素材包 | 环境、过程、工具/产品、老师、顾客案例、评价、历史发布内容 | 按用途、质量、时效、平台、权利和敏感度检索，不按文件夹盲选 |
| 历史内容与表现包 | 已发布内容、用户采用/拒绝、有效结构、平台反馈、关联线索 | 用于“做同款”和下一轮推荐，不把偶然高表现自动固化为永久规则 |
| 账号与承接包 | 平台账号、账号定位、已验证能力、主页/团购/预约/联系方式 | 决定平台变体和可用 CTA，不决定创作主链 |

团购订单、预约、核销、时段空档和平台表现不应被假定为已经自动接通。当前只使用账号级已验证接口、带来源的导入/截图提取、聚合统计或用户确认信号；没有可验证来源时不生成精确经营结论，也不把“可能有效”写成已经发生。

### 5.2 行业资产：回答“这类美业宣发任务通常怎样完成”

| 行业资产包 | 内容 | 作用 |
| --- | --- | --- |
| 美业场景包 | 案例种草、团购优惠、专业科普、顾客口碑、同城引流、项目展示等任务模板 | 把高频任务变成可复用起点 |
| 项目/品类知识包 | 美甲、美睫、美发、SPA、生活美容等品类的概念、流程、常见关注点和拍摄建议 | 补充表达结构，不覆盖本店事实 |
| 平台内容包 | 平台容器、版式、封面、正文/脚本结构、素材顺序、CTA 与发布包要求 | 生成真正的平台变体 |
| 热点借势配方 | 热点相关性判断、切入角度、原创重组、失效时间、版权/风险规则 | 将趋势变成与本店有关的原创内容，不做搬运 |
| IP 栏目配方 | 品牌价值、主理人观点、专家科普、幕后日常、案例讲解等系列结构 | 保证长期叙事连续性 |
| 营销物料模板 | 封面、项目卡、流程卡、价格/优惠卡、预约引导卡、长图、朋友圈海报 | 让 Agent 直接产出稳定物料，而不是打开自由画布 |
| 转化配方 | 不同任务与平台可用的私信、加微、预约、买券、核销、导航、到店承接方式 | 让内容带明确下一步 |
| 合规与权利规则 | 价格来源、广告表达、AIGC、资质、肖像/评价/案例素材权利等规则 | 在编译和交付时阻断或替换风险内容 |

### 5.3 匹配原则

```text
个性化资产提供事实、身份和证据
  + 行业资产提供任务配方、平台结构和成品模板
  + 本次机会提供时机与角度
  = 属于这家店、适合这个平台、服务这次转化目标的成品包
```

行业资产不能虚构个性化事实，个性化资产也不能替代行业方法。真正的 Agent 价值是把两者在每次任务里动态编译，而不是让用户手工选择十几个标签。

## 6. 上下文分层、优先级与生命周期

### 6.1 三类上下文

| 生命周期 | 内容 | 默认处理 |
| --- | --- | --- |
| 长期资产 | 已确认门店事实、服务、品牌、IP 身份、视觉规范、可复用模板、已授权素材 | 跨任务召回；有来源、版本和更新时间 |
| 活动/阶段上下文 | 当前主推项目、团购、节日活动、当月栏目、阶段性目标 | 在有效期内优先；过期后不再自动使用 |
| 单次上下文 | 这次热点、临时角度、当前素材、一次性语气纠偏 | 只影响当前任务，除非用户明确“以后都这样”或主动保存 |

### 6.2 冲突优先级

```text
本次用户明确指令
  > 当前活动且仍在有效期的事实
  > 已确认门店 / 服务 / IP 资产
  > 已确认的本店历史偏好
  > 当前版本行业场景与平台包
  > 模型通用知识
```

任何价格、优惠、资质、团购、老师履历和顾客案例事实，都不能被低优先级内容覆盖。

### 6.3 召回不等于全部塞进提示词

Context Compiler 应按本次六维任务只取需要的内容：

- 项目曝光只召回相关服务、项目素材、表达身份、平台和 CTA。
- 热点借势额外召回热点结构、失效时间和相关性证据。
- IP 内容额外召回该身份的历史栏目、口吻和已接受表达。
- 促销内容强制召回价格/活动来源、有效期和团购/预约承接。
- 宣传物料强制召回品牌视觉、模板、安全区和输出尺寸。

这能避免上下文越积越多后出现人物串线、价格过期、视觉混用和通用文案污染。

## 7. Agent 后台编译流水线

### 7.1 对用户可见的流程

```text
说目标或选择一个推荐机会
  -> 先看到一个主推荐，主观分歧明显时按需展开备选
  -> 选择、快捷修改或直接使用
  -> 获得多平台成品 / 宣传物料 / 发布包
```

### 7.2 后台实际执行

```text
1. Intent Resolver
   识别主要宣发任务、目标项目/活动、平台与转化意图

2. Opportunity Planner
   汇总主推项目、活动时效、当前可验证的团购/预约/核销聚合信号、内容节奏和平台/人工策展热点，给出可解释机会；未接通的数据不伪装成实时信号

3. Context Compiler
   按六维契约加载门店、服务、活动、品牌、IP、账号和历史内容

4. Industry Pack Selector
   选择美业场景、项目知识、平台结构、热点借势、CTA 和物料模板

5. Asset Resolver
   按相关性、清晰度、时效、权利、敏感度、平台适配和重复使用情况选素材

6. Content Core Composer
   生成平台中立的核心主张、证据、叙事角度和转化钩子

7. Platform Adapter
   生成各平台的标题、正文/脚本、封面、素材顺序、话题和 CTA

8. Artifact Builder
   生成项目套图、价格/优惠卡、预约引导卡、长图、口播/分镜、拍摄清单和发布包

9. Fact / Rights / Compliance Gates
   校验价格和活动来源、账号能力、顾客素材权利、合规表达和 AIGC 标识

10. Result Curator
    先展示一个最推荐的完整路线；主观分歧明显时再展开少量差异清楚的备选，不展示几十个参数和中间步骤

11. Learning Writer
    区分临时改动、长期偏好、可复用内容和已确认事实，按用户意图写回相应资产层
```

### 7.3 一个任务应交付“宣发成品包”，不是一段聊天文本

最小成品包可以包含：

- 一个清晰的宣发角度与目标。
- 平台中立的内容核心。
- 目标平台可直接使用的变体。
- 封面或图文卡；需要时生成价格/优惠卡、流程卡、预约引导卡。
- 需要视频时给出口播、分镜、字幕和拍摄清单。
- 使用了哪些门店事实、素材和来源。
- 转化动作与承接方式。
- 权利与合规状态。
- “做同款”“换身份”“换平台”“换风格”“加强到店引导”等快捷动作。

## 8. 不同宣发任务如何调用同一个编译内核

| 任务 | 必选个性化资产 | 必选行业资产 | Agent 的关键判断 | 默认输出重点 |
| --- | --- | --- | --- | --- |
| 日常项目/服务曝光 | 服务事实、相关素材、门店/IP、预约方式 | 项目展示/科普配方、平台包、项目套图模板 | 这次突出过程、体验、专业、环境还是结果；素材缺口如何安全替代 | 项目图文、流程/卖点卡、口播或拍摄清单、预约引导 |
| 热点借势 | 相关服务/品牌/IP 事实、可用素材 | 热点结构、相关性评分、平台包、原创与风险规则 | 热点与本店是否真相关；应该借话题、结构还是情绪；何时过期 | 原创热点角度、平台成品、相关素材建议、自然 CTA |
| 品牌/个人 IP | 品牌定位、门店故事与视觉；或指定个人的经历、擅长项目、口吻和出镜素材 | 品牌/主理人/专业人员栏目配方、系列节奏、平台包 | 本次内容如何推进长期叙事；该身份有资格说什么；如何既一致又像本人 | 系列图文/短视频、观点/科普/幕后、统一视觉、栏目续集 |
| 促销/团购 | 活动事实、价格来源、有效期、团购/预约承接 | 促销配方、价格/优惠卡、平台 CTA 规则 | 主卖点、紧迫度、适用人群和承接路径是否真实 | 团购图文、活动海报、口播、朋友圈版、预约/买券引导 |
| 日常物料 | 品牌视觉、项目/活动事实、使用场景 | 物料模板、尺寸/安全区、信息层级 | 线上/线下在哪里使用，必须让用户先看到什么 | 价目卡、服务菜单、长图、海报、门店屏幕图 |

## 9. 前台交互：六维藏在后台，首屏只给宣发入口

### 9.1 首屏建议入口

首屏不展示“选择 Agent、选择工作流、填写品牌表、填写人设表、选择模板参数”。建议以真实任务语言提供：

1. **今天发什么**：Agent 根据近期节奏、主推项目和可用素材先给一个可直接采用的主推荐，备选按需展开。
2. **推一个项目/服务**：选择或直接说项目，先生成完整成品。
3. **跟一个热点**：展示与本店相关且仍有效的机会，并解释关联点。
4. **做品牌/IP 系列**：继续已有栏目或为一个身份创建首期。
5. **做活动/团购物料**：读取当前活动；缺关键事实时只问价格、日期、承接等阻塞项。
6. **做一套宣传物料**：从用途出发生成海报、价目卡、项目套图或朋友圈版。

自然语言输入始终可用，入口只是示例起步，不是固定流程。

### 9.2 成品优先的结果页

第一次结果默认给一条最推荐的完整路线；当审美、身份或流量角度确有明显分歧时，再展开最多两条差异明确的备选，例如：

- 专业解释型：强调项目原理、流程和适合人群。
- 体验种草型：强调环境、过程、感受和预约门槛。
- 活动转化型：强调优惠、有效期和买券/预约动作。

用户对成品做判断比对参数做想象更容易。每条路线的快捷操作应是业务语言：

- 更像老板本人 / 换技师身份。
- 不要太促销 / 加强优惠感。
- 改成小红书 / 抖音 / 微信视频号；或引用点评/美团事实并导出朋友圈/线下版。
- 换一组本店素材。
- 加强同城和到店引导。
- 把这一版做成海报 / 套图 / 口播。
- 做同款，再换一个项目。

### 9.3 只在关键未知事实处提问

需要追问：

- 用户指定的团购或活动没有价格、日期、链接或使用规则。
- 同名服务存在多个版本，无法安全判断要推广哪一个。
- 目标平台或表达身份会显著改变结果，但上下文没有可用默认值。
- 唯一相关素材权利不明，且用户坚持使用该素材。

不应追问：

- 已经存在于门店档案中的信息。
- Agent 能从行业场景包安全决定的结构和版式。
- 可以先给成品候选、再由用户选择的主观风格。
- 可以用安全素材或模板先完成的非阻塞素材缺口。

## 10. 正确的 Human-in-the-loop 切入方式

HITL 应围绕事实、主观判断、风险和资产沉淀切入，而不是围绕岗位强制排队。

| 人类介入类型 | 合适节点 | 交互方式 | 是否沉淀 |
| --- | --- | --- | --- |
| 关键事实确认 | 价格、活动期、团购规则、老师履历等缺失或冲突时 | 单个问题、引用来源、就地确认 | 确认后写入对应事实资产并保留来源/有效期 |
| 主观喜好选择 | 主推荐不合适，或用户主动查看其他合理方向时 | 直接采用主推荐；需要时展开备选、混搭或说明喜欢点 | 单次选择先作为弱信号；重复或用户明确要求后再成偏好 |
| 临时纠偏 | “这次别太促销”“这条不要讲价格” | 对当前成品直接说，立即局部重编译 | 默认只影响当前任务 |
| 长期表达规则 | “以后这个 IP 都用第一人称”“价格卡一直用这套颜色” | 系统复述后提供“仅本次 / 以后都这样” | 用户确认后写入 IP、品牌或模板资产 |
| 可复用成果 | 一条内容、栏目、物料组合被确认有效 | “保存为系列 / 做同款 / 保存为门店模板” | 明确动作后进入本店私有资产库 |
| 外部不可逆动作 | 官方发布、账号授权、付费投放或其他高风险动作前 | 展示最终成品、目标账号、CTA 与风险摘要，单次确认 | 保存审计，不把批准自动泛化为永久授权 |
| 特定素材权利 | 被选素材含顾客肖像、身体/面部、评价、案例结果等时 | 就地显示权利状态；允许替换、脱敏或补充授权 | 只更新该素材/用途的权利记录 |

用户的内容偏好与门店事实不能混为一类记忆。“我喜欢这版”不是事实，“这个项目价格是 398 元”也不是风格偏好。

## 11. 顾客素材授权只是一道条件式素材权利门

### 11.1 何时触发

只有被实际选入公开成品的素材包含下列内容时才触发：

- 可识别顾客肖像、面部、身体或姓名。
- 顾客评价截图或聊天记录。
- before/after、项目结果或敏感案例。
- 授权范围、平台、期限或商业使用状态不明确的顾客相关内容。

### 11.2 触发后的处理分支

```text
rights = allowed_for_this_use
  -> 正常使用并记录用途

rights = unknown / expired / scope_mismatch
  -> 优先推荐替换素材
  -> 或脱敏 / 裁切 / 模糊到不可识别
  -> 只有用户坚持使用时才补充授权

rights = blocked
  -> 不进入公开成品；生成不依赖该素材的安全版本
```

### 11.3 明确不做的事

- 不把每条内容都变成“先找顾客授权”的流程。
- 不虚构顾客同意、评价或案例结果。
- 不因为一个案例素材不可用而阻塞整次宣发任务。
- 不把“技师、店长、账号责任人”串成固定审核队列。

权限系统可以配置谁有权修改素材权利、确认受监管内容和执行发布，但这些是后台 policy，不是用户主路径。

## 12. 平台机制与成品适配

下表是产品层抽象，不宣称平台算法或自动发布能力。实际能力必须读取账号级 verified capability，平台规则需版本化更新。

当前首发公开内容变体锁定小红书、抖音和微信视频号。点评/美团先作为项目、团购和履约事实来源，微信私域与线下物料先走可校验导出；只有账号级能力和发布回执真实验证后，才把某个平台升级为自动发布目标。

| 平台容器 | 主要成品形态 | 适配重点 | 常见承接 |
| --- | --- | --- | --- |
| 小红书 | 封面、图文套图、正文、话题、必要的视频脚本 | 搜索/种草语境、封面信息层级、真实体验或专业解释、素材顺序 | 评论/私信、主页、预约信息；以账号实际能力为准 |
| 抖音 | 短视频口播、分镜、字幕、封面、发布文案 | 开头切入、画面与节奏、同城/项目关联、可拍摄性 | 评论/私信、团购、位置/主页；以账号实际能力为准 |
| 点评/美团 | 项目介绍、服务/流程/价格卡、团购卖点、门店图 | 事实清晰、价格/优惠来源、门店信任和决策信息 | 买券、预约、核销、导航、到店 |
| 微信/私域 | 朋友圈文案、海报、长图、公众号素材 | 熟人信任、信息完整、活动时效、联系方式与预约说明 | 加微沟通、预约、转发、到店 |

平台变体共享同一 Content Core 和事实来源，但不是同一段文案机械裁切。

## 13. 从曝光到到店的反馈闭环

### 13.1 最小可观测结果

| 层级 | 信号 | 用途 |
| --- | --- | --- |
| 生产效率 | 从输入到首个成品的时间、追问次数、重做次数 | 判断是否真正降低创作门槛 |
| 内容采用 | 直接采用、小改、大改、拒绝、实际发布 | 判断成品是否像本店且可用 |
| 内容复用 | 做同款次数、系列续作、保存为门店模板 | 判断资产是否产生复利 |
| 曝光与互动 | 平台可取得的浏览、收藏、评论、主页访问等 | 观察内容是否获得注意；不承诺平台结果 |
| 转化信号 | 私信、问价、加微、预约、买券、核销、导航、到店备注 | 判断哪类任务、平台、IP 和 CTA 更接近经营结果 |

### 13.2 不做虚假归因

- 产品可以记录“这条内容之后出现了哪些线索”，但 P0 不声称严格因果归因。
- 不承诺 GMV、播放量、涨粉或到店量。
- 下一轮推荐应说明依据，例如“团购价格卡发布后关联到更多问价记录”或“主理人口播采用率更高”，而不是给出无法解释的自动决策或因果结论。

### 13.3 如何形成门店自己的复利

```text
生成成品
  -> 用户选择 / 修改 / 发布
  -> 记录采用与转化信号
  -> 识别有效的任务 + 身份 + 平台 + 素材 + CTA 组合
  -> 用户确认保存为栏目 / 模板 / 做同款配方
  -> 下一次只替换项目、热点或活动事实即可复用
```

## 14. 工程化的真正价值：重在后台，轻在前台

| 后台重能力 | 给用户的轻交互 |
| --- | --- |
| 六维任务解析与缺失信息判断 | 一句话目标或一个场景入口 |
| 多层上下文召回、冲突处理、来源与有效期 | 系统自动带出本店信息，只问真正缺失项 |
| 个性化资产与行业资产动态匹配 | 先看到属于本店的完整成品 |
| 热点相关性、原创重组和失效控制 | 看到“为什么适合本店”的热点建议 |
| 平台变体、模板渲染、发布包与异步恢复 | 点一次得到多平台内容和物料，可离开后回来继续 |
| 价格、权利、资质、AIGC 和合规 gates | 仅在相关风险出现时就地处理 |
| 临时纠偏、长期偏好、模板资产的分层写回 | “仅本次 / 以后都这样 / 保存为模板”三个清晰选择 |
| 内容、发布与线索关联 | 周报直接告诉用户哪些打法值得继续做 |

工程实现不应反向塑造出工作流编辑器、角色泳道、大型配置表或多窗口资料录入。复杂度要存在，但只能存在于 Agent 编译、状态机、事实来源、异步任务、审计和资产版本中。

## 15. 产品验收标准

### 15.1 主链验收

- 首次进入能直接看到“今天发什么、推项目、跟热点、做 IP、做活动/团购、做物料”等业务入口。
- 已有门店基础资产时，用户用一句话或一次选择即可得到首批完整成品，不需先填六维表格。
- 每个成品都能解释其宣发任务、表达身份、使用事实/素材、目标平台和转化动作。
- 同一 Content Core 可以生成真正的平台变体、物料和发布包，而不是复制粘贴。
- 用户可以对成品执行换身份、换平台、换素材、加强到店引导和做同款。
- 任务异步运行可离开、恢复、失败重试，不要求用户守在步骤页面。

### 15.2 个性化验收

- 不把其他门店、其他 IP 或过期活动的事实串入当前内容。
- 价格、团购、资质、经历和案例结论有可追溯来源。
- 同一项目用品牌官方、主理人和技师身份生成时，内容视角有真实差异。
- 用户明确的长期规则在后续同类任务中生效；单次纠偏不会污染长期资产。
- 认可的内容可一键沉淀为本店模板/栏目，并可换项目或热点复用。

### 15.3 纠偏验收

- 产品设计、研究报告和原型不再出现固定的“技师 -> 顾客 -> 店长 -> 账号责任人”默认链路。
- 角色只用于权限和责任配置，不作为内容生产导航。
- 顾客授权只在实际使用相关顾客素材时触发；权利不明时能换素材或生成安全版本。
- 热点只在与本店有可解释关联时推荐，公开内容保持原创或有授权。

## 16. 下一轮需要真实研究验证的判断

以下是待验证假设，不应提前固化为产品事实：

1. 六个首屏入口的使用频率和排序；是否“今天发什么”应成为唯一默认入口。
2. 各细分业态中，项目曝光、热点借势、IP、团购和物料的实际周频次与付费价值。
3. 老板/主理人、品牌官方、技师/专家等表达身份在不同业态中的真实使用比例。
4. 商家判断热点“与我有关”的标准，以及热点过期速度和可接受的原创改编幅度。
5. 哪些店能直接提供团购/订单/预约数据，哪些只能手工确认当前活动与转化信号。
6. 先给 2 个还是 3 个完整方向更利于快速选择；多少快捷修改会开始造成负担。
7. 哪些长期偏好可以由重复行为推断，哪些必须由用户明确点击“以后都这样”。
8. 顾客案例、评价和 before/after 在各业态中的真实使用率；安全替代素材能覆盖多少任务。
9. 不同平台最小可用发布包及 CTA 能力，需要继续按账号逐级验证，不能只靠文档推断。
10. 私信、加微、预约、买券、核销、到店的记录成本，何种半自动回流方式能被门店持续使用。

研究时应以真实宣发任务回放和成品测试为主，而不是询问门店“你们是否需要某个 Agent 工作流”。

2–4 周任务日历可以校准宣发任务频率、素材来源和入口排序，但不能证明产品已经形成长期复用。持续采用、栏目/IP 资产复利和付费价值应继续观察到 8–12 周，并至少保留一组无实时陪跑的自助样本，避免把运营人员的人工补位误判为 Agent 产品能力。

## 17. 决策摘要

1. **美业产品主链 = 宣发任务与流量机会驱动的内容/物料生产，服务广告曝光和到店引流。**
2. **六维模型 = 宣发任务 × 流量机会 × 表达身份 × 平台机制 × 门店事实/素材 × 转化动作。**
3. **个性化资产提供事实、身份和证据；行业资产提供场景、结构、平台和物料配方；Agent 在后台编译两者。**
4. **前台以示例起步、场景入口、最少素材、参数自动、成品优先、快捷修改、异步恢复和做同款复用为原则。**
5. **HITL 围绕关键事实、主观选择、临时纠偏、长期偏好、可复用资产和不可逆动作切入，不围绕岗位排队。**
6. **顾客素材授权降为特定素材权利门，不再定义默认创作链。**
7. **工程价值应藏在上下文、工作流、资产匹配、事实来源、异步状态、审计和反馈学习中，不暴露为表格和窗口。**
