# 小白创作交互与质量反馈闭环研究

- 调研日期：2026-07-24
- 研究票：`.wayfinder/issues/lpgs-05-research-novice-creation-ux-and-quality-loop.md`
- 研究问题：非专业用户如何用一句话、示例、素材或少量选择表达需求；品牌、身份与场景约束如何进入结果；Brief 何时可见、可改、可复用；系统如何从采纳、编辑、重做和偏好反馈中改善下一次结果。
- 产出边界：本报告给出研究结论、适用边界、最小流程候选和反馈信号候选，不画最终原型，不锁定最终字段或技术实现。

## 1. 证据口径

本文统一使用三类标签：

- **【事实】**：官方帮助文档明确描述的产品能力，或仓库中已有登录态只读实测直接观察到的行为。
- **【推断】**：由多个事实共同支持、但产品方没有直接宣称的机制判断。
- **【建议】**：面向“美业内容副驾”的候选设计，不等于已实现或已拍板。

外部资料检索遵循当前项目要求：

- 本报告收录的官方页面均于 2026-07-24 使用 `opencli web read --url ... --stdout -f yaml` 重新读取。
- Open CLI 对本报告引用页面均返回了有效正文，因此没有使用 Web Search 降级，也没有把搜索摘要作为证据。
- 官方帮助页只能证明“产品文档描述的能力”；除本地明确标记为“登录态实测”的材料外，本文不把官方营销文案等同于当前账号下的实时行为。
- 本地登录态证据均为已有只读留档；本轮没有触发生成、消耗积分或执行外部写操作。

## 2. 结论摘要

1. **【推断】小白并不需要学会 Prompt，而需要用自己已有的表达介质下任务。** 一句话适合表达目标，示例适合表达“想做成什么样”，素材适合提供真实对象与品牌归属，少量选择只负责补足平台、交付物或不可安全推断的关键差异。
2. **【建议】所有入口应编译到同一个“任务 Brief”，但默认不展示原始模型 Prompt。** 用户应能检查的是业务语言中的任务、身份、事实、素材、平台、CTA 与限制，而不是模型指令。
3. **【推断】隐藏 Prompt 只在输出合同足够窄时真正降低门槛。** 可灵和 Higgsfield 的登录态实测都显示：选定具名预设后，Prompt 输入被移除，用户只需上传符合要求的素材；开放式创作则仍保留自然语言入口。
4. **【建议】主流程最多追问一个真正阻塞的问题。** 非关键缺口采用可逆默认值并先给结果；价格、活动有效期、表达身份、素材权利等真实性或权限问题不能被默认值代替。
5. **【建议】第一次先给一个可判断的主推荐，不把模型不确定性变成多选题。** 快捷修改和自由文本同时存在；修改默认只影响当前结果。
6. **【推断】“重做”不是稳定的负反馈，“编辑差异”比单一好/坏更有解释力。** 采用、导出或发布是强结果代理；具体编辑暴露了不满意的维度；重做可能只是探索，必须结合原因、后续采用和任务上下文解释。
7. **【建议】长期偏好只能由明确意图或重复模式经确认后形成。** 一次修改、一次重做、停留时长或下载行为都不应静默升级为永久偏好；用户必须能查看、更正、撤回和限定作用域。

### 3.1 各输入方式的职责边界

| 输入方式 | 【建议】最适合表达 | 【建议】系统应如何处理 | 【建议】不适合承担 |
| --- | --- | --- | --- |
| 一句话 | 当前目标、对象、期望动作、明显限制，如“把新团购做一套小红书能发的” | 保留原话；抽取任务候选；自动匹配已有门店、项目、身份、素材和平台上下文；以 Brief 摘要显示关键推断 | 精确价格、有效期、资质、授权范围等不可猜事实 |
| 示例 / 基于此再创作 | 成品类型、结构、节奏、视觉方向和质量预期 | 明确标注示例来源；列出将继承的“结构 / 视觉 / 素材槽 / 平台形式”；用当前门店事实重新填充 | 直接复制示例中的门店名、价格、顾客信息、版权素材或身份 |
| 素材 / 参考图 | 本店真实对象、人物、环境、项目效果、品牌风格和构图参考 | 先声明素材角色；显示本次实际使用了哪些素材；权利不足时替换、匿名化或请求确认 | 把素材视觉内容无条件当作真实业务事实或长期品牌规则 |
| 少量选择 | 平台、输出类型、比例、数量、显著风格差异、成本或风险差异 | 使用可点 chips / 卡片；已有上下文时预选；只展示会明显改变结果的选项 | 模型名、采样参数、节点、内部 Prompt、完整工作流配置 |
| 对话补充 | 一个当前无法安全推断且会阻塞交付的问题 | 一次只问一个；提供 2–3 个具体候选和“稍后补 / 用安全版本”退路 | 把完整建档或多字段表单伪装成连续聊天 |

## 4. 五类交互机制的适用边界

### 4.1 隐藏 Prompt

**【事实】** 可灵和 Higgsfield 的登录态留档都观察到“选择具名预设后 Prompt 框消失”，且界面把用户注意力转向素材要求和生成动作。[可灵证据][kling-local] [Higgsfield 证据][higgsfield-local]

**【建议】适用条件：**

- 技能名称本身已表达明确任务，如“把一张项目图做成 9:16 动态展示”；
- 输入槽、输出种类、允许变化和失败回退都已固定；
- 系统不需要猜价格、活动、身份、资质或素材授权；
- 用户仍能看到业务语言的输入要求和结果用途；
- 生成后可以基于结果修改或切回开放模式。

**【建议】不适用条件：**

- “给门店做一次宣传”这类意图和交付物仍不明确；
- 结果会使用关键经营事实、人物身份或受限素材；
- 多平台、多个 CTA 或品牌/IP 之间存在冲突；
- 隐藏 Prompt 会同时隐藏系统对用户意图的高影响推断。

**结论：** 隐藏的是模型指令，不应隐藏业务理解。窄技能可以完全不露 Prompt；开放任务应显示可检查 Brief，原始 Prompt 仅作为高级排障或学习入口。

### 4.2 可检查 Brief

**【建议】Brief 不是长 Prompt，也不是审批表。** 它是系统对本次任务理解的可读投影，最小包含：

1. **做什么**：任务与本次交付物；
2. **给谁 / 在哪里用**：目标客群、平台或用途；
3. **谁在说**：品牌、主理人或专业人员身份；
4. **根据什么**：项目、活动、关键事实和实际使用素材；
5. **希望用户做什么**：CTA；
6. **不能做什么**：真实性、权利、专业或品牌限制。

**【建议】默认呈现方式：**

- 一句话或素材提交后，先以 4–6 个摘要 chips 折叠显示，不强制用户逐项检查；
- 用户点任一 chip 可就地更换或纠错，修改默认只影响当前任务；
- 当系统做了高影响推断、存在事实冲突、引用受限素材、费用显著或将执行外部动作时，在执行前展开相关项；
- 普通低成本生成不增加“确认 Brief”步骤，生成后仍可从结果旁查看和修改；
- 保存为模板或长期偏好时，不保存整段 Prompt，而保存固定结构、变量槽、适用范围、来源和权利。

**【推断】** ChatGPT 的对话式编辑与 Undo/Redo、Midjourney 的 Remix/Reset 和 Canva 的可编辑模板共同说明：小白需要的是“看见结果后可逆地改”，而不是生成前一次性把所有需求说完整。[OpenAI Images][oai-images] [Midjourney Remix][mj-remix] [Canva Magic Design][canva-magic-design]

### 4.3 字段表单

**【建议】主创作流程不使用多字段启动表单。** 字段控件只在以下条件同时满足时出现：

- 值是结构化且高影响的，例如平台、尺寸、活动日期、价格、权益、表达身份、素材用途；
- 系统没有可信现值，或现值冲突、过期、撤权；
- 错填会导致不可接受的事实、权利、成本或交付错误；
- 该值可以用一个 chip、日期选择、单选或单张确认卡完成。

**【建议】多字段管理页仍可存在于低频后台：** 门店资料维护、品牌资产、活动信息和授权记录适合结构化管理，但不应成为每次创作的前置门。

### 4.4 对话追问

**【建议】追问判准：**

1. 缺少该答案是否无法产生诚实、可判断的结果？
2. 是否无法从当前有效事实、素材、用户原话或安全默认值获得？
3. 问题是否能改变本轮输出，而不是为了“把资料补全”？

三项都为“是”才阻塞追问。否则先生成安全版本，并在结果旁给非阻塞补充入口。

**【建议】交互预算：**

- 提交前最多一个阻塞问题；
- 一次只问一个维度；
- 优先给 2–3 个具体答案和“使用安全默认”；
- 用户回答后回到原任务，不开启新的问卷；
- 同一任务再次缺信息时，应优先降低交付而非无限追问。

CreatOK 已留档的向导端点只能证明存在分步状态机，不能证明“越多问题越好”。[CreatOK 架构留档][creatok-arch]

### 4.5 技能 / 模板入口

**【推断】** 可灵、Higgsfield 和 CreatOK 的共同点不是“模板数量多”，而是模板用具名业务任务、结果预览、输入要求和固定默认值，把内部能力包装为可理解的成品入口。[可灵证据][kling-local] [Higgsfield 证据][higgsfield-local] [CreatOK 证据][creatok-local]

**【建议】技能是可复用任务合同，至少声明：**

- 它解决的业务任务；
- 预期交付物和示例成品；
- 最少需要的素材；
- 自动读取的门店 / 品牌 / IP 上下文；
- 允许用户修改的少数高影响项；
- 缺料、权利不足或能力不可用时的回退。

**【建议】首屏只保留少量高频技能或示例卡。** 长尾能力放入搜索、更多或结果后的“基于此再创作”，避免把小白重新放进工具市场。CreatOK 已有登录态观察也显示其工具全集被收进菜单，首屏集中于高频任务，但这只是竞品行为，不是首发数量的直接结论。[CreatOK 功能拆解][creatok-local]

## 5. 从结果到下一次结果：反馈信号研究

### 5.1 先区分“任务结果”与“长期偏好”

**【事实】** Midjourney 的 Personalization 是独立画像，可选择并开关；Canva 需要用户选择结果并加入 Brand Kit 才进入未来品牌资产使用；ChatGPT Memory 文档说明记忆可以查看、编辑或删除。[Midjourney Personalization][mj-personalization] [Canva 品牌图片][canva-onbrand] [ChatGPT 能力概览][oai-capabilities]

**【推断】** 成熟产品把长期复用做成显式对象或显式控制，而不是把每次编辑都默认为永久规则。

**【建议】本产品保持三层：**

1. **当前版本指令**：只改变当前成品；
2. **当前任务偏好**：影响同一任务的后续变体；
3. **长期偏好 / 可复用资产**：明确确认作用域后才生效，可查看、修改、关闭或删除。

价格、活动、资质、身份和素材权利属于有来源、有时效的事实，不能从编辑或点赞中学习。

### 5.2 信号强弱与含义

| 信号 | 【推断】可表达什么 | 歧义 / 风险 | 【建议】如何使用 |
| --- | --- | --- | --- |
| 采用为主推荐、导出、发布、复制完整成品 | 用户认为结果达到某个实际用途的最低标准 | 可能只是赶时间；导出不等于真正发布 | 作为本任务最强正向结果代理，必须绑定精确成品版本、平台和任务上下文 |
| 明确说“这个以后都这样”并确认范围 | 用户希望形成长期规则 | 范围可能仍不清楚 | 生成长期偏好候选，展示“门店 × 身份 × 场景 × 平台”最窄作用域后确认 |
| 保存为同款 / 模板 / 系列 | 用户希望复用结构或素材组合 | 旧价格、日期和顾客信息可能被一并带入 | 抽取固定结构和变量槽，预览来源、权利与适用范围后保存新版本 |
| 直接编辑文案、替换素材、改 CTA、平台或身份 | 指明了具体不满意维度 | 一次修改可能只为当前任务 | 记录前后差异和目标维度；默认只作用当前任务；重复模式仅生成待确认候选 |
| 快捷修改 chip | 提供结构化的纠偏原因 | chip 可能过粗，不能替代自由文本 | 记录 chip 与随后是否采用；保留“其他 / 直接说” |
| 轻改 / 强变体 / 局部改 | 用户想保留部分结果并探索 | 不等于否定原结果 | 记录保留对象、修改范围和后续采用结果，不直接写长期偏好 |
| 重做 / 再生成 | 当前结果未被直接采用，或用户正在探索 | 原因可能是随机性、质量、事实、素材、风格、平台或单纯想多看 | 不作长期负偏好；可非阻塞提供原因 chips，并以随后采用的版本解释 |
| 点赞 / 不喜欢 | 粗粒度显式态度 | 无法说明是内容、事实、风格还是偶然 | 与结果版本、原因和后续动作结合；只作为候选证据 |
| 停留、预览、展开 Brief、下载单个素材 | 可能表示兴趣或检查 | 噪声高，容易误判 | 只用于漏斗和可用性分析，不单独学习偏好 |
| 关闭、离开、任务失败 | 流程中断 | 可能是性能、价格、错误或外部原因 | 进入失败归因与产品诊断，不作为内容审美负反馈 |

### 5.3 重做原因候选

**【建议】重做时不弹必填问卷。** 在按钮附近提供可跳过的原因：

- 事实不对；
- 不像本店 / 不像这个人；
- 素材或主体不对；
- 结构 / 画面不喜欢；
- 平台或用途不匹配；
- 想看另一个方向。

其中“事实不对”“身份不对”“素材权利不对”必须进入事实或权利纠错通道，不能被记成审美偏好。

### 5.4 最小事件语义候选

这不是最终数据合同，只用于说明质量闭环至少需要哪些语义：

```text
ResultSignal
  task_id
  package_revision_id
  action                 # adopt | export | publish | edit | retry | reject | save_as_asset
  target                 # copy | image | video | asset | brief | package
  reason_code?           # optional, never required for retry
  delta_summary?         # what changed, not raw private content by default
  requested_scope        # revision | task | campaign | scene_ip_platform | store
  explicit_persistence   # whether user explicitly asked to remember/reuse
  occurred_at
```

**【建议】数据最小化：**

- 信号绑定精确任务和成品版本，避免只存一个脱离上下文的“喜欢”；
- 默认保存结构化差异摘要，不为学习目的复制全部私密原文和素材；
- 长期偏好晋升另有确认事件，不能由 `edit` 或 `retry` 自动生效；
- 跨门店、跨身份、跨平台默认不共享；
- 用户可查看触发偏好候选的证据并撤回。

## 6. 最小小白主流程候选

以下是行为流程，不是最终页面或原型。

### 第 0 步：同一个起点

**【建议】** 首屏同时提供：

- 一个可直接说人话的 Composer；
- 上传图片 / 视频 / 文档的素材入口；
- 4–6 个可见的技能或示例成品卡；
- 已有门店上下文的轻量提示，但不要求先建完档。

用户可从一句话、一个示例或一份素材任意起步，三者最终进入同一任务 Brief。

### 第 1 步：自动形成可检查 Brief

**【建议】** 系统在后台合并：

- 用户原话；
- 当前门店、项目 / 服务和活动事实；
- 已确认品牌 / IP；
- 已授权素材；
- 场景与平台默认值；
- 已确认且命中当前作用域的偏好。

前台只显示 4–6 个业务 chips 和“本次用了哪些事实 / 素材”，不展示长 Prompt。

### 第 2 步：只解决唯一阻塞点

**【建议】** 如果缺少价格、有效期、表达身份、素材用途等不能安全推断的信息，一次问一个；否则采用安全默认值继续。高成本生成、受限素材或外部动作只确认受影响的那一项。

### 第 3 步：先交一个主推荐

**【建议】** 第一次返回一个完整、可判断的主推荐，而不是要求用户先从多份半成品中选方向。主推荐旁显示：

- 使用了哪些本店事实和素材；
- 适用平台 / 用途；
- 快捷修改；
- 自由文本修改；
- 必要时的“看另一个方向”，最多展开少量备选。

### 第 4 步：在结果上纠偏

**【建议】** 用户可：

- 直接采用、导出或进入发布；
- 改文字、身份、素材、CTA 或平台；
- 对图像 / 视频做局部改、轻改或换方向；
- 基于此再创作；
- 重做并可选说明原因。

所有普通修改默认标记为“仅这版”，并提供 Undo / 恢复上一版。

### 第 5 步：非阻塞地提议复用

**【建议】** 用户已经得到可用结果后，系统才可提议：

- “以后该平台都少一点促销感”；
- “保存为本店团购三段式”；
- “把这组视觉作为品牌参考”。

提议必须说明观察证据、固定项、变量槽和最窄作用域；用户确认后才进入长期偏好或可复用资产。

### 第 6 步：下一次透明复用

**【建议】** 下一任务命中偏好或模板时，以一个可关闭的说明展示“本次沿用了什么”；用户可临时关闭、修改范围或删除，不要求再次学习 Prompt。

## 7. 质量闭环指标候选

| 目的 | 指标候选 | 解释边界 |
| --- | --- | --- |
| 降低首任务门槛 | `time_to_first_evaluable_result`、首轮阻塞问题数、Day-0 任务完成率 | 需剔除供应商队列等待；完成不等于质量合格 |
| 衡量结果可用性 | 主推荐采用率、导出 / 发布率、采用前编辑次数、采用前重做次数 | 导出 / 发布是代理指标，需结合真实任务和平台 |
| 衡量 Brief 质量 | Brief 纠错率、事实 / 身份 / 素材 chip 替换率、因 Brief 冲突被阻塞比例 | 纠错率下降不能以隐藏错误或减少可见性换取 |
| 衡量修改效率 | 从首次结果到采用的时间、局部改后采用率、恢复上一版率 | 需要区分内容质量与交互可用性 |
| 衡量学习价值 | 偏好候选确认率、确认偏好后采用率变化、保存模板复用率 | 只统计已确认、命中正确作用域的偏好 |
| 防止错误学习 | 未确认偏好生效率、事实被当偏好覆盖次数、撤回后继续命中次数 | 三项上线阈值应为 0 |
| 防止真实性与权利事故 | 错价格 / 活动、错身份、未授权素材、跨门店串线次数 | 不得用采用率抵消，属于独立硬失败门 |

## 8. 研究支持的取舍

### 应采用

- **【建议】** 一句话、示例和素材并列为同一 Composer 的自然输入；
- **【建议】** 业务语言 Brief 可检查、可就地改，模型 Prompt 默认隐藏；
- **【建议】** 具名窄技能可以完全隐藏 Prompt，但必须显示输入要求和输出用途；
- **【建议】** 少量高影响 chips，普通任务最多一个阻塞问题；
- **【建议】** 一个主推荐 + 结果上快捷修改 + 基于此再创作；
- **【建议】** 采用、编辑差异、重做原因和长期偏好确认分开记录；
- **【建议】** 长期偏好与可复用资产有明确作用域、来源、版本和撤回。

### 不应采用

- **【建议】** 空白聊天框承担全部发现、建档和创作；
- **【建议】** 生成前多字段必填表；
- **【建议】** 把模型、节点、内部 Prompt 和供应商参数暴露给小白；
- **【建议】** 第一次就要求在大量方向中选择；
- **【建议】** 把一次编辑、一次重做、停留或下载静默学习成永久偏好；
- **【建议】** 将示例中的事实、人物、价格或版权素材复制进本店上下文；
- **【建议】** 用审美偏好覆盖事实、身份、资质或素材权利。

## 9. 尚需用真实门店任务验证

1. 用户首任务更常从一句话、示例还是素材起步；
2. 4–6 张首屏技能 / 示例卡是否足够，何种排序真正提高首任务完成率；
3. 哪些 Brief chips 对用户有解释价值，哪些只是系统自我暴露；
4. “最多一个阻塞问题”在哪些高风险任务上需要例外；
5. 一个主推荐与少量备选的采用率、修改成本和信任差异；
6. 重做原因 chips 的选择率及其对下一版采用率的真实提升；
7. 哪些重复编辑值得生成偏好候选，以及确认频率怎样避免打扰；
8. 已确认偏好是否在正确门店、身份、场景和平台作用域内改善结果；
9. 示例、参考图和品牌资产的权利提示是否足够清楚；
10. 真实门店素材下，图文 / 视频结果的主体、品牌、中文排版和导出稳定性。
