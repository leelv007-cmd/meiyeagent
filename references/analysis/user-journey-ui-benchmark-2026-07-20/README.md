# 用户旅程与 UI 对标增量审计（2026-07-20）

## 1. 本轮结论

当前产品的核心问题不是缺少入口或底层合同，而是**入口层信息过载、结果层成品感不足**：

1. Day-0 首屏同时呈现今日推荐、图文/视频切换、场景卡、素材说明、输入、额度、营销入口和更多启动方式；功能都在，但用户需要先理解产品结构才能开始。
2. 提交后的工作台能承载候选、版本、设置、Job、ContentPackage 和派生任务，但呈现仍偏工程记录；小红书图文、图片套图、视频成片没有各自成为视觉中心。
3. 现有 durable Task / Work / Job / Asset / ContentPackage 合同、来源血缘、异步恢复、候选采用和 result 阶段自由调整都值得保留，不应通过另建三套孤立工具页解决 UI 问题。

已确认的产品结构是：

> **一个统一创作入口 + 三类成品工作区（文案/图文、图片、视频）+ 一套共享任务、历史、素材和调整合同。**

统一的是“如何开始、如何等待、如何恢复、如何追溯”；分化的是“如何看结果、如何修改、如何交付”。

该结构已于 2026-07-20 由用户接受并记录为 D-073。首屏又通过 D-074～D-078、D-081～D-084 收敛为已确认的四层架构：用户主动选择 `文案 | 图文 | 视频` 对口，再由动态 Composer、快捷模板和两类创作工具承接；系统不得推断、推荐或默认选中创作对口。首个发布版本暂采用六张快捷卡片与八个单对口 Recipe variant，三个对口、精选模板和工具推荐均由后台版本化 Surface 配置发布，不永久硬编码在前端。移动冷态六卡以两列三行完整展示，模板与工具分区进入同一全屏目录的不同 kind，不用横向隐藏或半高抽屉承载完整目录。后续仍需逐项细化三类成品工作区。

## 3. 当前产品：保留什么，修什么

### 3.1 已经成立的能力

- 商家一级导航已经收束为创作、内容、素材、门店，未退化为工具大全。
- Day-0 与 Day-N 使用同一工作面；没有事实时诚实显示冷态，不制造伪个性化。
- 图文/视频、场景建议、真实素材上传、粘贴/拖放、来源引用和示例做同款已经进入同一 CreationEntry。
- 第一条业务写入发生在用户明确开始创作之后；示例浏览和预填不污染门店事实。
- 文案可以流式返回主推荐，备选折叠；Job、Asset、Work、ContentPackage、历史与来源血缘有稳定合同。
- 异步任务可恢复，结果不靠 toast 或临时页面状态表达。
- result 阶段已经有常驻自由文本“调整方向”，通过派生 Work/revision 实现，不新增消息真相层。
- 模型、费用和高级设置可以渐进展开，媒体能力已有显式可用性和引用边界。

### 3.2 首屏结构问题

当前首屏依次出现：大幅氛围图和问候 → “今天值得发什么”大卡 → CreationEntry。CreationEntry 内又同时放入：

- 图文/视频 operation；
- 主场景和展开场景；
- 大型素材上传区与意图输入；
- 跳过、额度和主按钮；
- 五类营销上下文；
- 今日建议；
- 更多启动方式、模板、来源及 Agent/直接模式。

这不是传统多页表单，但在认知上仍形成“表单回潮”：用户面对多个彼此重叠的分类法，需要先决定产品怎么工作，才能说出自己想做什么。

直接影响：

- 第一屏主轴从“一句话开始”变成“先浏览推荐与分类”。
- 场景、营销任务、今日建议和模板都在争夺“我应该点哪个”的解释权。
- 素材授权说明和链接解析状态在输入前后占据较大高度，使简单文案任务也显得很重。
- `暂时跳过`、额度、主 CTA 同屏，虽然只有一个 primary，仍让用户感到在完成一套开通步骤。

### 3.3 结果结构问题

文案结果已经有主推荐、评分、备选折叠、采用和再生成，但真机上仍呈现为一张大白卡中的文本记录：

- 没有小红书手机预览、标题/正文/话题/首图/CTA 的成品结构。
- 图片序列、封面与正文没有共同组成可编辑的图文笔记。
- “调整方向”虽已实现，但位于长记录靠后位置，不像结果阶段的持续主输入。
- `本次设置`、费用、Job、候选、版本和 ContentPackage 都正确，却缺少“默认只看成品、证据按需展开”的层级。

图片和视频若沿用同一记录排布，会继续把媒体预览降为合同附件；这也是为什么入口可以统一，结果不能强行同构。

## 4. 对标产品的可迁移价值

### 4.1 小云雀：立即开始 + 自动默认

值得借鉴：

- 登录后直接进入创作面，Composer 在首屏中心；历史、技能和作品围绕它组织。
- 图片/视频模式仍在同一壳内，切换后只改变上下文、模型/比例/时长和推荐词。
- “查看全部”使用一层可筛选的创作工具目录，同一目录里的入口可原位改写 Composer、打开聚焦工具弹层或进入独立画布工作区。
- 自动比例、自动时长、自动模型是默认；具体模型和比例在二级菜单中展开。
- 参考、画布和创意助手以单按钮收口复杂能力。
- 示例作品和做同款承担 onboarding，不另建前置教学流程。

结合我方改造：

- 保留“同一 Composer 切上下文”，前台采用用户已确认的 `文案 | 图文 | 视频` 创作对口；三项由用户主动选择，系统不根据输入、素材或模板推断和切换。
- “图文”继续通过当前模板或交付物 chip 区分纯图片、海报/套图与图文笔记，再编译为既有 operation 和 ContentPackage child runs。
- 用户选定创作对口后，模型、比例、时长等专业参数仍可由门店、平台、场景、套餐和当前模板编译 Auto 默认；这些默认不得反向改变创作对口。首层紧凑显示产品模型与当前最相关设置，完整目录和专家参数按需展开。
- 创作工具只保留 `composer_recipe` 与 `standalone_tool` 两种产品入口；弹层、独立页和 Pro Studio 只是 standalone 的不同承载容器。

明确不采用：

- 不复制达人带货等多字段必填 modal。
- 不把模型新品 banner、通用作品流或短剧 Agent 变成美业产品主叙事。
- 不照搬“点击自由画布即静默创建空项目”的浏览副作用；我方只有在用户明确新建/开始后才持久化对象。

### 4.2 CreatOK：生成器、示例、历史和资产闭环

值得借鉴：

- Dashboard 用视频/图片/分析切换承载高频入口，输入、参考、模型、规格、数量、优化、向导和消耗在一个紧凑组件中闭环。
- 专项生成页把“历史 / 示例”与底部固定生成器组合，用户看参考时仍能立即开始。
- Agent 不是泛聊天，而是“一句话 + 技能 + 三个高频任务”。
- 资产库、任务历史和生成页是同一循环；异步生成不是一次性响应。
- “优化”“向导”把复杂 prompt 工程收口为快捷代理动作。

结合我方改造：

- 采用“历史 / 示例 / 当前任务”作为同一创作上下文的可切换投影，不建立每个工具一套历史。
- 采用“优化本次意图”“帮我补齐”“做同款”这类一键代理动作，但底层继续派生 Task/Work 并保存血缘。
- 视频大额消耗继续显式确认；普通文案和低成本图片不把 credits 变成首屏主信息。
- 默认模型、规格和报价由已发布运行时配置驱动；用户未明确选择时可跟随新默认，用户已经明确选择 CatalogModel 后不得因后台默认变化静默换成另一模型。

明确不采用：

- 不复制 20+ 工具菜单、hover 工具大全和电商平台术语。
- 不让模型品牌、分辨率、时长和积分先于商家任务占据注意力。
- 不引入第二个 Agent 首页、第二套历史或第二资产真相。

### 4.3 讯飞绘文：选题到成文 + 文档资产

值得借鉴：

- 创作首页用“直接成文、一题多写、仿写、改写、二次创作、跨平台适配”等任务 chip 把空白输入变成明确写作动作。
- 选题中心把“来源 + 赛道 + 话题 + 原文”串成可解释证据链，比孤立热榜更适合承接“为什么今天值得发”。
- 跨平台适配是一等任务：从已有内容出发，再选择目标平台和补充条件，不要求用户重新编译一份 prompt。
- 草稿箱、知识库、图片库形成文档创作资产面；最近创作在侧栏可直接恢复。
- 文章创作拥有独立编辑语义，生成不是终点；后续校对、改写、标题、摘要、封面和平台适配属于同一内容生命周期。

结合我方改造：

- 把“选题中心”能力折叠进“今天值得发什么”的证据抽屉：显示为什么推荐、来自哪里、适合哪个门店/平台，并可一键进入 Composer。
- 用美业任务替代通用写作术语：从案例图写小红书、把旧帖改成同城版本、一题三写、换平台口吻、生成活动图文套组。
- 图文笔记结果进入轻量编辑工作区，标题、正文、话题、CTA、封面和图片序列共同形成 ContentPackage revision。

明确不采用：

- 不复制“文章类型 / 字数 / 主题”等前台空槽句式；只借其可读性，由 Agent 先补齐事实和默认值，再显示可改的 Brief chips。
- 不复制矩阵号运营、发布数据、账号空间等超出当前产品定位的一级导航。
- 不把搜索热点或大模型直接发散的话题当成门店事实；推荐必须展示证据等级与时效。
- 不用“草稿箱/知识库/图片库”重建与 Content、Asset、Work 冲突的新对象。

## 6. 推荐目标结构

### 6.1 一个统一创作入口

2026-07-20 已通过 D-074 选定统一 Composer 主轴，D-081 进一步明确冷态必须由用户主动选择创作对口；本节不再保留自动推断对口的方案。

用户已确认修订后的四层架构合理。首屏从上到下为：

1. 轻量问候和一条“今天值得发什么”推荐，可展开理由，不再使用大卡占据主轴。
2. 单一 Composer：冷态均未选中的 `文案 | 图文 | 视频` 对口、一句话和 `+` 来源；用户选中后再显示当前产品模型、动态相关设置、预计总消耗和唯一主 CTA。
3. 快捷模板：从案例图写小红书、朋友圈项目介绍、项目/活动套图、促销海报、抖音项目成片、旧内容换平台。
4. 工具组合：少量上下文推荐 + Pro Studio +“查看全部”；示例/近期作品继续位于其后。

场景、营销入口、今日建议、模板和工具不再五套并列：

- “场景”成为推荐和 brief 的上下文标签；
- “快捷模板”以版本化创作配方共同建议上下文、模型、设置、来源要求和输出合同；
- “工具组合”只推荐当前任务相关的增强能力，完整目录进入“查看全部”；
- “今日建议”只负责推荐一个可解释的起点。

模板、创作对口、模型设置和工具选择共享可预览、可提交、可撤销的变更合同。创作对口只能由用户显式选择；切换时原文、来源、素材和权利事实始终保留，不兼容的模板、显式模型、手改参数和工具先暂存并展示差异。系统只能更新已选对口内未被用户触碰的默认值。普通用户可看到产品模型名称，但不看到官方/中转交易方、Deployment、New API/Sub2API 或供应路由。

### 6.2 对话内 Brief 确认

用户选定创作对口并提交一句话后，不跳多字段设置页。Composer 下方出现一张可编辑摘要：

- 要做什么；
- 给哪个平台；
- 使用哪些门店事实/素材；
- 交付文案、图片或视频；
- 预计消耗与是否需要一次确认。

缺信息时一次只问一个问题；Agent 自动补全其余默认。用户可直接确认，也可改一个 chip 或用自然语言纠偏。

### 6.3 三类成品工作区

#### A. 文案 / 图文笔记

- 中心：标题、正文、话题、CTA 的轻量编辑器；支持选中改写、缩写、换语气和事实引用查看。
- 右侧或可切换预览：小红书/朋友圈/点评等平台成品预览。
- 媒体条：封面和图片顺序，支持替换、补图、改封面文案。
- 备选标题/段落按需展开，不同时平铺三份完整文案。

#### B. 图片 / 套图

- 中心：选中图片大预览；下方候选/套图序列。
- 快捷修改：换背景、保留主体、改比例、改文案、补一张、统一风格。
- 模型、prompt、seed、真实费用和来源证据进入“本次设置/运行详情”，不抢主视图。

#### C. 视频成片

- 中心：视频播放器和封面。
- 下方：分镜/镜头状态、字幕/口播、配乐与素材来源；精确编辑可进入现有 Composer/Pro Studio 边界内的适当工作区。
- 等待中仍占用同一位置，以阶段卡替换播放器；完成后原位回装，不自动跳走。

### 6.4 一套共享底层体验

- 顶部始终显示任务意图、来源和当前 revision。
- 底部常驻“调整方向”自由文本，快捷 chips 只是加速器。
- Task、Work、Job、Asset、ContentPackage 和 RouteSnapshot 继续保持现有唯一真相与血缘。
- Recent/历史只是跨对象投影；不为三种成品各建独立历史数据库。
- 采用、保存为内容、保存为素材、导出/发布是不同动作，状态语言不可混用。

## 7. 开发优先级建议

### P0：先修旅程结构

1. **首屏主轴重排**：推荐卡压缩，Composer 提到首屏；验证 1440×900 下输入、来源和主 CTA 无滚动可见。
2. **CreationEntry 分类收敛**：首发采用冷态均未选中的 `文案 | 图文 | 视频` 三对口，由用户主动选择；把 operation、场景、营销入口和今日建议编译为“已选对口上下文 + 快捷模板 + 动态设置”。对口编组、标签、顺序和精选组合读取已发布 Surface revision，但后台不得配置默认选中项；稳定执行合同仍为文本、图片和视频。
3. **共享 Task/Result Shell**：统一等待、恢复、异常、实际模型/费用和历史入口；默认隐藏工程证据。
4. **文案/图文成品工作区**：先补小红书图文笔记、普通文案和跨平台适配的编辑/预览闭环。
5. **图片成品工作区**：大预览、候选/套图、快捷修改、自由调整和资产采用。
6. **视频成品工作区**：播放器、分镜/字幕/封面、长任务状态和高成本确认。
7. **保护用户原始输入**：场景、模板或快捷任务只补充/变换上下文；不得无提示覆盖已输入内容，所有替换可预览、可撤销。
8. **清理启动语义**：把当前含混的“暂时跳过”拆成“暂不添加图片”和“退出本次创作”，并说明草稿是否保留。
9. **补齐移动新建图文断点**：手机创建 Work 后必须复用桌面同一“创建 ContentPackage + 提交 Harness”的编排 seam，不能只建空 Work 等待其他端补跑。
10. **补齐媒体结果直接动作**：图片/视频结果同屏提供下载、系统分享/复制链接、继续调整、保存到素材/内容和做同款；不能只给预览、详情或“去内容库”。
11. **创作工具入口合同**：首页只放少量相关工具和“查看全部”；实现 `composer_recipe` 与 `standalone_tool` 两类入口，所有结果复用当前 Task、Asset、ContentPackage 与报价合同。
12. **后台创作界面编排**：在既有管理壳增加“创作入口与模板”，提供结构化排序、替换、上下架、桌面/移动预览、校验、发布和回滚；前台与任务冻结 surface / recipe revision，不能使用散落硬编码或原始 JSON 作为正式交付。

### P1：补强连续使用

1. 选题证据抽屉与“推荐 → Composer → 成品”的可解释闭环。
2. Recent、示例和资产选择器统一，去除重复入口。
3. 移动端只保留采集、确认、进度、轻改和发布交接，不复制桌面编辑器。
4. 额度从预计、预占到实际扣除/失败返还保持连续可解释，并标明所属文案、图片或视频额度池。
5. 首次登录的 workspace provisioning 用可恢复 `pending` 状态承接，不把正常准备过程作为 500 暴露给页面。
6. 视觉密度、全局命令 option 名称、键盘路径、焦点顺序、横向列表可发现性、reduced-motion 与状态非颜色表达复核。

## 8. 验收指标建议

- 1440×900 冷态首屏无需滚动即可看到：三个必选创作对口、一句话输入、来源入口和下一动作；用户选择后同一位置显示精确交付物、预计消耗和唯一主 CTA。
- 输入“做一个抖音视频”、上传视频或点击后台推荐都不会自动选中视频；创作对口只能由用户点击、键盘选择或在模板差异确认中明确同意。
- 从输入一句话到普通文案/低成本图片任务开始不超过 2 次显式操作；视频只允许因高成本多一次确认。
- 首次用户无需理解 Agent/Direct、CatalogModel、Work/Job/ContentPackage 或模板 family 即可开始。
- 同一来源从等待到结果原位回装；刷新、离开再回来不创建重复 Job。
- 三类结果均能在首屏识别“成品、当前状态、下一动作”；运行证据最多一层展开可达。
- 图片和视频完成后，无需离开当前结果即可下载/分享、继续调整、保存和做同款。
- 修改模型、规格或数量后报价即时重算；后台默认更新不能改写当前任务中已明确冻结的模型选择。
- result 阶段自由文本调整始终在成品附近可见；提交后创建派生 revision，原结果不被覆盖。
- 图文笔记可以一次看见标题、正文、话题、首图/图片序列和平台预览，并形成一个 ContentPackage revision。
- 手机新建图文与桌面共享同一创建/提交合同，能进入 Progress 并得到可采用结果，而不是只创建 Work。
- 桌面、移动端均无横向页面溢出；所有核心操作具备键盘焦点、可读标签和不依赖颜色的状态说明。
