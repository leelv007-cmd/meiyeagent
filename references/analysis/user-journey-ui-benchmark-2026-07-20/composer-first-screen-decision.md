# 首屏 Composer 方向选择（2026-07-20）

## 1. 已确认结论

用户在三种首屏概念中选择方案 1，正式采用**意图先行 Composer**作为冷态默认方向：

> 用户在同一 Composer 顶部主动选择文案、图文或视频，再用一句自然语言说明今天想发布什么；系统只在已选对口内匹配具体交付物、来源、默认设置和预计消耗，商家任务快捷入口负责降低空白输入成本。

该选择已记录为 D-074。用户随后结合小云雀四处批注，明确补入“文案/图文/视频切换、快捷模板、动态模型与设置、工具组合”，并确认修订后的四层架构合理；对应决定记录为 D-076/D-077。D-081 又明确三项创作对口必须由用户主动选择，取代此前自动推断对口的口径。概念图用于锁定信息层级和交互主轴，不是最终像素稿、最终文案或后端数据证明。

![已确认方案：意图先行 Composer 四层架构](concepts/01-intent-first-selected-four-layer-tools.png)

## 2. 冷态首屏信息层级

从上到下只保留七层：

1. 轻量问候与一条“今天值得发什么”推荐；理由按需展开，不再用大卡挡住输入。
2. Composer 顶部固定提供 `文案 | 图文 | 视频` 创作对口；冷态均不预选，必须由用户主动选择。用户可以先输入或添加来源，但提交前必须选定一个对口。
3. 一句话输入与 `+ 来源`成为首屏唯一视觉中心；选中来源以 chips 显示，自动引用不得隐形。
4. 用户选定对口后，Composer 底部才动态显示当前产品模型、该对口最相关的 3～5 个设置、预计总消耗和一个有文字标签的主 CTA；专家项进入“更多设置”。
5. Composer 下方显示“快捷模板”，首批沿用六个商家任务；模板会共同建议上下文、模型和设置，但套用前必须可预览、套用后可撤销。
6. 再下一层显示少量“工具组合”和“查看全部”；Pro Studio 是次级专业工作区入口，其他工具按当前任务动态推荐。
7. 示例与 Recent 位于其后，并按当前创作对口与精确交付物过滤。

`文案 | 图文 | 视频`是前台创作对口，不直接等于底层 operation。“图文”同时承接纯图片、海报/套图和图文笔记，精确结果由当前快捷模板或可改交付物 chip 表达，再编译为既有 `copy.generate`、`image.generate` 或共享父 Task 下的 child runs。这样保留用户已经确认的三项切换，也不牺牲纯图片首轮可发现性。

## 3. 交互合同

- 用户可直接输入，也可从快捷任务开始；任何快捷任务、场景、模板或推荐都不能静默替换已有文字。
- 创作对口只能来自用户显式选择，不得根据输入文字、素材类型、模板、后台默认或系统判断自动选中或切换。系统仍可在已选对口内建议平台和精确交付物，但不能反向改变对口。
- 快捷模板是版本化创作配方：可见上下文补丁、模型策略、设置补丁、来源要求、输出合同和报价策略共同生效；隐藏 prompt 只保留服务端 revision 引用。
- 模板、创作对口、模型设置与工具选择统一执行 `previewChange → commitChange → undoChange`。切换对口必须始终保留原文、来源和权利事实；若模板、显式模型、手改参数、工具、素材角色或报价不兼容，先展示“保留 / 暂存 / 改变”差异，确认前保持原对口。系统只能改动仍属 system 且未被用户修改的对口内默认值。
- 动态设置行可以显示面向用户的 CatalogModel 产品名称，但官方 API、中转商、New API/Sub2API、Deployment 和真实供应渠道继续隐藏；固定模型不可用时阻塞并建议“改用智能匹配”，不得静默跨模型回退。
- 普通文案和低成本图片由主 CTA 合并确认并直接提交；多模态、高成本视频、素材授权或报价变化才原位展开一次条件确认。
- `+ 来源`统一承接真实素材、近期内容、门店事实和选题证据；上传失败只影响对应附件，不清空草稿。
- 提交后同一 Composer 原位进入可离开、可恢复的 Task 状态；完成后进入对应成品工作区，Composer 收缩为常驻“调整方向”。
- 对口、模型、规格和报价 revision 一旦随 Task 冻结，不得被后台默认更新或界面切换静默改写；如需改变对口，必须基于当前内容创建派生草稿。

## 4. 不采用为冷态默认的方向

### 交付物货架优先

![备选方向：交付物货架](concepts/02-deliverable-shelf.png)

不把 4～6 个交付物做成首屏第一视觉中心，避免用户在表达意图前先完成产品分类。其“文本、图片、视频对称可发现”价值保留为 Composer 下方快捷入口。概念图中超出现有“创作、内容、素材、门店”的导航仅属生成偏差，不进入产品范围。

### 可视 Brief 双栏优先

![备选方向：可视 Brief](concepts/03-visual-brief.png)

不把双栏 Brief 作为所有冷态任务的默认起点，避免简单文案回到多字段启动表单。其来源、交付物、规格和总消耗透明度只在多模态、高成本、低置信度或合同冲突时条件展开。

## 5. 现状改造要点

1. 将大 Hero 与推荐卡压缩，使 `1280 × 720` 能无滚动看到输入、推断交付物、来源和主 CTA。
2. 合并当前 CreationEntry 与后续 Record Composer 的重复启动阶段；普通路径不得先建空 Work 再要求第二次生成确认。
3. 补齐图片冷态一级入口，且不把任何非视频 operation 强制映射为文案。
4. 将场景、五类营销入口和今日建议分别收敛为推断上下文、快捷模板与轻量推荐；完整创作工具目录进入“查看全部”，不与六个模板并列扩张为卡墙。
5. 移除含混的“暂时跳过”，分别表达“暂不添加素材”或“退出本次创作”，并说明草稿保留状态。
6. 手机端复用桌面同一 `Work → ContentPackage → Harness Task` 提交 seam，只改变呈现，不改变业务合同。

## 6. P0 验收

- `1280 × 720`：一句话输入、交付物、来源和唯一主 CTA 无滚动可见；`1440 × 900` 额外可见一行快捷任务。
- 从一句话到普通文案/低成本图片开始不超过 2 次显式操作；视频只因高成本多一次确认。
- 浏览、预填、切换交付物和查看示例不产生 Work、Task 或 ContentPackage 写入。
- 快捷任务作用后原文逐字保留，替换必须可预览、可撤销。
- `文案 | 图文 | 视频`始终可见且冷态均未选中；只输入“做一个抖音视频”或上传视频也不得自动选择视频。图文下的纯图片、海报/套图和图文笔记都可由模板或交付物 chip 到达。
- 模板套用、模型/参数变化和工具选择都更新可见预览与报价；固定模型不可用时不得静默更换 CatalogModel。
- 用户无需理解 Agent/Direct、ExecutionChannel、ProviderProfile、Work/Job/ContentPackage 或内部 prompt family。
- 双击、刷新、离开返回和网络重连只产生一个 canonical 任务链，草稿、来源和冻结报价不丢失。
- 核心触区至少 `48 × 48px`；交付物、图标按钮、上传项和恢复动作具备稳定可访问名称；200% 缩放和 320px 有效宽度无页面横向溢出。

## 7. 暂定快捷模板与创作工具入口

首屏快捷任务暂定为（D-075，首发显示组合由 D-078 进一步纳入后台版本化配置）：

1. 从案例图写小红书；
2. 朋友圈项目介绍；
3. 项目/活动套图；
4. 促销海报；
5. 抖音项目成片；
6. 旧内容换平台。

六项现在正式解释为“快捷模板”而非六个孤立生成器。每项选择一个版本化 `CreationRecipeVersion`，向当前 Composer 提议可见上下文、模型策略、设置、来源要求和输出合同；未提交前只改变可撤销草稿，不创建业务对象。

D-082 已暂定首个发布映射：前台继续显示六张卡片，底层发布八个单对口 Recipe variant。前五张各指向一个具体 revision；“旧内容换平台”作为 Surface 内的 Recipe collection，只有在用户主动选择文案、图文或视频后才解析到对应 variant。该映射和默认输出均可由后台后续发布新 revision 调整，但不得追改当前草稿和历史任务。

D-083 已暂定六张卡片的首发副文案和点击规则：卡片明确写出目标对口，无受保护字段冲突时一击完成“用户主动选择 + 套用”，不统一增加确认弹窗；同对口手改冲突或跨对口切换才展示 `RecipePatchPreview`。“旧内容换平台”冷态继续不预选对口和目标载体。标题、副文案、顺序和预览素材后期可发新 revision 调整，安全动作由真实 lens 生成。

D-084 已暂定移动容器：冷态六卡使用两列三行完整展示，选定对口后收敛为最多四张 P0 卡片的两列两行；“查看全部模板”和“查看全部创作工具”进入同一全屏目录的不同 kind/tab，Pro Studio 继续使用独立全宽专业工作区横条。完整布局、返回恢复、抽屉边界与验收矩阵见 `mobile-creation-cards-catalog-decision.md`。

六项之后、Recent/示例之前增加“工具组合”行：首页只显示当前任务最相关的少量入口和“查看全部”。底层分为两类：

1. `composer_recipe`：在当前 Composer 内预览并套用，例如做同款、节点营销、旧内容换平台；
2. `standalone_tool`：打开聚焦弹层、独立页面或专业工作区，例如多平台尺寸适配、批量去背景和 Pro Studio。

“Pro Studio 无限画布”继续用于复杂多素材编排、高阶精修、TTS/SFX 和受控画布 Agent。它不作为第七个交付物，不进入默认一级导航，不使用首屏 primary；点击统一进入现有 `/pro-studio` 权益与 SSO 入口，不直接绕过锁定、购买或激活状态。

小云雀三条入口的实际操作证据和我方映射见 [创作工具入口补充走查](xiaoyunque-creative-tools-entry-audit.md)。完整工具目录和首批工具清单仍可根据真实任务频次、启动率、纠偏率、模型能力与成本调整，但“两类入口、一个 canonical 任务/资产真相”的边界已经锁定。

## 8. 后台可视化配置边界

三个创作对口、六个首页模板、各对口精选模板和工具推荐都作为**首发设计默认组合**进入开发，不永久写死在前端。后台“内容能力”增加“创作入口与模板”，允许管理员以结构化界面调整标签、顺序、精选项、上下架和目录排序，并通过 `草稿 → 预览 → 校验 → 发布 → 回滚`生效；运行时选择策略固定为用户显式选择，后台不得配置默认选中项。

配置只负责前台编排：当前 `文案 | 图文 | 视频` 是首个发布组合，后续可在 2～4 个用户可见对口内重新编组；`copy.generate | image.generate | video.generate`、成品工作区、模型/报价/路由和业务对象合同保持稳定。正常发布不能创造第四类 operation，也不能让文本、图片或视频任一首轮能力失去可发现入口。每个 Composer 初始 `lensId` 为空；用户选择后冻结所读取的 lens / surface / recipe revision，后台新发布版本只影响新草稿，不得选中或改变用户正在编辑、已报价或已提交的任务。

## 9. 创作对口显式选择与切换合同

2026-07-20 用户明确纠偏：三个创作入口不做自动推荐，由用户主动选择。首发采用“顶部三段式对口 + 当前对口模板过滤”的组合：冷态三个对口等权且均未选中，输入框和 `+来源`仍可先使用；未选时主动作提示“选择创作类型后继续”并把焦点移回对口组，不能替用户选中。

用户点选后才加载该对口的模板、模型、参数、工具、报价和目标结果工作区。快捷模板在冷态可以浏览，但跨对口动作必须明确写成“选择图文并套用”等，并把对口选择与 Recipe patch 作为一个可撤销的原子变更；已选对口下的模板不得静默切换到其他对口。

切换对口时，原始文字、来源、上传素材和权利事实始终保留。若当前模板、显式模型、手改参数、工具、素材角色或已确认报价不兼容，先显示差异预览：哪些继续保留、哪些只暂存、哪些将改变；取消保持原对口，确认后可以撤销，切回时恢复该对口之前的设置。选择、切换、预览、取消和撤销均为本地草稿状态，不创建 Work、Task、Job、ContentPackage 或额度预占。

桌面与移动共享同一 `unselected → selected → switch_preview → frozen` 状态机。对口组使用必选 `radiogroup`，初始没有选中项；移动端三项完整可见且不横向滚动，冲突预览使用单一 bottom sheet。当前代码默认初始化 `copy.generate`、冷态 Picker 只有文案/视频且用 `aria-pressed`，切换还会直接重置比例，均属于首轮必须替换的实现。

推荐首发的全局六项、各对口 P0/P1、首轮工具窄切片、配置对象分层和开发完成定义见 [创作入口、快捷模板与工具的后台配置方案](creation-surface-admin-configuration.md)。
