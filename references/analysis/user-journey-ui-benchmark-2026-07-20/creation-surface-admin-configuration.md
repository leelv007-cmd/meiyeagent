# 创作入口、快捷模板与工具的后台配置方案（2026-07-20）

## 1. 已确认方向

`文案 | 图文 | 视频` 三个创作对口、首页快捷模板和工具推荐都按**首发设计默认值**进入开发，不再视为永久写死的信息架构。后续运营可以在后台完成排序、替换、上下架和回滚，不需要每次修改前端代码。

但“可配置”只作用于前台编排，不等于允许运营人员任意改写底层执行合同：

- `copy.generate | image.generate | video.generate`、模型目录、报价和三类成品工作区是稳定执行合同；当前 `文案 | 图文 | 视频` 是首个已发布的创作对口组合。正常配置发布不能创造第四种 operation，也不能把“图文”静默改成视频执行。
- 快捷模板引用版本化 `CreationRecipeVersion`，后台只选择已经通过校验并可发布的 recipe revision，不直接向浏览器下发或现场编辑隐藏系统 prompt。
- 创作工具继续使用 D-077 的 `composer_recipe | standalone_tool` 两种入口，并落到现有 Task、Work、Job、Asset、ContentPackage 和 RouteSnapshot。
- 浏览、预览、排序和套用都不得创建业务对象；只有用户明确“开始创作”或在独立工具内明确提交后才写入。

## 2. 推荐首发组合

### 2.1 首发三个创作对口

首发顺序保持：

1. **文案**：朋友圈、活动促销、项目科普、门店/技师介绍等以文字交付为主的任务。
2. **图文**：小红书笔记、纯图片、海报、套图和科普卡片；精确交付物仍由模板或可改 chip 表达。
3. **视频**：抖音项目成片、图文转口播、活动预热和其他短视频任务。

冷态三个对口等权展示且均不预选。用户可以先输入文字或添加来源，但提交前必须主动选择一个对口；输入内容、素材类型、模板、后台默认和系统判断都不得替用户选中或切换对口。首发不增加第四个“智能匹配”入口，也不保留隐藏的自动推断状态。

用户选中后，本次草稿记录 `source: user_explicit`，再加载该对口对应的模板、模型、参数、工具、报价和结果工作区。模型、比例等专业参数仍可在**已选对口内部**使用 Auto 默认，但 Auto 不能反向改变创作对口。提交时冻结选择；已提交任务需要改变对口时，必须基于当前内容创建派生草稿，不能原地改写执行合同。

后台后续可以发布 2～4 个用户可见对口，例如在有真实需求时把“图文”拆成“图文笔记 / 图片设计”；但所有对口合计必须继续清晰覆盖文本、图片和视频三类首轮能力，且只能引用既有 operation 与结果工作区。调整的是入口编组，不是新增一套执行引擎。

### 2.2 首页全局六个快捷模板

在尚未选择对口时，可以浏览以下跨模态精选，但卡片不得静默决定对口。动作必须明确写成“选择图文并套用”“选择视频并套用”等；确认后把对口选择与 Recipe patch 作为一个可撤销的原子变更：

| 顺序 | 快捷模板 | 主要对口 | 首发理由 |
| --- | --- | --- | --- |
| 1 | 从案例图写小红书 | 图文 | 最贴合美业现有案例素材，可直接形成可发布 ContentPackage |
| 2 | 朋友圈项目介绍 | 文案 | 输入成本最低，覆盖高频私域沟通 |
| 3 | 项目 / 活动套图 | 图文 | 明确展示多图与批量视觉能力 |
| 4 | 促销海报 | 图文 | 目标、事实和成品边界清晰，适合紧急活动 |
| 5 | 抖音项目成片 | 视频 | 保证视频在首轮一级可发现，并明确是项目成品而非泛视频生成 |
| 6 | 旧内容换平台 | 跨对口 | 连接 Recent 与 ContentPackage，形成内容复用闭环 |

D-082 暂定“六张用户可见卡片、八个具体 Recipe variant”：前五张卡片各引用一个单对口 Recipe revision；“旧内容换平台”在 Surface 中保存为一组有序 revision 引用，分别对应文案、图文、视频。它不是新的运行时对象，也不允许自动解析；冷态点击后必须由用户主动选择对口，再加载对应 variant。该首发映射后续可通过新 Surface / Recipe revision 调整。

D-083 进一步暂定首发卡片文案与动作：普通卡片的标题、副文案和预览素材来自 Recipe presentation，Surface 只承接 revision 引用、顺序、精选和上下架；`选择文案/图文/视频并套用`、跨对口差异确认和不可用原因根据真实合同生成，不能由运营人员自由填写。无受保护字段冲突时一击套用，只有同对口手改冲突或跨对口切换才增加确认；完整文案与状态矩阵见 `creation-template-card-copy-interaction-proposal.md`。

D-084 将移动首屏投影与运营编排分开：后台可发新 Surface/Recipe/Tool revision 调整标题、副文案、预览、顺序、精选和上下架，并同时预览桌面/移动效果；但 320/390px 两列、冷态六卡全展示、模板/工具分区、Pro Studio 独立横条、用户显式选对口和安全动作由产品合同控制。普通发布不得把移动首屏切成横向隐藏、四卡摘要或默认选中；全屏目录容器与返回恢复合同见 `mobile-creation-cards-catalog-decision.md`。

用户主动选择对口后，不再继续展示六项混合清单，而是切换为该对口的 P0 推荐：

- **文案**：朋友圈项目介绍、活动促销文案、旧内容换平台、项目科普 / 顾客问答。
- **图文**：从案例图写小红书、项目 / 活动套图、促销海报、项目科普卡片。
- **视频**：抖音项目成片、图文转口播视频、活动预热短片。

每个对口首屏最多显示 4 项；更多模板进入“查看全部模板”。门店 / 技师介绍、前后对比案例、价目表 / 团购长图、节气热点、案例对比视频等先作为 P1 候选，避免首屏形成模板墙。这里的“高频”是当前产品范围、竞品流程和美业任务的设计判断，不冒充真实运营数据。

### 2.3 首批工具快捷入口

首页“创作工具”首轮只实现两个窄切片，达到发布门后才进入已发布推荐位：

1. **做同款**：`composer_recipe`，P0 只承接已确认 `AssetRevision` 与图文结果，把参考内容、目标交付物和风格建议以可预览 patch 带回当前 Composer；发布前必须替换当前已经退役的复用命令。
2. **预设尺寸重排与导出**：`standalone_tool`，进入聚焦处理界面并复用现有宣传物料尺寸重排能力；在智能裁剪、批量逐项重试完成前，不包装成“一键智能多平台适配”。

**Pro Studio 无限画布**虽然在底层属于 `standalone_tool: workspace`，但前台继续按 D-075 作为独立“专业工作区”横条，位于创作工具之后，不混入普通工具推荐位。桌面工具位最多 3 项、移动最多 2 项；当前可交付工具不足时留空，不用不可用能力补位。

批量去背景、字幕擦除等能力继续留在候选目录，等输入输出合同、模型可用性、费用和失败恢复达到发布门后再由后台上架，不能只因为竞品存在入口就先展示不可交付工具。后台配置的 `enabled` 只代表运营发布意图，前台最终可用性必须取以下交集：

```text
已发布入口配置 ∩ 当前能力目录 ∩ Provider live evidence ∩ 权益 ∩ 素材与权利条件
```

## 3. 后台信息架构

在既有后台管理壳的 **内容能力** 域增加“创作入口与模板”，不另建第二套后台；领域数据使用独立 **Creation Experience Catalog** 聚合：

```text
后台管理
└── 内容能力
    ├── 创作入口与模板   ← 本方案新增
    ├── 官方模板         ← 复用现有模板版本/发布能力
    └── 创作工具目录     ← 可先作为同页第二个页签
```

首版采用结构化可视编辑器，而不是让运营人员编辑 JSON：

- 桌面 / 移动预览；
- 创作对口的新增/移除、标签、副文案、排序与展示状态；运行时选择策略固定为 `user_explicit`，后台不得配置默认选中项；
- 首页精选、各对口精选、更多目录的拖动排序和替换；
- 模板与工具的可用性、来源要求、目标工作区和预计费用摘要；
- 变更差异、影响范围、发布原因和校验结果；
- `草稿 → 预览 → 校验 → 发布 → 回滚`。

拖动排序必须同时提供键盘可用的“上移 / 下移”操作。不可用或已退役的 recipe、CatalogModel、工具或目标工作区不能进入发布版本；后台应显示原因，而不是只把卡片变灰。

## 4. 配置对象分层

为避免把“模板内容”和“首页摆放”绑死在一个大 JSON 中，首版拆成四类版本化对象：

### `CreationLensDefinition`

- 稳定 `id`、用户可见标签、说明、图标和排序；
- 允许的 output intent、operation 与目标成品工作区引用；
- 选中后使用的 recipe collection、模型与参数策略引用；
- 展示状态与不可用说明。

### `CreationRecipeVersion`

- 平台、交付物和输出合同；
- 用户可见上下文 patch 与来源要求；
- 服务端 prompt revision 引用；
- model auto / fixed 策略和设置 patch；
- 报价策略、目标成品工作区、版本状态。

### `CreationSurfaceRevision`

- 2～4 个用户可见对口及其标签、顺序和固定 `selectionPolicy: user_explicit`；
- 首页最多六个精选项；每项指向一个 recipe revision，或像“旧内容换平台”一样指向按 lens 键控的 recipe collection（只保存有序 revision 引用与展示信息）；
- 每个对口最多四个精选 recipe revision；
- 首页精选工具、更多目录分类与排序；
- fallback、状态、revision、actor、reason、发布时间。

### `CreativeToolEntry`

- 复用 D-077 已确认的 entry kind、输入输出、能力、权益、报价、可用性、canonical route / recipe revision 和目标结果工作区。

`CreationSurfaceRevision` 只做展示编排，不能复制 `CreationRecipeVersion` 或 `CreativeToolEntry` 的业务字段。这样替换首页模板不会产生第二份 prompt、模型或费用真相。

Creation Experience Catalog 必须拥有独立的表与原子发布聚合。现有 admin-config 是固定 key 的单项即时应用/回滚，现有 OfficialTemplate version body 又固定承载 CanvasDocument；二者都不能直接充当 Surface/Recipe/Tool 存储。这里只复用 admin-config 的 append-only、CAS、actor/reason/audit 基础设施和 OfficialTemplate 的 preview/publish/retire 生命周期模式，**不写入现有 `admin_config_revisions` 或 `p1_template_versions`**。

## 5. 发布与运行合同

- 首版只发布**平台全局**配置；工作区 / 套餐 / 地区差异等覆盖等真实商业需求出现后再增加，避免当前就形成难以解释的层层继承。
- 独立 Catalog 的发布实现复用现有 admin-config 的 append-only revision、CAS、actor、reason、history 和 rollback 基础设施模式，以及官方模板已经存在的版本、预览、发布和退役生命周期；一次 Surface 及其引用关系必须原子校验、原子发布，不能逐项即时生效。
- 每次 Composer 会话读取一个已发布 `CreationSurfaceRevision`，初始 `lensId` 必须为空；用户显式选择后冻结当前 lens revision，首次套用模板时同时冻结 `recipeRevision`。后台随后发布的新版本只影响新草稿，不得选中、切换或改写用户正在编辑、已报价或已提交的任务。
- 普通发布必须保证文本、图片和视频三类首轮能力仍有清晰入口。若供应故障需要临时关闭某类执行，只能走高影响应急开关，显示原因和恢复状态，并留下独立审计记录。
- 发布前校验：创作对口为 2～4 项、没有默认选中项、选择策略只能是 `user_explicit`，并合计覆盖文本/图片/视频；首页精选不超过 6 项、对口精选不超过 4 项、无重复；所有引用已发布且可用，固定模型可以报价，目标结果工作区存在。
- 暂不把运营指标看板纳入本次开发范围；但 exposure、select、apply、start、complete、correct、cancel 事件必须携带 surface / recipe / tool revision，便于后续用真实数据调整组合。

## 6. 首轮开发完成定义

1. 后端建立独立 Creation Experience Catalog，提供四类对象的查询、草稿、校验、原子发布、历史和回滚合同，并迁移当前三个对口、六个模板、两个普通工具和 Pro Studio 专业工作区为首个 Surface revision；普通工具只有通过运行可用性交集后才激活。
2. 后台提供结构化编排、桌面 / 移动预览、差异确认和审计原因，不以原始 JSON 编辑器作为正式交付。
3. 前台只消费已发布配置；配置服务暂时不可用时使用最后一个成功发布版本，不能退回散落在组件内的多份硬编码清单。
4. Composer 冷态不预选对口；选择、切换和模板联动均来自用户显式动作，并在 Task 提交时冻结 lens、surface、recipe、model、quote 和 route revisions。会话中途发布新配置不会选择或改变当前草稿和提交结果。
5. 自动化覆盖“输入或上传不触发选择”、排序、上下架、非法默认值、并发发布冲突、回滚、三模态可发现、零写入浏览、切换冲突/撤销、移动返回恢复和键盘操作。

这套边界允许先按推荐组合完成开发，再按真实运营需要频繁调整前台陈列，同时保护底层模型路由、费用、任务、资产和结果工作区不被运营配置破坏。
