# CreatOK 登录态增量 UX 审计

- 审计日期：2026-07-20
- 对象：[CreatOK 登录态应用](https://www.creatok.ai/app/dashboard)
- 方式：OpenCLI Browser Bridge `v1.8.6`，独立会话 `creatok-0720`
- 重点：Dashboard、Agent、图片生成、视频生成、示例/向导、模型与规格、价格提示、历史与资产复用
- 安全边界：只读；未上传素材、未输入 Prompt、未提交生成、未发布、未消耗积分、未修改账户或工作区设置

## 结论先行

CreatOK 仍然最适合参考的是一条连续的媒体创作语法：

> 结果/场景示例 → 参考素材与 Prompt → 模型/规格/数量 → 提交前成本 → 异步任务 → 工具历史 → 全局资产 → 二次创作或发布

它当前最成熟的部分是：创作入口靠前、图片与视频共用相似 Composer、示例承担冷启动、模型与规格显式、费用在提交前可见、图片历史支持筛选和批量操作。最不应照搬的是：电商领域语言、重复工具分发、模型选择过密、图片/视频历史能力不一致、空态缺少就地行动、固定 Composer 遮挡内容，以及仍存在的语义与无障碍风险。

本轮有两个重要增量：

1. 2026-07-11 的 Dashboard 与视频生成器默认是 `Veo 3.1 Fast（体验）`，基线截图显示预计 `5` 积分；2026-07-20 当前默认变为 `Seedance 2`，同一 `720P · 9:16 · 8s · 1 条`组合显示预计 `44` 积分。原因未验证，不能断言是永久默认或全量配置，但它证明“默认模型 + 默认价格”是会变化的运行时配置，不应写死在我方 UI。
2. 图片生成维持 `Nano Banana 2 · 2K · Auto · 1 张 · 1 积分`，且历史页已有模型、分辨率、比例、下载状态、时间和 Prompt 搜索；视频历史空态则没有同等级筛选和行动，跨模态历史体验仍不一致。

## 步骤健康度

| 步骤 | 当前健康度 | LIVE-0720 事实 | 对我方的含义 |
|---|---|---|---|
| Dashboard → 开始创作 | 良好 | 视频/图片/分析三模式在首屏；参考、首尾帧、编辑、Prompt、模型、规格、数量、预设、优化/向导和预计积分集中在一个 Composer | 首页应直接承接高频创作，但不能同时复制工具卡、侧栏菜单、生成器顶部菜单的三重入口 |

| 视频示例 → Composer | 部分良好 | 示例先于历史；当前可见产品展示、生活方式、穿搭分享、UGC 种草、好物推荐、科技发布等场景；Composer 始终停靠 | 场景卡适合冷启动，但点击后的继承字段、来源标识和可编辑性本轮未验证 |
| 图片示例 → Composer | 良好 | 当前可见白底图、产品精修、场景图、模特、试穿、主图、生活化场景、细节、卖点、A+ 等至少 12 类示例 | 参考“结果角色”而非电商名称；在美业中改为项目/客群/渠道/内容结果 |
| 模型/规格/成本 | 良好但过密 | 视频模型分体验/标准两组，共 16 个当前选项；图片当前 7 个选项；提交按钮前显示动态积分 | 专家透明度值得保留；新手第一层应按结果与能力选择，完整模型目录渐进展开 |
| 视频历史与恢复 | 较弱 | 当前为空，只显示“暂无视频生成记录”；Composer 仍在；没有空态 CTA 或本轮可见筛选 | 不能按媒体各做一套历史；统一任务收件箱必须承接 queued/running/failed/resume |
| 图片历史与管理 | 部分良好 | 即使为空仍显示模型、分辨率、比例、下载状态、时间、Prompt 搜索、布局与批量操作 | 筛选维度值得参考，但空态不应先展示一整排无效筛选，应提供“去创作/从任务继续” |
| 结果操作 | 未验证 | 当前账户没有可见生成记录；未提交任务 | 下载、编辑、变体、做同款、失败恢复、扣费反馈和部分成功不能由入口推断 |
| 全局资产复用 | 部分良好 | AI 生成、上传资产、数字人、商品库、回收站五类；有容量、筛选、批量、生成图片/视频入口 | 保留“工作历史 → Product Asset”的分层；领域分类需改写，中心空态需要明显 CTA |

## 关键页面观察

### 1. Dashboard：入口快，但默认选择变化可能制造价格惊讶

`LIVE-0720`：Dashboard 仍以单一大 Composer 承接视频、图片和分析；下方再分发图片生成、爆款复刻、提示词反推、去字幕、商品套图、A+、详情长图等工具。

当前视频默认是：

```text
Seedance 2
720P · 9:16 · 8s
生成 1 条
预计 44 积分
```

`BASELINE-0711` 同位置是 `Veo 3.1 Fast（体验）`、预计 `5` 积分。当前快捷卡编排也与基线不同，例如当前出现“详情长图”“TikTok 脚本提取”“图片复刻”，而旧截图对应位置出现“换装试穿”“多角度”“视频翻译”。这些变化可能来自配置、轮换或实验，本轮未验证原因。

对我方最重要的不是复制数字，而是建立以下守卫：

- 恢复用户上次明确选择，不因后台默认更新静默换模型；
- 默认变化时明确展示“本次使用模型”和新旧费用差异；
- 规格变化、数量变化或报价刷新后实时重算；
- 价格仅来自 Catalog/Deployment/Ledger 正式事实源，不从页面常量推导。

证据：[Dashboard 当前截图](screenshots/creatok/01-dashboard-desktop.png)

### 2. Agent：任务入口清楚，但仍是一个平行的品牌首页

`LIVE-0720`：Agent 提供附件、技能、历史和结果型快捷项，能把“我要做什么”转成更具体的任务；发送按钮在空输入下不可执行。它的问题是首屏仍以大口号和装饰图为中心，核心创作上下文与 Dashboard/生成器分离。

我方应把 Agent 作为 Composer 内的“帮我整理需求/补 Prompt/分析素材/形成分镜”能力，使输出直接写入当前任务字段，而不是再造一套会话、历史和结果系统。

证据：[Agent 当前截图](screenshots/creatok/02-agent-desktop.png)

### 3. 视频生成：场景发现和参数透明优秀，认知负担也最大

`LIVE-0720`：默认仍是“示例”，不是历史；固定 Composer 让用户浏览场景时随时可输入。视频模型当前包含：

- 体验：Veo 3.1 Lite、Veo 3.1 Fast、Gemini Omni Flash、Grok Imagine；
- 标准：Seedance 2/2 Fast/2 Mini/1.5 Pro、Happy Horse 1.1、Sora 2、Kling 3/3 Omni、Veo 3.1 Fast/Quality、Wan 2.7、Grok Imagine。

选项同时可能显示模型说明、支持人脸、最低积分、优惠/New/Hot 标签和部分成功率。透明度高，但“先选厂商/版本”会把新手的业务任务变成模型采购题。

适配建议：第一层提供“快速草稿 / 高质量成片 / 多参考一致性 / 低成本批量”等能力方案；用户明确选定具体 CatalogModel 后不得跨品牌静默替换。完整目录、成本与供应健康度进入专家层。

证据：

- [视频示例与固定 Composer](screenshots/creatok/03-video-generator-examples.png)
- [视频模型、能力与价格弹层](screenshots/creatok/05-video-model-selector.png)
- [视频历史空态](screenshots/creatok/04-video-history-empty.png)

### 4. 图片生成：结果角色比空 Prompt 更适合美业迁移

`LIVE-0720`：图片页保持“示例/历史 + 固定 Composer”结构；当前默认 `Nano Banana 2 · 2K · Auto · 1 张`，预计 `1` 积分。当前模型目录为 GPT Image 2、Nano Banana 2/2 Lite/Pro、Seedream 5.0 Pro/5.0 Lite/4.5。

图片示例直接表达输出角色，这一点比模型列表更值得迁移。美业适配可改为：

- 项目主视觉、疗程步骤、前后对比、顾客案例封面；
- 小红书首图、九宫格、知识卡、活动海报；
- 门店环境、技师形象、产品/仪器展示；
- 视频首帧、尾帧、分镜参考和封面。

点击示例后的实际预填字段、是否保留来源、能否逐项修改，本轮没有点击验证，不宣称已经形成完整“做同款”闭环。

证据：

- [图片模型选择器](screenshots/creatok/07-image-model-selector.png)
- [图片历史筛选与空态](screenshots/creatok/08-image-history-filters.png)

### 5. 历史与资产：对象方向正确，但跨模态不一致

`LIVE-0720`：图片历史把检索、筛选、布局和批量操作放在工具上下文内；资产库再负责跨工具沉淀。这说明“工具历史”和“全局资产”是两个不同对象，方向正确。

当前不足：

- 视频历史空态没有同等级筛选与下一步；
- 图片历史为空时仍先展示整排筛选，中心没有行动；
- 资产库中心只说明“开始创作”，生成图片/视频动作位于顶部图标区，发现性较弱；
- 当前没有真实结果，无法核对来源、版本、费用、失败、变体和发布动作。

我方应固定三层对象：

```text
当前任务工作历史
  → 跨工具统一任务收件箱
  → 可复用 Product Asset
```

任务收件箱负责进度、失败、恢复和取消；Asset 只承接已落库且可复用的产物，不把 provider 临时 URL 或历史卡当作第二份事实。

证据：[资产库当前空态与操作区](screenshots/creatok/09-assets-empty-actions.png)

## 对我方可直接采用、需改写和应拒绝的模式

### 可直接采用的交互骨架

1. 图片/视频使用相同 Composer 语法，减少跨模态重新学习。
2. 示例与历史并列：一个解决冷启动，一个保证连续工作。
3. 参考素材、Prompt、模型、规格、数量和成本在提交前形成完整合同。
4. 复杂模式用结构化槽位表达：参考图/视频、首尾帧、编辑，而不是只给一个大 Prompt。
5. 工具历史与全局资产分责。
6. 价格在最终 CTA 上直接可见，并随模型、规格和数量变化。

### 必须按美业和当前 Product Core 改写

1. 第一层从“厂商模型”改为“内容结果/任务场景”，专家层才展开具体 CatalogModel。
2. 示例从电商商品角色改为门店项目、客群、渠道、图文笔记、视频脚本和营销目标。
3. “做同款”改为“以此结构创作”，明确继承的素材、结构、Prompt、规格和来源。
4. 图片、视频、图文笔记共用任务收件箱、恢复语法和资产回流；不同工具只保留上下文历史。
5. Agent 的分析、补问、改写和分镜直接写入当前工作台，不形成第二套结果域。
6. 模型默认和报价由后台控制面发布，但用户已选模型必须保持语义稳定。

### 应拒绝

1. 视频/图片各 10 余工具、Dashboard 快捷卡和生成器顶部菜单的重复分发。
2. 把 16 个视频模型、规格、积分和成功率同时放在新手第一层。
3. 图片历史和视频历史各自演化、缺少统一任务恢复。
4. 固定 Composer 无安全区地遮挡示例和移动操作。
5. 空态只有说明或无效筛选，没有“继续上次任务/开始创作/导入素材”。
6. 复制黑橙视觉、电商术语、媒体、Prompt 或闭源实现。

## 可访问性与可用性风险

### High

1. Agent、视频生成、图片生成和资产库的本轮 DOM 快照均未发现语义 H1；Dashboard 有 H1。页面层级在路由间不一致。
2. 当前中文资产页的 `html lang` 仍为 `en`，与 `BASELINE-0711` 的问题一致，会影响读屏语言选择。
3. 图片/视频 Composer 的空输入提交控件是无文字图标按钮，在 OpenCLI DOM 快照中没有可访问名称；需要真实 AX/VoiceOver 复核并补 `aria-label`。
4. 固定底部 Composer 在 1280×723 下遮挡示例/结果区；移动和低高度窗口风险更高。

### Medium

1. 视频模型列表的 DOM 快照显示 `role=option`，但 OpenCLI DOM 树未输出选项名称；页面 `innerText` 存在完整名称。是否能被 VoiceOver 正确命名仍需 AX/人工复核，不能直接宣称已通过。
2. Agent 的主输入为 `contenteditable`，本轮 DOM 快照没有明确可访问名称；视觉 placeholder 不能替代稳定 label。
3. 资产库生成图片/视频主要表现为顶部图标按钮，中心空态没有同等明显的 CTA。
4. 灰色说明文字与暗色背景的实际对比度未测，不能宣称 WCAG 失败，但应列入视觉验收。

## 证据限制

1. 本轮没有提交真实图片或视频生成，所以 `pending/queued/running/completed/failed/cancelled/resume` 的当前 UI、扣费/退款、离页恢复、通知和结果操作仍是 `LIMIT`。
2. 当前账户没有生成历史，因此无法验证下载、编辑、变体、做同款、批量、来源追踪或资产双落点。
3. 视频示例缩略媒体在独立 OpenCLI 会话等待后仍呈暗色占位；图片示例在打开模型选择器后加载。旧 2026-07-11 视频截图也有类似占位，可能涉及 lazy loading、自动播放、扩展或网络环境。本报告只引用可见的场景名称，不把占位断言为素材下线、加载失败率或性能问题。
4. 没有点击优化、向导、示例卡或发布入口，以避免潜在远端调用或账户副作用；相关交接只保留既有基线，未作当前成功声明。
5. 页面显示的积分、成功率、模型描述和默认值仅是 2026-07-20 当前 UI 证据，不是我方价格、供应商质量或 SLA 的来源。

## 本轮可带入总方案的结论

CreatOK 应继续作为图片/视频创作流程的高权重参照，但参考权重应落在**场景冷启动、统一 Composer、显式模型/规格、提交前成本、工具历史与资产分层**，而不是它的导航规模、模型密度或品牌视觉。

对当前项目最关键的产品守卫是：**场景优先、模型显式但渐进、默认变化不改写用户选择、图片/视频/图文共用任务恢复、结果进入唯一 Product Asset、Agent 只增强当前工作上下文。**
