# 当前产品用户旅程真相（2026-07-20）

> 快照：`main` @ `a5c8e5b`
> 范围：当前 Web/Core 代码、现行设计决定、最新实现总账、E2E 合同。
> 方法：只读审计；本轮没有调用真实模型、提交生成、发布、购买或授权动作，也没有把历史路线图当作当前实现。

## 1. 结论先行

当前产品并不是“能力没做出来”，而是**能力已经较深，用户旅程仍没有收成一个产品**：

1. 桌面端图文创作主链最完整：冷态一句话/素材 → 自动 Brief → Harness 流式主推荐 → 采用 → ContentPackage → 平台变体、修改、导出与复用，已经是可识别的端到端产品链。
2. 前台一级入口只有“图文”和“视频”，实际底层却有文案、图片、视频三类生成能力。`image.generate` 只能从已有 Work 的高级“复用/工具”区域进入，**冷态没有独立图片生成主入口**。
3. 视频的持久化、恢复、分镜、逐镜候选、合成和最终 MP4 都已实现，但当前路径是“显式报价 → 编辑四镜 → 锁定 → 再确认生成 → 可能逐镜选择 → 合成”，能力完整，体验仍偏工作流控制台。
4. 生成反馈已经有三套：Harness 文案 token 流、通用图片 Job 状态、视频五阶段工作流；另有跨页面异步任务中心。但它们的状态语言、结果动作和返回位置尚未统一，任务中心也只收图片/视频，不收文案 Harness。
5. 结果后的“采用、改写、做同款、版本、平台变体、发布/导出、结果信号”都存在，但散落在工作台结果区、ContentPackage 详情、素材库和高级复用区。能力密度高，连续感弱。
6. 移动端不是简单缩放，而是独立的 Action / Progress / Handoff 行动簿，拍摄、上传恢复、候选选择、文本小改、发布交接和桌面接力都有实现；但**手机新建图文只创建 Work，没有像桌面端一样创建 ContentPackage 并提交 Harness**，这是当前代码可直接证明的 P0 断点。
7. 讯飞绘文式的“图文笔记/长内容编辑工作区”目前不存在。现有文本编辑是 ContentPackage 的标题、正文、Hook、话题字段与快捷修改，不是大纲—段落—配图—预览一体的文档编辑器。

这与 D-072 的判断一致：当前缺项不只是视觉样式，而是文本、图片、视频在入口、等待、交付、修改与复用上的统一问题（`docs/design/beauty-marketing-agent-product-design-2026-07-17.md:1254-1264`）。

## 2. 判定口径

- **已实现**：当前生产代码存在完整用户动作、权威对象写入/恢复路径，且有对应测试合同或最新总账闭环证据。
- **部分实现**：能力存在，但入口不可发现、跨端不一致、结果交付不完整、仍依赖另一个页面完成，或关键验收合同缺失。
- **缺失**：当前商家前台没有可完成该目标的入口或交互承载，不以底层 API、证明页或历史设计稿代替。

设计边界仍以现行决定为准：Day-0 与 Day-N 同界面（D-029）、主流程不回退到多字段启动表单（D-031）、首次默认主推荐而非强制三选一（D-023）、无冲突路径首 token 前不超过两次激活（D-043）、结果阶段保留自由文本调整口（D-046）。证据分别见设计文档 `:620-629`、`:691-702`、`:717-728`、`:874-884`、`:907-915`。

## 4. 三条当前实际主流程

### 4.1 图文 / 小红书文案（桌面）

`冷态工作台` → 选场景或输入一句话/上传素材 → `开始创作` → 创建 Work + 自动确认 Brief → 创建 image_text ContentPackage → 提交 Harness → token 流主推荐（备选折叠）→ 采用 → ContentPackage 详情 → 快捷修改/平台变体/视觉排序 → 导出或批准/辅助发布 → 结果记录与复用。

这是当前最接近“完整产品”的链路。优势是首 token 前已经压到 ≤2 次用户激活，素材授权也在上传当下内联处理；弱点是结果后的编辑语义被拆成“工作台调整方向”和“内容页快捷修改”两套入口，且长图文仍是字段表单而非文档式创作。

### 4.2 独立图片生成（桌面）

`先存在一个 Work` → 展开高级区 → 复用/工具 Shelf → 选择图片工具（选择本身不执行）→ 回到执行区选择/沿用模型和参数 → 显式提交 → Job 状态/恢复 → 图片媒体结果 → 保存为素材 → 可选回装来源 ContentPackage。

底层链条完整，但不是冷态一级旅程。用户若从“我要生成一张图”开始，当前首屏没有与图文、视频并列的入口；生成结束也没有“下载、分享、继续编辑、生成同款”同屏动作簇，只能预览、看详情、回装内容或再去素材库。

### 4.3 视频生成

`冷态工作台选择视频` → 一句话/素材 → 创建 Work → 模型/报价/合规合同 → 大额显式确认 → 四镜分镜编辑 → 锁定分镜 → 再次确认并生成 → 后台五阶段（可离开）→ 可能逐镜二选一 → 合成 MP4 → 播放 → 内容库/交接。

视频的状态真实性和恢复能力比一般原型深，但交互把“高级可控性”设成了所有用户的必经路径。下一轮应讨论的是哪些节点默认自动、哪些按需展开，而不是删除 ApprovalReceipt、恢复、接受态或审计这些已经正确的底层约束。

## 5. P0：下一轮必须先解决的旅程断点

### P0-1 手机新建图文没有启动生成

移动端 `createWork` 只调用 `create_creative_work`，成功后只保存 Work、刷新投影（`mobile-action-book.tsx:1397-1413`）。它没有桌面端的 `create_content_package` + `submitHarnessTask`（桌面实现见 `unified-creation-workbench.tsx:1620-1684,1824-1831`），Core 的 `create_creative_work` dispatcher 也只是建 Work，不会隐式启动 Harness（`apps/core/src/p1/operations/foundation-module.ts:744-763`）。

因此手机新建 copy Work 后，当前代码没有新 Job、ContentPackage 或 Harness 结果可进入 Progress；移动端只能展示此前已由其他端生成的候选/包。应先修成与桌面共享同一“创建并启动 Task”命令或共享 orchestration seam，再讨论视觉优化。

### P0-2 图片生成没有冷态一级入口

首屏与 Work 内 composer 都把模式限制为 copy/video（`creation-entry.tsx:184-230`；`unified-creation-workbench.tsx:3496-3512`），图片只存在于高级 Shelf。这个缺口让“三模态能力首轮完整”在商家旅程上表现成“两类产品入口 + 一个隐藏工具”。

下一轮必须拍板：三种内容是否共用一个 Composer 壳、以“图文 / 图片 / 视频”三种结果意图并列，还是图片作为图文任务内的生成动作；无论选择哪种，不能继续保留“底层一等能力、前台二等入口”。

### P0-3 图片/视频结果缺少完成任务所需的直接动作

当前 CanonicalMediaGallery 提供媒体预览、lightbox、失败重试和详情链接（`canonical-media-gallery.tsx:74-208,210-313`）；工作台图片结果提供保存素材/回装内容（`unified-creation-workbench.tsx:3216-3302`）；视频最终结果提供播放器和“去内容库”（`video-workflow-panel.tsx:692-711`）。三处都没有直接下载、系统分享、复制链接、继续编辑/同款的统一动作簇。

对于以图片或视频为终点的用户，这不是装饰性 polish，而是交付未收口。PWA proof 的 Web Share/下载测试不能替代生产页面动作。

## 6. P1：紧随其后的结构性体验缺口

1. **统一跨模态生成壳与状态词汇**：现在文案、图片、视频各有一套进度容器；应统一“已提交—排队—生成—需要你处理—完成—可恢复—失败”的顶层语义，再保留各模态专有细节。异步任务中心也应明确文案短任务是否纳入，而不是由实现偶然决定。
2. **视频默认路径瘦身**：保留一次大额确认，但默认自动生成并锁定分镜；用户主动展开时才进入四镜编辑。当前“编辑并锁定 + 确认生成”是两个连续必经动作（`video-workflow-panel.tsx:430-477,607-640`）。
3. **图文长内容编辑器**：当前只有字段式 ContentPackage 编辑。若重点对标讯飞绘文，应补“标题/大纲—段落正文—配图槽—平台预览—局部重写”的编辑工作区，并把保存结果仍落为 ContentPackage revision；不能新建第二套内容真相。
4. **结果页与内容页职责切分**：工作台负责“本次结果、快速方向调整、采用”；内容页负责“精修、平台化、发布”；历史、用量、结果信号、血缘应折叠或分区。当前详情单页同时承载编辑、发布、历史、账本、结果、血缘，认知负载过高。
5. **移动端补素材与结果调整**：底栏没有素材入口，手机结果阶段也没有 D-046 的自由文本“调整方向”；精细布局只能转桌面。应先保证图片/视频结果的下载分享、图文结果的小改和素材选择可在手机完成，再把精排留给桌面。
6. **默认主推荐补完整验收**：实现已有 Harness `recommendedCandidateId` 和备选折叠，但 E2E 明确标记推荐 trace 合同缺失。应补生产形状回归，避免 legacy A/B/C 或“数组第一项”被误标为推荐。
7. **额度耗尽就地恢复**：Day-0/Composer 有额度阻塞和去设置页链接，但实现总账仍记录“阻塞卡无就地输入兑换码”为 P2 UX open（`docs/reviews/implementation-gap-ledger-2026-07-19.md:218-223`）。这会在最关键的开始生成节点打断旅程。

## 7. 不应误判为缺项的已实现能力

- Day-0 不是独立 onboarding；同一工作台冷/热态切换已经实现。
- 素材上传、事实确认、授权证据、删除当前引用但保留素材库已经实现，不需要再造上传中心。
- ContentPackage 单一采用事实、平台变体、版本回滚/比较、派生血缘和做同款已经实现。
- 图片 Job 与视频 workflow 的跨页面恢复、失败恢复和异步通知已经有产品骨架。
- 视频的持久工作流、取消、质量复核和最终 MP4 不是“待开发原型”；下一轮重点是默认路径和信息层级。
- 自动发布不能按按钮存在就概括为全平台可用；产品已按 automatic_verified / assisted 诚实分级，这是正确边界。

## 8. 证据边界与发布状态

1. Recorded-provider E2E 走真实 App Shell/Core adapter，但明确不使用外部模型凭据（`tests/e2e/TEST-CATALOG.md:120-129`）；它能证明对象、状态和恢复合同，不能证明生成质量、真实成本与排队时延。
2. 视频工作流 E2E 证明持久化、恢复、取消、候选和最终 MP4 的产品合同（`TEST-CATALOG.md:294-304`），但托管环境 Last-Event-ID 重连和真实视频运营六题仍未闭（`docs/reviews/implementation-gap-ledger-2026-07-19.md:88-98,147-148`）。
3. 最新总账明确当前仍不可宣称“可试点 / 可面世 / 宣发闭环 ≥1”（`implementation-gap-ledger-2026-07-19.md:212-228`）。本报告的“已实现”只表示当前代码产品能力已存在，不等于外部发布批准。

## 9. 供下一轮讨论直接使用的拍板顺序

1. 先拍“图文 / 图片 / 视频”入口关系与共享 Composer 壳。
2. 同时修复手机 copy 启动断点，不让错误实现污染新 UI 方案。
3. 拍统一生成中状态与跨模态结果动作合同，至少含返回、下载/分享、继续调整、保存素材/内容、做同款。
4. 再分别收敛三条模态路径：图文进入长内容编辑器，图片进入视觉结果台，视频默认自动分镜、按需展开专业控制。
5. 最后重排内容库、素材库、移动端与发布交接，使同一个 ContentPackage/Asset 真相贯穿而不新增第二业务对象。
