# 小云雀创作工具入口补充走查（2026-07-20）

## 1. 范围与行为边界

- 目标：验证“小云雀式创作工具入口”不是一套单一跳转，而是如何分别承接 Composer 模板、聚焦工具和专业工作区。
- 通道：Codex 内置浏览器，复用用户当前登录态；页面为 `https://xyq.jianying.com/home?from_page=xiaoyunque_landing_page&tab_name=home&agent_tab=creative`。
- 实际操作：打开“全部创作工具”，依次检查“爆款复刻”“图片多尺寸延展”“自由画布”，随后返回首页。
- 未做：未输入提示词、未上传素材、未点击生成、未付费、未发布、未导出。
- 例外事实：点击“自由画布”会立即进入带新 `projectId/canvasId/thread_id` 的空画布，并在左侧历史新增一个“未命名项目”。本次未继续编辑，也未擅自删除该空项目。这个副作用只作为竞品交互证据，不建议照搬。

## 2. 工具目录本身

“查看全部”打开一层大尺寸工具目录弹窗，而不是把完整工具墙长期平铺在首页。当前可见筛选为：

1. 全部；
2. 沉浸式短片；
3. 生成图片；
4. 产品推广；
5. 智能长视频 2.0。

每个入口使用“缩略图 + 名称 + 一句能力说明”，目录中混合了三种实际承接方式。这个“一个目录、不同交付方式”的结构值得借鉴；分类名称本身偏 AIGC 技术与平台营销语言，不适合直接复制到美业商家产品。

## 3. 三条实际操作证据

### 3.1 “爆款复刻”：原位改写 Composer 的配方型入口

点击后 URL 不变，首页 Composer 原位切换为“沉浸式短片”，并同步改变：

- 说明语：解析参考视频的爆点原因并借鉴在视频中；
- 默认模型：`2.0 Mini 体验版`；
- 可见设置：比例、10 秒、全能参考、更多设置；
- 计价：`4/秒`；
- 推荐词：切换为宣传片、电影风、猫狗剧情、漫剧等视频上下文。

它不是一个独立工具页，本质是把“意图上下文 + 模型 + 设置 + 推荐词”一次性装载进同一个 Composer。对我方应抽象为版本化 `CreationRecipeVersion`，前台仍叫“快捷模板”。

![爆款复刻原位切换 Composer](screenshots/xiaoyunque/15-tool-inline-breakout-clone-2026-07-20.png)

### 3.2 “图片多尺寸延展”：聚焦弹层型独立工具

点击后不替换当前 Composer，而是打开聚焦弹层。弹层只保留完成该任务所需的局部输入：

- 必填 1 张图片；
- 2:1、16:9、4:3、1:1、3:4、9:16、1:2 等目标尺寸；
- 自定义尺寸；
- “编辑提示词”和“生成”动作。

这是适合有稳定输入输出合同、步骤短且无需完整编辑工作区的独立工具形态。我方可用于“多平台尺寸适配、批量去背景、字幕擦除、首尾帧生视频”等窄能力，但仍要复用统一素材、任务、报价和结果对象。

![图片多尺寸延展聚焦弹层](screenshots/xiaoyunque/16-tool-modal-multi-size-2026-07-20.png)

### 3.3 “自由画布”：路由级专业工作区入口

点击后进入独立 `/project` 工作区，画面包含：

- 空白无限画布；
- 视频、图片、文本、音频四类快速节点；
- 项目资产与画布工具栏；
- 右侧独立 Agent 会话与素材入口；
- 自动保存状态。

它不是普通模板或局部弹层，而是另一种专业操作空间。这个承接方式与我方现有 Pro Studio 边界一致：首屏只负责发现和带上下文进入，工作区继续走 canonical `/pro-studio` entitlement/SSO gate，产物通过 adoption 回到唯一 ContentPackage 真相。

![自由画布独立工作区](screenshots/xiaoyunque/17-tool-workspace-free-canvas-2026-07-20.png)

## 4. 对我方的正式抽象

前台统一叫“创作工具”，底层只保留两类入口：

| 入口类型 | 用户体验 | 适用对象 | 写入边界 |
| --- | --- | --- | --- |
| `composer_recipe` | 在当前 Composer 内预览并套用模板 | 做同款、节点营销、旧内容换平台、项目/活动套图 | 套用前只改草稿；用户确认开始后才创建 canonical 任务链 |
| `standalone_tool` | 打开聚焦弹层、独立页面或专业工作区 | 多尺寸适配、批量去背景、字幕擦除、Pro Studio | 浏览和打开入口不应自动创建 Work/Task；在工具内明确提交后才写入，Pro Studio 走既有 gate |

`standalone_tool` 的呈现可以是 `dialog`、`route` 或 `workspace`，但这只是 UI 容器差异，不新增第三套任务、历史、素材或结果真相。

首页不长期展示完整目录，只保留当前上下文最相关的少量“工具组合”与一个“查看全部”。完整目录按商家任务和交付结果组织，并由可用能力、套餐权益、素材类型和当前创作对口动态过滤。

## 5. 首批值得保留的参考映射

| 小云雀参考 | 我方候选 | 建议入口 |
| --- | --- | --- |
| 爆款复刻 | 做同款 / 从案例提取结构后重写 | `composer_recipe` |
| 节点营销 | 节日活动图文套组 | `composer_recipe` |
| 图片多尺寸延展 | 多平台尺寸适配 | `standalone_tool: dialog` |
| 一键批量去背景 | 批量商品/案例图去背景 | `standalone_tool: dialog` |
| 字幕擦除 | 视频清洁与字幕修复 | `standalone_tool: route` |
| 品牌 VI 手册制作 | 门店视觉规范提取 | 后续 `standalone_tool: route`，先验证真实需求 |
| 自由画布 | Pro Studio 无限画布 | `standalone_tool: workspace` |

这张表是能力形态参考，不是首轮开发清单。首页当前仍以已确认的六个快捷模板和 Pro Studio 为基线，新增工具必须经过真实需求、模型可用性、成本、权益与结果承接评估。

## 6. 不照搬的地方

1. 不把模型新品、会员标签、短剧 Agent 或技术生成类型作为美业商家的一级分类。
2. 不让“查看全部”退化为长期占据首屏的工具市场。
3. 不点击工具卡就开始生成、扣费、上传或发布。
4. 不像本次“自由画布”实测一样，仅浏览入口便静默创建空项目；我方应在用户明确“新建/开始”后才创建持久化对象。
5. 不让独立工具形成自己的账号、历史、素材库、额度或发布状态。
6. 不把隐藏 prompt、供应渠道或 provider 配置下发到浏览器；前台只拿可见上下文与版本引用。

## 7. 证据边界

- 三条入口均只走到可辨识其承接方式的第一屏，没有继续触发生成。
- 本轮确认的是入口与启动结构，不证明工具输出质量、生成时延、失败恢复、费用结算或资产回流。
- 页面显示的具体模型、积分和会员状态属于当日账号事实，不作为我方稳定产品规则。
