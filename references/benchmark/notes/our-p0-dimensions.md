# 我方 P0 对标维度提炼

日期：2026-07-07

来源：`合集-v1.2-含开源项目选型.md`

用途：把我方“美业内容副驾 P0”整理成可复用的竞品对标维度，供 CreatOK 和后续竞品统一评分。

> 2026-07-08 覆盖批注：本文为旧对标维度留档。最新 P0 以 `合集-v1.5-P0决策定稿.md` 修订摘要 #13 和 ADR-0008 为准：视频成片、视频额度、durable async jobs、存储/转码/AIGC 标识烧录进入 P0；图文渲染管线仍缓做。

## 1. P0 产品闭环

我方 P0 不是单点 AI 写作工具，而是本地到店商家的内容运营副驾。必须跑通的闭环是：

```text
门店档案
  -> 真实素材库
  -> Agent 工作台生成文案 / 视频成片（图文渲染缓做）
  -> 内容库管理草稿与平台变体
  -> 账号中心选择平台
  -> Regulated Content Mode / Publish Compliance Preflight
  -> L3 发布包交接；L1/L2 仅在账号能力 verified 后受控启用
  -> 线索台账记录咨询 / 加微 / 预约 / 核销
  -> 周报和下一轮内容建议
```

对标时要优先判断竞品是否能承接这个闭环，而不是只数功能入口数量。

## 2. P0 必做能力

| 模块 | P0 要求 | 对标关注点 |
| --- | --- | --- |
| 门店档案 | 项目价目、优惠活动、账号人设、老师/技师人设、资质、禁用表达 | 是否有垂类业务对象，而不是只让用户写 prompt |
| 真实素材库 | 案例图、环境图、before/after、好评截图、手法视频、素材标签、授权状态 | 是否把真实素材作为一等数据，是否能被生成工作流检索和复用 |
| 创作副驾 | 文案、平台改写、视频成片、分镜、素材缺口提醒；图文卡片为 Go 后 / P1 | 是否是 Agent 工作台 + 结构化内核，是否能读取门店档案和素材 |
| 内容库 | 内容母体、平台变体、版本、排期、发布状态、合规状态、本店爆款库 | 是否从“文件管理”升级为“内容项目管理” |
| 账号中心 | 平台账号、能力矩阵、授权状态、健康状态、账号人设 | 是否明确官方能力、浏览器辅助和发布包边界 |
| 发布包 / 受控发布 | L3 发布包常态兜底；L1 官方能力验证后启用；L2 只允许 no-submit 灰度 | 是否保留人在环，是否避免逆向和隐形全自动承诺 |
| 线索台账 | 咨询、评论意图、加微、预约、团购券领取/核销、人工标注、周报 | 是否能把内容生产和商家感知价值连接起来 |
| 合规 gate | AIGC 标识、广告法敏感词、Regulated Content Mode、价格/资质/素材授权校验 | 是否在保存、导出、发布包、提交前有可审计的合规检查 |
| 用量账本 | 内容额度、视频成片额度、发布包次数、素材容量、失败退款；图片/图文额度为 Go 后 / P1 | 是否有 reserve / commit / refund，而不是简单扣点 |
| 技术架构 | App Shell、Core API/Postgres、Agent Service/Mastra、Worker Pool、R2、Provider Registry | 是否把产品事实、AI 编排、重任务、对象存储和权限边界分清 |

## 3. P0 不做

对标时需要扣分或标记风险的方向：

- 不以 fully autonomous operations 作为 P0 主卖点。
- 不承诺全平台全自动发布。
- 不做 captcha bypass、cookie extraction、hidden API 调用、签名逆向或对抗式自动化。
- 不宣称复杂因果归因优化器，只做内容台账、线索看板和人工标注洞察。
- 不把专业剪辑器、重编辑时间线或数字人口播作为 P0 承重墙；P0 做视频成片薄链路，图文渲染缓做。
- 不用通用 RAG 或 Agent Memory 替代门店档案、价格、合规、发布、线索和用量账本事实。

## 4. 权重建议

总分 100。权重反映我方 P0 成败关键，而不是通用 AI 产品成熟度。

| 维度 | 权重 | 为什么重要 |
| --- | ---: | --- |
| 垂类 ICP 与 JTBD 匹配 | 8 | 判断竞品服务的是不是类似“商家内容运营”任务 |
| 门店/业务知识与 onboarding | 10 | 决定副驾是否懂这家店 |
| 真实素材库与素材权利 | 10 | 美业内容质量和合规的基础 |
| 内容生成覆盖与质量 | 12 | P0 头牌能力，必须覆盖文案、图文、脚本 |
| 平台原生变体与内容库 | 10 | 从一次生成升级为持续运营 |
| 发布/账号能力与人在环 | 10 | 不能只生成，必须能交接或受控发布 |
| 线索台账与反馈闭环 | 10 | 决定商家能否感知业务价值 |
| 合规、安全与审计 | 12 | 美业/医美 P0 红线，权重高于普通内容工具 |
| 用量账本与商业化 | 8 | 控制模型成本、套餐权益和失败补偿 |
| 技术架构与可扩展性 | 10 | 支撑异步任务、多模型、资产、审计和后续 agent 化 |

## 5. 评分口径

每个维度按 0-5 分评分，再乘权重：

| 分数 | 口径 |
| ---: | --- |
| 0 | 没看到能力或能力与 P0 无关 |
| 1 | 只有营销文案或非常薄的入口，没有可验证闭环 |
| 2 | 有单点功能，但缺少业务对象、状态或工作流 |
| 3 | 有可用工作流，但缺关键 P0 环节或行业迁移成本高 |
| 4 | 能明显借鉴，产品化成熟，只有局部缺口 |
| 5 | 与我方 P0 高度同构，可直接作为设计/架构标杆 |

证据置信度使用三档：

| 置信度 | 含义 |
| --- | --- |
| confirmed | 截图、网页文本、network preview、本地源码/官方仓库直接证明 |
| inferred | 由前端静态资源、API 命名、信息架构合理推断 |
| unverified | 只有营销说法或无法复验，需要后续补证 |
