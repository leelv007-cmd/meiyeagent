## 1. 使用原则

这套矩阵用于判断一个竞品对“美业到店 + 医美/医疗内容商家 · 云端 Web · Regulated Content Mode 创作副驾 P0”的参考价值。

对标时不要只比较“谁的 AI 工具更多”。我方 P0 的胜负手是：

1. 是否理解一家门店的项目、素材、账号、人设和限制。
2. 是否优先使用真实素材，而不是泛 AI 生成。
3. 是否能把内容从生成推进到内容库、发布包、账号中心和线索台账。
4. 是否在医美/医疗、价格、资质、AIGC 标识、顾客案例授权上有发布前核验。
5. 是否能用清晰的任务、账本、审计和架构边界支撑长期运营。

## 2. 评分方法

每个维度 0-5 分，再按权重折算为 100 分。

```text
维度加权分 = 维度评分 / 5 * 维度权重
总分 = 所有维度加权分相加
```

评分口径：

| 分数 | 标准 |
| ---: | --- |
| 0 | 没看到能力或与我方 P0 无关 |
| 1 | 只有营销文案或薄入口，没有可验证闭环 |
| 2 | 有单点功能，但缺少业务对象、状态或工作流 |
| 3 | 有可用工作流，但缺关键 P0 环节或行业迁移成本高 |
| 4 | 产品化成熟，可明显借鉴，只有局部缺口 |
| 5 | 与我方 P0 高度同构，可直接作为设计/架构标杆 |

证据置信度：

| 置信度 | 标准 |
| --- | --- |
| confirmed | 截图、网页文本、network preview、本地源码或官方仓库直接证明 |
| inferred | 由前端静态资源、API 命名、信息架构合理推断 |
| unverified | 只有营销说法或无法复验，需要后续补证 |

## 4. 单维度细则

### 4.1 垂类 ICP 与 JTBD 匹配，8 分

看竞品是否围绕一类明确商家的内容生产任务设计，而不是把通用模型功能换皮。

高分特征：
- 首页表达的是业务任务，不是模型能力堆叠。
- 有垂类对象，如商品、门店、服务项目、账号、素材、线索。
- 核心工作流能从“准备资料”走到“生成内容”和“业务动作”。

扣分项：
- 只提供 prompt box、图片生成、视频生成等单点能力。
- 只做内容灵感，不承接后续发布、管理或反馈。
- 目标客户和我方本地商家差异过大，迁移成本高。

### 4.2 门店/业务知识与 onboarding，10 分

看竞品是否有“懂这家店/这个商家”的资料结构。对我方 P0，业务知识必须沉淀在 Core API/Postgres 的产品事实中，不能只放在 prompt 或聊天记录里。

高分特征：
- 有结构化 profile，包括项目、价格、优惠、资质、账号人设、受众、禁用表达。
- 支持从价目表、历史内容、案例图、海报、好评截图导入。
- 生成前会主动检查资料缺口，并给拍摄清单或补充问题。

扣分项：
- 只支持自由文本描述。
- 只有商品 SKU，没有本地服务、预约、资质、禁用表达等对象。
- 业务信息不能被后续内容库、合规和线索台账复用。

### 4.3 真实素材库与素材权利，10 分

美业内容高度依赖真实案例、环境、老师、好评和手法素材。AI 图适合做背景和卡片元素，不应伪装成真实顾客效果。

高分特征：
- 资产库支持上传、AI 生成、发布包、门店资料、回收站。
- 素材有项目、平台、用途、授权状态、合规状态、是否已用等 metadata。
- 生成工作流会优先检索真实素材，并在素材不足时给拍摄清单。

扣分项：
- 只按文件夹存文件。
- 没有顾客授权、敏感素材、before/after、AI 辅助等状态。
- 生成结果和上传素材不能进入统一素材生命周期。

### 4.4 内容生成覆盖与质量，12 分

这是 P0 头牌能力，但评分重点是“可交付内容包”，不是模型炫技。

高分特征：
- 覆盖小红书/抖音/点评/公众号文案、图文卡片、视频脚本、分镜、拍摄清单。
- 有场景包，例如案例种草、项目介绍、优惠活动、店员口播、顾客好评、同城探店。
- 支持平台语气、篇幅、标题、话题、封面、字幕草稿等原生化参数。
- 高成本任务前有成本估算和确认。

扣分项：
- 真视频生成能力很强，但无法产出本地商家常用的文案、图文、发布包。
- 缺少历史任务、版本和可恢复任务 id。
- 生成内容不读门店档案和真实素材。

### 4.5 平台原生变体与内容库，10 分

我方内容库按内容项目组织，而不是简单文件夹。一个内容母体应能产生多个平台变体，并保留版本、合规状态、发布状态和线索关联。

高分特征：
- 有内容母体、平台变体、草稿、版本、排期、发布状态。
- 平台适配不是简单换字数，而是标题、封面、话题、CTA、素材比例和语气都变化。
- 有本店爆款库或历史复用机制。

扣分项：
- 只有生成历史，没有内容项目。
- 不区分平台变体。
- 内容无法关联合规结果、发布结果和线索。

### 4.6 发布/账号能力与人在环，10 分

P0 默认 L3 发布包兜底，L1 官方能力只在官方文档和账号级验收后启用，L2 浏览器辅助只允许 no-submit 灰度准备。

高分特征：
- 有账号列表、授权状态、平台能力矩阵、健康状态。
- 明确官方 API、浏览器辅助、发布包的不同边界。
- 高风险动作可预览、可确认、可审计、可失败兜底。
- 发布包包含文案、素材、封面、标签、CTA、合规提示和复制/下载说明。

扣分项：
- 承诺隐形全自动发布。
- 依赖逆向、cookie、captcha bypass、hidden API。
- 没有发布前确认和失败兜底。

### 4.7 线索台账与反馈闭环，10 分

我方不宣称因果归因优化器，但必须让商家看到内容和咨询/预约/到店之间的相关性。

高分特征：
- 支持咨询、评论意图、加微、预约、团购券领取/核销、人工标注。
- 线索能关联到内容、平台、项目、素材和时间。
- 周报能输出下一轮内容建议。

扣分项：
- 只做内容生产，完全没有业务反馈。
- 只接平台 analytics，不支持人工登记。
- 把小样本相关性包装成确定因果归因。

### 4.8 合规、安全与审计，12 分

这是美业/医美 P0 的最高风险维度之一，权重高于普通内容工具。

高分特征：
- AIGC 标识注入率可追踪。
- 医美/医疗、注射、激光、手术、药械等触发 Regulated Content Mode。
- 发布、导出、发布包交接、L2 备稿、L1 提交前执行 Publish Compliance Preflight。
- 检查价格/优惠、资质、疗效承诺、顾客案例授权、平台规则。
- 合规返回可操作替代表述，并记录审计。

扣分项：
- 只做通用内容安全。
- 合规只有提示语，没有任务状态和审计。
- 允许移除 AI 标识或绕审话术。
- 直接输出“保证合法/可放心发布”等承诺。

### 4.9 用量账本与商业化，8 分

用量不是简单扣点。它要连接模型成本、任务失败、套餐权益、团队协作、保留期和发布辅助次数。

高分特征：
- 有 credits、plan、quota、ledger、team sharing、storage quota。
- 高成本任务有预估；失败任务可 refund。
- 支持 reserve / commit / refund，避免并发扣费错乱。

扣分项：
- 只有订阅，没有任务级用量。
- 额度规则和模型成本不透明。
- 失败任务仍扣费且无解释。

### 4.10 技术架构与可扩展性，10 分

对标不是逆向复制技术栈，而是判断产品机制背后的架构边界。

高分特征：
- App Shell、Core API、Agent Service、Worker Pool、Object Storage 分界清晰。
- 生成任务异步化，有 task id、状态、恢复、重试、失败原因。
- 上传走 presigned URL，对象存储只存二进制，metadata 进入业务库。
- 模型能力、价格和 provider 通过 registry/capabilities 管理。
- Agent tools 有明确输入输出、权限、确认和审计。

扣分项：
- 前端直连 provider 或把业务事实写在对象存储 metadata 里。
- 长任务依赖浏览器连接不断。
- 合规、账本、权限散落在工具实现里。

## 6. CreatOK 对我方的结论

CreatOK 的核心参考价值不是“跨境电商”本身，而是它把垂类内容生产做成了产品系统：

| CreatOK 机制 | 我方 P0 应如何吸收 |
| --- | --- |
| 首页即主工作流 | 创作台首屏直接给“本周内容”或“从素材生成一条内容” |
| 工具卡矩阵 | 收敛成文案、图文、视频脚本、发布包、线索周报、拍摄清单 |
| 视频/图片历史和 task id | 所有生成任务进入内容库/任务历史，支持恢复、重试、审计 |
| 资产库 | 改造成真实素材、AI 生成、发布包、门店资料、回收站 |
| 商品套图 / A+ 模块 | 改造成项目套图、案例卡、服务流程卡、价格/优惠卡、注意事项卡 |
| 官方 TikTok 发布 | 改造成账号能力矩阵和发布层级说明，L3 发布包兜底 |
| credits + plan + refund | 建 Usage Ledger，支持 reserve / commit / refund |
| Agent Skills | P0 先内部 tools 化，P1/P2 再开放美业内容 skills |

不应照搬：

| CreatOK 做法 | 原因 | 我方替代 |
| --- | --- | --- |
| TikTok 爆款复刻作为核心卖点 | 美业更依赖真实素材、门店口碑和合规表达 | 本店历史内容复用 + 竞品结构参考 + 合规改写 |
| 真视频生成首屏承重 | 成本、质量、交付稳定性和合规风险高 | 视频脚本、分镜、拍摄清单、轻视频发布包 |
| 商品 SKU / TikTok Shop 链接 | 美业服务不是标准 SKU | 项目价目、活动、案例素材、预约规则 |
| 电商 A+ 详情图 | 本地生活不以详情页成交为主 | 小红书/点评/抖音图文卡和项目介绍 |
| TikTok 官方 API 路径 | 国内平台官方能力差异大 | 账号能力 verified 后 L1，常态 L3 发布包 |

## 8. 对当前规划的直接影响

这次矩阵反推后，我方 P0 需要继续坚持以下产品边界：

1. 创作台首屏应该是主工作流，不是功能导航页。
2. 资产库必须从 P0 设计真实素材 metadata、授权状态和合规状态。
3. 内容库必须按内容母体、平台变体、版本、状态、线索关联组织。
4. 发布能力必须产品化为账号能力矩阵 + 发布层级 + 发布包，而不是隐藏自动化。
5. 合规 gate 必须在保存、导出、发布包、L2 备稿和 L1 提交前重复出现。
6. Usage Ledger 必须早建，避免模型、图片、视频脚本、发布辅助和失败补偿混在业务代码里。
7. Agent Service 可以借鉴 CreatOK Skills 的 thin-client 思路，但 P0 先做内部 tools/workflows，外部 skills 后置。
