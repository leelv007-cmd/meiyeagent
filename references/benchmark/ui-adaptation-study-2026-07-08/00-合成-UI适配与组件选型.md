## 0. 结论摘要

1. **第一眼价值的三个承载**：①打开即见"已经替你想好的本周内容"（示例工作区+场景卡，价值前置）；②生成时的**流式逐字浮现+分步白话叙事**（"AI 正在为我干活"的第一信号）；③拟人化一句话问候（人格触点）。三者的组件成本都极低——第一眼价值花的是设计判断，不是组件预算。**二轮补充的硬证据把排序钉死：五杠杆之首是"示例内容质量"——样例文案必须像头部美业操盘手写的，文案就是产品本体，比任何视觉都重要**（Google 17-50ms / NN/g 美学-可用性效应 / Stanford Fogg design-quality=首要信任判据，亚洲用户同样成立）。
2. **组件采购总原则**：shadcn 官方件做主干（模板已含 54 个 primitives）+ **prompt-kit 做 AI 展示零件**（Base UI 下仅 5 处改写、价值中心组件零改写）+ **AI Elements 按需单件**（副驾对话期）+ **Streamdown+@streamdown/cjk 做中文流式渲染**。全部 copy-in 源码、手动单件移植，**不跑任何整包安装**。
3. **技术路线钦定**：AI SDK UI（useChat + tool parts + data parts + useObject）；**RSC/streamUI 官方已判实验性、禁入生产**。这与 ADR-0007（AI SDK 起步）完全咬合。
4. **四个避坑**（一手核实）：assistant-ui（核心包焊死 9 个 Radix 依赖）、CopilotKit（AG-UI 协议+Runtime 绑定）、AutoForm（无 License）、Origin UI（AGPL+组件迁移中）；Tremor 放缓改用官方 Chart。
5. **唯一真工程风险 = PWA on TanStack Start**（生产构建 SW 不生成的构建管线坑，Serwist 有不牺牲 SSR 的社区解法）→ 列入 Week-1 POC。
6. **一条已被 v1.5 采纳的升级**：v1.5 原定的"placeholder=真实美业示例"撞上 NN/g 长期立场（会消失的占位符有害）——已升级为"**AI 预填的可编辑真实默认值 + 标签下常驻说明**"。

## 1. 第一眼价值锚定：首屏 10 秒的设计

**三条一手硬证据（二轮补充，详见 ai-native-ux-practices.md 补充章）**：①用户在 **17–50ms** 内凭美学直觉决定去留，两个可控杠杆 = 低视觉复杂度 + 高原型熟悉度（Google Research）；②**美学-可用性效应**——好看的产品被认为更好用、对小瑕疵更宽容（NN/g，Hitachi ATM 实验）；③**design quality 是可信度首要判据**（Stanford Fogg："design look" 占信任评论 46%），且该判据**对亚洲用户同样成立**。推论：非技术美业用户无法评估功能深度，只能凭表面信号 50ms 定性"专不专业/值不值"——**首屏体验不是装饰，是护城河的对外面**。

**老板娘第一眼判断的五杠杆（按影响力排序）**：
1. **示例内容质量（第一杠杆，比任何视觉都重要）**——预置/预填的样例文案必须读起来像头部美业操盘手写的（真实门店口吻、能直接发）。用户拿"样例好不好"给整个产品定性，**文案就是产品本体**。→ 落点：示例美甲店的 3 张内容卡 + 场景卡的 AI 预填值，须投入人工打磨到"能直接发"的水准，这是设计预算的第一优先级。
2. **视觉档次**——留白、高质图、零错别字、配色贴"美/专业"语义（暖、向往感，非企业蓝；模板主色橙可调）。
3. **拟人化温度**——第一人称暖语气（已拍板的一句话提醒）。
4. **简单+熟悉**——首屏一个清晰动作；卡片形态复用小红书/美团/微信心智原型，**不做密集 dashboard**。
5. **10 秒即得价值**——投入任何输入前先摸到一条成品（示例工作区），避免空状态触发负向螺旋。

竞品第一屏（小云雀/CreatOK 实测）是"工具菜单"——用户仍要自己想"我要做什么"。**我们的第一眼差异 = 打开就看到"已经替你想好了"**：

| 秒 | 用户看到 | 承载组件 | 成本 |
|---|---|---|---|
| 0-3s | 拟人化一句话问候+提醒（"王姐，这周做染烫的客人多，我备好了 3 条内容"） | 自建轻组件（sonner/Alert 底子） | 极低 |
| 3-8s | 本周内容卡 3 张（示例工作区预置成品/正式用户的周计划产出） | Card grid + Badge（可选 Magic UI 点睛） | 极低 |
| 8-10s | 点开任一张：**正文逐字流出+"正在配标题…"步骤叙事** | prompt-kit ResponseStream/Steps + Streamdown cjk | 低（零-5 处改写） |

支撑证据链：流式逐字浮现和分步进度是非技术用户感知"这东西聪明"的第一信号（ui-libs 二轮分层）；"专门化任务用卡片而非 pill"（NN/g）；"占位→成品就地替换"（AI SDK 官方取向）。**结论：第一眼价值全部由最轻、最兼容的组件承载；重型对话框架买的是用户看不见的"架构对内"重量，一分不买。**

## 2. 底盘硬事实（四路交叉确认）

- mkfast-template = **React 19 + Tailwind 4.1 + Base UI 版 shadcn 4.0**（非经典 Radix，组合 API 用 `render={}`，新组件禁写 `asChild`）——恰好满足 prompt-kit/AI Elements 的硬前提（React19+TW4）。
- 54 个 ui primitives + 企业级 data-table（13 文件）+ 统一表单范式（rhf+zod4）+ 上传管线（→R2）+ sonner/vaul/skeleton/empty 已内置；六界面覆盖 🟢5/🟡5/🔴1（L3 发布包全新——本来就是我们独有物）。
- 模板有请求-响应式 AI 调用（Workers AI/fal.ai server functions），**零 streaming/chat 代码**——流式呈现层是本次采购的核心增量；prompt-kit ResponseStream 后端无关，可直接吃现有 server function 流，不必先上 useChat。
- shadcn 系 copy-in 组件不会双装 Radix（registryDependencies 解析到本地 Base UI 版 ui/）；真实成本=asChild→render 改写：prompt-kit 全套 5 处，AI Elements 所需子集个位数。
- 中文字体缺口：模板只配英文品牌字体（Bricolage Grotesque），中文界面字体（思源黑体/系统栈）需在落地周补配。

## 4. AI 原生交互规范（六条，全部一手依据）

1. **内容卡流 = tool parts 三态**（`input-available` 占位卡 → `output-available` 成品卡 → `output-error`）+ 同-id data part reconciliation；**禁 RSC**。卡片 min-height 防 CLS。
2. **异步任务四态卡**：排队中（位次）→ 生成中（**白话阶段叙事**："正在读你的门店信息/正在写初稿/正在配标题"，禁假百分比）→ 完成（显著角标+连接桥通知）→ 失败（一键重试）。**退款分层：技术失败自动退+流水留痕；成功但不满意不退、送免费重试**（Meshy/PixAI 共识，反例 Google Flow 信任崩塌）。
3. **表单 = AI 预填可编辑默认值**（升级 placeholder 拍板，见 §5）+ AI 字段标记 + 一键"回到 AI 版本"（Carbon revert-to-AI）+ 手机端点选优于打字（项目/风格/时长做 chips）。
4. **HITL**：采用/发布默认 **undo**（N 秒撤回），确认框仅留给"不可逆+高监管后果"；合规拦截=两档+四段式（陈述限制不指责→一句原因→给 1 条可用的合规替换→"改用这句"按钮归还控制权）。
5. **学徒心智**：首用一句话讲清"能做/不能做/会犯错要你把关"；全程收益语言（"帮你把这条更好卖出去"），不出现模型/prompt 黑话但可用美业行业词（与 v1.5 话术原则完全一致，获 NN/g/PAIR 背书）。
6. **AI 生成透明**：产出常驻"AI 生成，请核对"轻标注（兼作 AIGC 标识义务的 UI 面）。
